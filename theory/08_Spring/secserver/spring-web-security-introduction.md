# ✨ Spring Web Security 소개

## 1. Spring Web Security 개념

Spring Web Security는 스프링 웹 애플리케이션에서 인증과 인가를 처리하기 위한 보안 기능이다.

스프링 시큐리티를 적용하면 사용자가 특정 페이지나 기능에 접근하기 전에 로그인 여부와 권한을 확인할 수 있다. 📌

즉, 웹 애플리케이션에서 “누가 접근하는지”와 “어디까지 접근할 수 있는지”를 관리하는 기능이다.

## 2. Spring Web Security 설정 후 실행

Spring Security가 설정되면 모든 페이지는 보안 정책에 따라 접근된다.

기본 설정에서는 대부분의 페이지가 인증된 사용자만 접근할 수 있도록 보호된다.

즉, 로그인하지 않은 사용자가 보호된 페이지에 접근하면 로그인 페이지로 이동하게 된다. ✅

## 3. 기본 보안 정책

스프링 시큐리티가 설정되면 기본적으로 다음과 같은 정책이 적용될 수 있다.

- 모든 페이지는 로그인을 해야 접근 가능
- 로그인하지 않은 사용자는 `/login` 페이지로 리다이렉트
- 로그인 성공 후 원래 요청한 페이지나 지정된 페이지로 이동

즉, 별도의 세부 설정을 하지 않으면 기본적으로 애플리케이션 전체가 보호되는 방향으로 동작한다. 📌

## 4. 인증

인증(Authentication)은 자신을 증명하는 것이다.

즉, 사용자가 “내가 누구인지”를 시스템에 증명하는 과정이다.

예를 들어 다음 정보가 인증에 사용될 수 있다.

- 아이디
- 비밀번호
- 이메일 인증
- 토큰
- 인증서

사용자는 자기 자신을 증명할 만한 자료를 제시하고, 시스템은 그 정보가 올바른지 확인한다. ✅

## 5. 인가

인가(Authorization)는 인증된 사용자에게 특정 자격이나 권한이 부여되는 것이다.

즉, 사용자가 로그인에 성공했다고 해서 모든 기능을 사용할 수 있는 것은 아니다.

예를 들어 다음처럼 권한에 따라 접근 가능한 기능이 달라질 수 있다.

- 일반 사용자 → 게시글 조회 가능
- 로그인 사용자 → 게시글 작성 가능
- 관리자 → 회원 관리 가능

즉, 인증은 “누구인가”를 확인하는 것이고, 인가는 “무엇을 할 수 있는가”를 결정하는 것이다. 📌

## 6. 인증과 인가의 차이

인증과 인가는 함께 사용되지만 의미가 다르다.

| 구분 | 의미            | 예시                         |
| ---- | --------------- | ---------------------------- |
| 인증 | 자신을 증명     | 로그인                       |
| 인가 | 권한을 부여받음 | 관리자 페이지 접근 가능 여부 |

즉, 먼저 인증으로 사용자를 확인하고, 이후 인가로 접근 가능 범위를 결정한다.

## 7. AuthenticationManager

`AuthenticationManager`는 인증을 담당하는 핵심 객체이다.

스프링 시큐리티에서 인증 요청이 들어오면 `AuthenticationManager`가 이를 처리한다.

다양한 방식의 인증 처리를 지원할 수 있다.

예를 들면 다음과 같다.

- 아이디/비밀번호 인증
- 토큰 기반 인증
- OAuth 인증
- 커스텀 인증

즉, `AuthenticationManager`는 인증 흐름의 중심 역할을 한다. ✅

## 8. 인증과 권한 부여

스프링 시큐리티에서는 인증(Authentication)과 권한 부여(Authorization)를 분리해서 처리한다.

인증은 사용자의 신원을 확인하는 작업이고, 권한 부여는 인증된 사용자가 어떤 권한을 가지는지 확인하는 작업이다.

인증이 완료되면 사용자 정보와 권한 정보가 함께 구성되고, 이후 요청마다 이 권한을 기준으로 접근 가능 여부를 판단한다. 📌

## 9. ProviderManager

`ProviderManager`는 `AuthenticationManager`의 대표적인 구현체이다.

`ProviderManager`는 인증 처리를 직접 모두 수행하지 않고, `AuthenticationProvider` 타입의 객체를 이용해 인증을 처리한다.

즉, 여러 인증 제공자 중에서 현재 인증 요청을 처리할 수 있는 provider를 찾아 인증 작업을 위임한다.

## 10. AuthenticationProvider

`AuthenticationProvider`는 실제 인증 작업을 진행하는 객체이다.

예를 들어 사용자가 아이디와 비밀번호를 입력하면, `AuthenticationProvider`는 해당 정보가 올바른지 검증한다.

역할은 다음과 같다.

- 인증 요청 처리
- 사용자 정보 확인
- 비밀번호 검증
- 인증 성공 또는 실패 반환

즉, 실제 인증 로직을 담당하는 핵심 객체이다. ✅

## 11. UserDetailsService

`UserDetailsService`는 사용자 정보를 가져오는 역할을 한다.

인증 과정에서 사용자의 아이디를 기준으로 사용자 정보를 조회하고, 인증된 정보에 권한 정보를 구성할 수 있다.

즉, 로그인할 사용자의 정보와 권한 정보를 스프링 시큐리티가 이해할 수 있는 형태로 제공한다. 📌

예를 들어 DB에서 회원 정보를 조회한 뒤 다음 정보를 구성할 수 있다.

- 사용자 아이디
- 비밀번호
- 계정 상태
- 권한 목록

## 12. 인증 처리 흐름

스프링 시큐리티의 인증 흐름은 다음과 같이 이해할 수 있다.

1. 사용자가 로그인 정보 입력
2. 인증 요청 생성
3. `AuthenticationManager`가 인증 처리 시작
4. `ProviderManager`가 적절한 `AuthenticationProvider`에게 인증 위임
5. `AuthenticationProvider`가 실제 인증 작업 수행
6. `UserDetailsService`를 통해 사용자 정보와 권한 정보 조회
7. 인증 성공 시 인증 객체 생성
8. 이후 권한 정보를 기준으로 인가 처리

즉, 인증은 여러 객체가 역할을 나누어 처리한다.

## 13. 스프링 시큐리티 커스터마이징

스프링 시큐리티는 기본 동작을 그대로 사용할 수도 있지만, 프로젝트 요구사항에 맞게 커스터마이징할 수 있다.

대표적인 방식은 다음 두 가지이다.

- `AuthenticationProvider`를 직접 구현하는 방식
- 실제 처리를 담당하는 `UserDetailsService`를 구현하는 방식

즉, 인증 처리 전체를 직접 제어하거나, 사용자 정보를 조회하는 부분을 직접 구현할 수 있다. ✅

## 14. AuthenticationProvider 직접 구현

`AuthenticationProvider`를 직접 구현하면 실제 인증 로직을 세밀하게 제어할 수 있다.

예를 들어 다음과 같은 특수한 인증 방식이 필요할 때 사용할 수 있다.

- 일반 아이디/비밀번호가 아닌 별도 인증 방식
- 외부 시스템과 연동한 인증
- 추가 검증 로직이 필요한 인증
- 커스텀 토큰 인증

즉, 인증 판단 자체를 직접 구현해야 할 때 사용하는 방식이다. 📌

## 15. UserDetailsService 구현

`UserDetailsService`를 구현하는 방식은 실제 프로젝트에서 많이 사용된다.

보통 회원 정보가 데이터베이스에 저장되어 있으므로, 로그인 시 DB에서 사용자 정보를 조회해야 한다.

이때 `UserDetailsService`를 구현해서 DB의 사용자 정보를 스프링 시큐리티가 사용할 수 있는 형태로 변환한다.

즉, 실제 회원 테이블과 스프링 시큐리티 인증 시스템을 연결하는 역할을 한다. ✅

## 16. 중요 포인트 📌

- Spring Web Security는 웹 애플리케이션의 인증과 인가를 처리한다.
- 스프링 시큐리티가 설정되면 기본적으로 모든 페이지는 로그인 후 접근하도록 보호될 수 있다.
- 로그인하지 않은 사용자는 `/login` 페이지로 리다이렉트된다.
- 인증은 자신을 증명하는 과정이다.
- 인가는 인증된 사용자에게 권한을 부여하는 과정이다.
- 인증은 “누구인가”를 확인하고, 인가는 “무엇을 할 수 있는가”를 결정한다.
- `AuthenticationManager`는 인증을 담당하는 핵심 객체이다.
- `ProviderManager`는 `AuthenticationProvider`를 이용해 인증을 처리한다.
- `AuthenticationProvider`는 실제 인증 작업을 진행한다.
- `UserDetailsService`는 사용자 정보와 권한 정보를 구성하는 데 사용된다.
- 스프링 시큐리티 커스터마이징은 `AuthenticationProvider` 직접 구현 또는 `UserDetailsService` 구현 방식으로 할 수 있다.

## 정리 ✅

Spring Web Security는 스프링 웹 애플리케이션에서 인증과 인가를 처리하는 보안 기능이다.  
스프링 시큐리티가 설정되면 기본적으로 모든 페이지가 보호될 수 있고, 로그인하지 않은 사용자는 `/login` 페이지로 리다이렉트된다.  
인증은 사용자가 자신을 증명하는 과정이고, 인가는 인증된 사용자에게 특정 기능이나 페이지에 접근할 자격을 부여하는 과정이다.  
스프링 시큐리티의 인증 처리는 `AuthenticationManager`를 중심으로 이루어지며, `ProviderManager`가 `AuthenticationProvider`에게 실제 인증 작업을 위임한다.  
프로젝트에 맞게 보안을 커스터마이징할 때는 `AuthenticationProvider`를 직접 구현하거나, 사용자 정보 조회를 담당하는 `UserDetailsService`를 구현하는 방식이 사용된다.
