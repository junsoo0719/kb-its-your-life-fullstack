# ✨ 개발을 위한 준비

## 1. 로그 레벨 설정

애플리케이션을 실행하면 많은 로그 메시지가 출력될 수 있다.  
이때 로그 레벨을 설정하면 출력할 로그의 범위를 조절할 수 있다.

즉, 필요 이상으로 많은 로그가 출력되는 것을 줄이고, 상황에 맞는 정보만 확인할 수 있다. 📌

로그 레벨은 에러, 경고, 일반 정보, 디버깅 정보처럼 중요도에 따라 구분된다.

## 2. 로그 레벨 종류

로그 레벨은 보통 다음 순서로 구분할 수 있다.

- `FATAL`
- `ERROR`
- `WARN`
- `INFO`
- `DEBUG`
- `TRACE`

위로 갈수록 더 심각한 상황을 의미하고, 아래로 갈수록 더 자세한 정보를 의미한다.

즉, `TRACE`는 가장 상세하고, `FATAL`은 가장 심각한 로그만 출력한다. ✅

## 3. FATAL

`FATAL`은 가장 치명적인 에러가 발생했을 때만 로깅한다.

예를 들어 애플리케이션이 더 이상 정상적으로 실행될 수 없는 수준의 문제가 발생했을 때 사용된다.

즉, 시스템 실행 자체에 치명적인 문제가 있을 때 사용하는 로그 레벨이다. ⚠️

## 4. ERROR

`ERROR`는 일반적인 에러가 발생했을 때 로깅한다.

`FATAL`보다는 낮은 수준이지만, 정상적인 처리가 실패한 상황을 나타낸다.

예를 들어 예외 발생, DB 연결 실패, 요청 처리 실패 같은 상황에서 사용할 수 있다.

## 5. WARN

`WARN`은 에러는 아니지만 주의할 필요가 있는 상황을 로깅한다.

즉, 현재 실행은 가능하지만 나중에 문제가 될 수 있는 상황을 나타낸다.

예를 들어 권장되지 않는 설정, 잠재적인 문제, 예상과 다른 입력 등이 있을 때 사용할 수 있다. 📌

## 6. INFO

`INFO`는 일반 정보를 나타낼 때 사용하는 로그 레벨이다.

애플리케이션의 정상적인 흐름이나 주요 실행 정보를 확인할 때 사용한다.

예를 들어 서버 시작, 설정 로딩, 요청 처리 시작 같은 일반 정보가 포함될 수 있다.

`INFO` 레벨을 설정하면 일반적으로 `INFO` 이상의 로그인 `WARN`, `ERROR`, `FATAL`도 함께 출력된다.

## 7. DEBUG

`DEBUG`는 일반 정보를 더 상세하게 나타낼 때 사용하는 로그 레벨이다.

디버깅에 필요한 정보를 확인할 때 사용한다.

예를 들어 변수 값, 메서드 호출 흐름, SQL 실행 정보 등을 자세히 보고 싶을 때 사용할 수 있다.

개발 중에는 유용하지만 운영 환경에서는 로그가 너무 많아질 수 있으므로 주의해야 한다. ⚠️

## 8. TRACE

`TRACE`는 경로 추적을 위해 사용하는 가장 상세한 로그 레벨이다.

애플리케이션 내부 흐름을 매우 세밀하게 추적할 때 사용한다.

즉, `DEBUG`보다 더 자세한 로그를 남기고 싶을 때 사용한다.

## 9. 로그 레벨 선택 기준

로그 레벨은 상황에 따라 다르게 설정한다.

개발 중에는 문제 원인을 찾기 위해 `DEBUG`나 `TRACE`를 사용할 수 있다.  
하지만 운영 환경에서는 너무 많은 로그가 성능과 저장 공간에 영향을 줄 수 있으므로 보통 `INFO`, `WARN`, `ERROR` 중심으로 설정한다.

정리하면 다음과 같다.

- 개발 환경 → `DEBUG`, 필요 시 `TRACE`
- 운영 환경 → `INFO`, `WARN`, `ERROR`

즉, 로그는 많이 찍는 것이 항상 좋은 것이 아니라 필요한 수준으로 조절하는 것이 중요하다. ✅

## 10. 패키지 구조

스프링 프로젝트에서는 역할에 따라 패키지를 나누어 관리한다.

필기 기준으로 주요 패키지는 다음과 같다.

- `config`
- `controller`

## 11. config 패키지

`config` 패키지는 스프링 설정 클래스를 두는 패키지이다.

예를 들어 다음과 같은 설정 클래스가 위치할 수 있다.

- 스프링 MVC 설정
- 빈 설정
- 데이터베이스 설정
- 웹 관련 설정
- 보안 설정

즉, 프로젝트의 환경과 동작 방식을 설정하는 클래스들을 모아두는 곳이다. 📌

## 12. controller 패키지

`controller` 패키지는 기본 컨트롤러 클래스를 두는 패키지이다.

컨트롤러는 사용자의 요청을 받아 처리하고, 필요한 응답을 반환하는 역할을 한다.

스프링 MVC에서는 `@Controller` 또는 `@RestController`가 붙은 클래스들이 주로 이 패키지에 위치한다.

즉, 웹 요청의 시작점 역할을 하는 클래스들을 관리하는 패키지이다.

## 13. "/resources/\*\*" 경로

스프링 MVC 설정에서 정적 리소스 경로를 지정할 때 다음과 같은 패턴을 사용할 수 있다.

    /resources/**

이 패턴은 `/resources/` 아래의 모든 경로를 의미한다.

예를 들어 다음과 같은 요청들이 포함될 수 있다.

    /resources/css/style.css
    /resources/js/app.js
    /resources/images/logo.png

즉, CSS, JavaScript, 이미지 같은 정적 파일을 매핑할 때 자주 사용한다. ✅

## 14. \*와 \*\*의 차이

경로 패턴에서 `*`와 `**`는 의미가 다르다.

`*`는 경로 한 단계만 매칭한다.

    /resources/*

이 경우 다음 경로는 매칭될 수 있다.

    /resources/app.js

하지만 다음처럼 하위 폴더가 더 있는 경로는 매칭되지 않을 수 있다.

    /resources/js/app.js

반면 `**`는 여러 단계의 하위 경로까지 모두 매칭한다.

    /resources/**

이 경우 다음 경로들이 모두 매칭될 수 있다.

    /resources/app.js
    /resources/js/app.js
    /resources/css/main/style.css

즉,

- `*` → 한 단계 경로
- `**` → 여러 단계 하위 경로 전체

로 구분하면 된다. 📌

## 15. 중요 포인트 📌

- 로그 메시지가 너무 많이 출력될 때 로그 레벨로 출력 범위를 조절할 수 있다.
- 로그 레벨은 `FATAL`, `ERROR`, `WARN`, `INFO`, `DEBUG`, `TRACE`가 있다.
- `FATAL`은 가장 치명적인 에러 상황에 사용한다.
- `ERROR`는 일반적인 에러 상황에 사용한다.
- `WARN`은 에러는 아니지만 주의가 필요한 상황에 사용한다.
- `INFO`는 일반 정보를 나타낼 때 사용한다.
- `DEBUG`는 디버깅 정보를 자세히 출력할 때 사용한다.
- `TRACE`는 경로 추적을 위해 가장 상세한 정보를 출력할 때 사용한다.
- `config` 패키지는 스프링 설정 패키지이다.
- `controller` 패키지는 기본 컨트롤러 패키지이다.
- `/resources/**`는 `/resources/` 아래의 모든 하위 경로를 의미한다.
- `*`는 한 단계 경로만 매칭한다.
- `**`는 여러 단계 하위 경로까지 매칭한다.

## 정리 ✅

개발을 위한 준비에서는 로그 레벨 설정과 기본 패키지 구조, 정적 리소스 경로 패턴을 이해하는 것이 중요하다.  
로그 레벨은 출력할 로그의 범위를 조절하기 위한 기준이며, `FATAL`, `ERROR`, `WARN`, `INFO`, `DEBUG`, `TRACE` 순으로 구분된다.  
개발 중에는 `DEBUG`나 `TRACE`로 자세한 정보를 확인할 수 있고, 운영 환경에서는 보통 `INFO` 이상의 로그를 사용해 필요한 정보만 출력한다.  
스프링 프로젝트에서는 설정 클래스는 `config`, 요청 처리 클래스는 `controller` 패키지에 두는 방식으로 역할을 나누어 관리한다.  
또한 `/resources/**`에서 `*`는 한 단계 경로, `**`는 여러 단계 하위 경로까지 매칭한다는 점을 기억해야 한다.
