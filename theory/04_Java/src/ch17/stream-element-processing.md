# ✨ 스트림 요소 처리

## 1. 스트림의 개념

스트림은 컬렉션이나 배열의 요소를 반복 처리하기 위한 기능이다.  
데이터가 하나씩 흘러가면서 처리된다고 생각하면 된다.

예를 들어 `List` 컬렉션에서 스트림을 얻고, 각 요소를 처리할 수 있다.

    Stream<String> stream = list.stream();

    stream.forEach(item -> {
        // item 처리
    });

여기서 `list.stream()`은 `List` 컬렉션의 요소를 처리하기 위한 `Stream` 객체를 얻는 코드이다.  
그리고 `forEach()`는 각 요소를 하나씩 처리하는 최종 처리 메소드이다. 📌

## 2. forEach와 람다식

스트림에서 요소를 처리할 때는 람다식을 자주 사용한다.

    stream.forEach(item -> {
        System.out.println(item);
    });

이 코드는 스트림 안의 요소를 하나씩 꺼내서 `item`으로 전달하고, 그 요소를 출력하는 코드이다.

즉, 개발자는 반복문을 직접 작성하지 않고 "각 요소를 어떻게 처리할지"만 람다식으로 제공한다.

## 3. 스트림과 Iterator의 차이

스트림은 기존의 `Iterator`와 비슷하게 요소를 반복 처리할 수 있지만, 중요한 차이가 있다.

스트림의 특징은 다음과 같다.

- 내부 반복자이므로 처리 속도가 빠르고 병렬 처리에 효율적이다.
- 람다식으로 다양한 요소 처리 방법을 정의할 수 있다.
- 중간 처리와 최종 처리를 연결해 파이프라인을 형성할 수 있다.

특히 스트림의 핵심은 파이프라인이다.  
여러 작업을 순서대로 연결해서 데이터 처리 흐름을 만들 수 있다. ✅

## 4. 외부 반복자와 내부 반복자

지금까지 주로 사용한 `for`, `while`, `Iterator` 방식은 외부 반복자이다.

외부 반복자는 반복을 돌리는 책임이 개발자에게 있다.

예를 들어 다음처럼 직접 반복문을 작성해야 한다.

    for (String item : list) {
        System.out.println(item);
    }

반면 스트림은 내부 반복자를 사용한다.

내부 반복자는 개발자가 반복을 직접 제어하지 않고, 요소를 어떻게 처리할지만 람다식으로 전달한다.

    list.stream().forEach(item -> {
        System.out.println(item);
    });

즉, 개발자는 처리 코드만 제공하고 반복은 스트림 내부에서 수행된다. 📌

## 5. 내부 반복자의 장점

내부 반복자는 요소 처리 방법을 컬렉션 내부로 주입해서 반복 처리한다.

이 구조의 장점은 다음과 같다.

- 반복 제어 코드를 줄일 수 있다.
- 람다식으로 처리 로직을 간결하게 작성할 수 있다.
- 병렬 처리에 유리하다.

즉, 개발자는 "어떻게 반복할지"보다 "요소를 어떻게 처리할지"에 집중할 수 있다.

## 6. 병렬 스트림

스트림은 병렬 처리를 지원한다.

병렬 스트림은 여러 스레드로 요소를 나누어 처리할 수 있는 스트림이다.

    Stream<String> parallelStream = list.parallelStream();

필기에는 `parallemStream()`이라고 적혀 있지만, 정확한 메소드명은 `parallelStream()`이다. ⚠️

병렬 스트림을 사용하면 내부 반복자가 멀티스레드 방식으로 요소를 처리할 수 있다.  
다만 모든 상황에서 병렬 처리가 더 빠른 것은 아니므로 데이터 크기와 작업 특성을 고려해야 한다.

## 7. 스트림 파이프라인

스트림은 한 번만 흘려보낼 수 있다.  
즉, `Iterator`를 한 번 사용하면 다시 순회하려면 새 Iterator를 얻어야 하듯이, 스트림도 한 번 사용하면 다시 얻어야 한다.

하지만 스트림은 한 번 흐르는 동안 여러 작업을 연결할 수 있다.  
이 연결 구조를 스트림 파이프라인이라고 한다.

파이프라인에서는 앞 작업의 출력이 다음 작업의 입력이 된다.

즉,

    원본 스트림 → 중간 처리 → 중간 처리 → 최종 처리

의 흐름으로 동작한다. 📌

## 8. 중간 처리와 최종 처리

스트림 파이프라인은 크게 중간 처리와 최종 처리로 나뉜다.

### 8-1. 중간 처리

중간 처리는 데이터를 가공하거나 걸러내는 작업이다.  
중간 처리는 여러 개 연결할 수 있다.

대표적인 작업은 다음과 같다.

- 필터링
- 매핑

즉, 원본 데이터를 원하는 형태로 바꾸거나 필요한 데이터만 남기는 단계이다.

### 8-2. 최종 처리

최종 처리는 파이프라인의 마지막 처리이다.  
최종 처리는 보통 하나만 사용한다.

대표적인 작업은 다음과 같다.

- `forEach`
- 집계

중요한 점은 최종 처리 메소드가 호출되는 시점에 실제로 파이프라인이 열리고 데이터가 흘러간다는 것이다. ✅

즉, 중간 처리만 작성해 두면 바로 실행되는 것이 아니라 최종 처리가 있어야 실제 처리가 수행된다.

## 9. 필터링과 매핑

스트림의 중간 처리에서 자주 사용하는 개념은 필터링과 매핑이다.

- 필터링 → 조건에 맞는 요소만 남김
- 매핑 → 요소를 다른 값이나 다른 형태로 변환

예를 들어 `Student` 객체에서 점수만 꺼내고 싶다면 매핑을 사용할 수 있다.

    IntStream scoreStream = studentStream.mapToInt(student -> student.getScore());

이 코드는 `Student` 객체를 `getScore()` 메소드의 리턴값인 점수로 변환한다.

즉, 객체 스트림을 점수 스트림으로 바꾸는 것이다.

## 10. map과 mapToInt

`map()`은 제네릭 타입의 스트림으로 매핑할 때 사용할 수 있다.

반면 `mapToInt()`는 요소를 `int` 값으로 매핑해서 `IntStream`을 만들 때 사용한다.

예를 들어 다음 코드는 학생 객체에서 점수만 추출한다.

    studentStream.mapToInt(student -> student.getScore());

즉,

- `map()` → 일반 객체 타입으로 변환
- `mapToInt()` → int 전용 스트림으로 변환

이라고 이해하면 된다. 📌

## 11. 메소드 체이닝 패턴

스트림은 메소드 체이닝 방식으로 자주 사용된다.

예를 들어 학생 점수 평균을 구하는 코드는 다음과 같다.

    double avg = list.stream()
        .mapToInt(student -> student.getScore())
        .average()
        .getAsDouble();

이 코드의 흐름은 다음과 같다.

1. `stream()`으로 스트림을 얻는다.
2. `mapToInt()`로 학생 객체에서 점수만 추출한다.
3. `average()`로 평균을 구한다.
4. `getAsDouble()`로 결과를 꺼낸다.

즉, 스트림은 중간 처리와 최종 처리를 연결해서 데이터 처리 흐름을 한 줄처럼 표현할 수 있다. ✅

## 12. 메소드 참조 사용

람다식이 단순히 인스턴스 메소드를 호출하는 경우에는 메소드 참조로 줄일 수 있다.

예를 들어 다음 코드가 있다.

    student -> student.getScore()

이 코드는 `Student` 객체의 `getScore()` 메소드를 호출하는 구조이다.  
따라서 다음처럼 줄일 수 있다.

    Student::getScore

즉, 인스턴스 메소드 참조를 사용해서 더 간결하게 작성할 수 있다.

    double avg = list.stream()
        .mapToInt(Student::getScore)
        .average()
        .getAsDouble();

## 13. 컬렉션 초기화

기존에는 컬렉션을 만들고 요소를 하나씩 추가했다.

    List<String> list = new ArrayList<>();
    list.add("A");
    list.add("B");

하지만 `add()`는 메소드 체이닝이 불가능하므로 코드가 길어질 수 있다.

간단한 리스트는 `List.of()`로 만들 수 있다.

    List<String> list = List.of("A", "B", "C");

또는 배열을 리스트로 받을 때 `Arrays.asList()`를 사용할 수 있다.

    List<String> list = Arrays.asList("A", "B", "C");

다만 이 방식으로 만든 리스트는 읽기 전용 성격이 강해서 추가나 삭제가 제한될 수 있다. ⚠️

즉, 간단한 초기화에는 편하지만 수정이 필요한 경우에는 주의해야 한다.

## 14. 스트림 인터페이스

스트림 관련 인터페이스의 가장 상위에는 `BaseStream`이 있다.

그 아래에 일반 객체 스트림인 `Stream<T>`가 있다.

- `BaseStream` → 스트림의 가장 부모 인터페이스
- `Stream<T>` → 제네릭 기반 객체 스트림

즉, `Stream`은 다양한 타입의 객체 요소를 처리할 수 있는 제네릭 스트림이다.

## 15. 스트림 얻는 방법

스트림은 컬렉션이나 배열에서 얻을 수 있다.

대표적인 방법은 다음과 같다.

    java.util.Collection.stream()

    Arrays.stream(T[])

    Stream.of(T[])

예를 들면 다음처럼 사용할 수 있다.

    List<String> list = List.of("A", "B", "C");
    Stream<String> stream1 = list.stream();

    String[] arr = {"A", "B", "C"};
    Stream<String> stream2 = Arrays.stream(arr);
    Stream<String> stream3 = Stream.of(arr);

즉, 컬렉션과 배열 모두 스트림으로 변환해서 동일한 방식으로 처리할 수 있다. 📌

## 16. static과 참조 변수 특징

필기에서 언급한 static과 참조 변수의 특징은 매개변수 전달과 연결해서 이해할 수 있다.

참조 타입 객체를 매개변수로 전달하면 객체 자체가 복사되는 것이 아니라 참조값이 전달된다.  
즉, 전달받은 쪽에서도 같은 객체를 가리킬 수 있다.

스트림에서도 객체 요소를 처리할 때 원본 객체의 참조를 기반으로 처리할 수 있으므로, 객체 상태를 직접 변경하는 작업은 주의해야 한다. ⚠️

즉, 스트림은 간결하지만 원본 객체 변경 여부를 항상 의식해야 한다.

## 17. 중요 포인트 📌

- 스트림은 컬렉션이나 배열의 요소를 반복 처리하기 위한 기능이다.
- `list.stream()`으로 `Stream` 객체를 얻을 수 있다.
- `forEach()`는 요소를 하나씩 처리하는 최종 처리 메소드이다.
- 스트림은 내부 반복자를 사용한다.
- 개발자는 반복 코드가 아니라 요소 처리 코드만 람다식으로 제공한다.
- 병렬 스트림은 `parallelStream()`으로 얻는다.
- 스트림은 한 번만 사용할 수 있다.
- 스트림 파이프라인은 중간 처리와 최종 처리로 구성된다.
- 중간 처리는 필터링과 매핑에 자주 사용된다.
- 최종 처리가 호출되어야 실제 데이터 처리가 수행된다.
- `mapToInt()`는 객체를 int 값으로 매핑할 때 사용한다.
- `Student::getScore`처럼 메소드 참조를 사용할 수 있다.
- `List.of()`와 `Arrays.asList()`는 간단한 컬렉션 초기화에 사용할 수 있지만 수정에 주의해야 한다.
- 스트림은 `Collection.stream()`, `Arrays.stream()`, `Stream.of()`로 얻을 수 있다.

## 정리 ✅

스트림은 컬렉션이나 배열의 요소를 반복 처리하기 위한 기능이며, 내부 반복자를 사용해 개발자가 반복문을 직접 작성하지 않아도 된다.  
스트림의 핵심은 파이프라인으로, 중간 처리와 최종 처리를 연결해서 데이터를 필터링하거나 매핑하고 최종 결과를 얻을 수 있다.  
중간 처리는 여러 개 연결할 수 있지만 최종 처리가 호출되어야 실제로 데이터가 흘러가며 처리된다.  
또한 `mapToInt()`, `average()`, `forEach()` 같은 메소드를 체이닝해서 간결하게 작성할 수 있고, `Student::getScore`처럼 메소드 참조를 사용해 더 짧게 표현할 수도 있다.  
시험 대비에서는 내부 반복자, 병렬 스트림, 파이프라인 구조, 중간 처리와 최종 처리 차이, 스트림 생성 방법을 함께 정리해 두는 것이 중요하다.
