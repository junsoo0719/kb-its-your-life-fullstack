# ✨ 중첩 선언과 익명 객체

## 1. 중첩 클래스

중첩 클래스는 클래스 내부에 클래스를 정의하는 내부 클래스이다.  
즉, 어떤 클래스와 밀접하게 관련된 클래스를 외부에 따로 두지 않고 클래스 내부에 선언하는 방식이다.

중첩 클래스를 사용하면 클래스의 접근 범위를 제한할 수 있고, 관련된 코드를 한 곳에 모을 수 있어 코드 복잡성을 줄일 수 있다. 📌

## 2. 중첩 클래스의 종류

중첩 클래스는 선언 위치와 성격에 따라 나눌 수 있다.

- 멤버 클래스 → 클래스의 멤버로 선언
- 로컬 클래스 → 메서드 내부에 선언

멤버 클래스는 다시 다음 두 가지로 나뉜다.

- 인스턴스 멤버 클래스
- 정적 멤버 클래스

즉, 중첩 클래스는 어디에 선언되었는지와 외부 클래스 인스턴스가 필요한지에 따라 구분된다.

## 3. 인스턴스 멤버 클래스

인스턴스 멤버 클래스는 외부 클래스의 인스턴스가 있어야 사용할 수 있는 내부 클래스이다.

예를 들어 A 클래스 내부에 B 클래스가 있을 때, B 객체를 만들려면 먼저 A 객체가 필요하다.

    A a = new A();
    A.B b = a.new B();

즉, B는 A 객체에 소속되어 만들어지는 구조이다.

인스턴스 멤버 클래스는 바깥 클래스의 인스턴스와 연결되어 있으므로 바깥 객체의 멤버에 접근할 수 있다.

## 4. static 메소드에서 인스턴스 멤버 클래스 사용 제한

클래스 A 안에 `static void useB2()` 메소드가 있다고 하자.  
이 static 메소드 안에서는 인스턴스 멤버 클래스 `B`를 바로 `new B()`로 생성할 수 없다.

이유는 static 메소드에는 `this`가 없기 때문이다. ⚠️

즉, 인스턴스 멤버 클래스는 바깥 객체가 필요한데, static 영역에서는 특정 바깥 객체가 존재하지 않는다.

따라서 바깥 클래스의 static 멤버에서는 인스턴스 멤버 클래스를 직접 사용할 수 없다.

## 5. 내부 클래스 기능 사용 방식

내부 클래스의 기능은 보통 바깥 클래스의 메서드를 통해 간접적으로 사용한다.

즉, 외부에서 내부 클래스를 직접 다루기보다 바깥 클래스가 내부 클래스 생성과 사용을 관리하는 방식이 더 자연스럽다.

이렇게 하면 내부 구현을 숨기고 필요한 기능만 외부에 공개할 수 있어 캡슐화에도 도움이 된다. 📌

## 6. 정적 멤버 클래스

정적 멤버 클래스는 `static`이 붙은 내부 클래스이다.

예를 들어 클래스 A 안에 다음과 같이 선언할 수 있다.

    static class B {
        ...
    }

정적 멤버 클래스는 바깥 클래스의 인스턴스가 없어도 사용할 수 있다.

객체 생성 방식은 다음과 같다.

    A.B b = new A.B();

정적 멤버 클래스의 static 메소드도 다음처럼 호출할 수 있다.

    A.B.method2();

즉, 정적 멤버 클래스는 바깥 객체와 연결되지 않고, 바깥 클래스 이름을 통해 접근한다.

## 7. 로컬 클래스

로컬 클래스는 메서드 내부에 정의하는 클래스이다.

즉, 특정 메서드 안에서만 필요한 클래스를 그 메서드 내부에 선언하는 방식이다.

로컬 클래스는 선언된 메서드 안에서만 사용할 수 있으며, 외부에서 직접 접근할 수 없다.

즉,

- 메서드 내부에 정의
- 메서드 내부에서 사용
- 외부 직접 접근 불가

로 정리할 수 있다.

## 8. 로컬 클래스와 지역 변수 접근

로컬 클래스는 외부 클래스의 지역 변수에 접근할 수 있다.

하지만 중요한 제한이 있다.

- 지역 변수 읽기 가능
- 지역 변수 수정 불가

즉, 로컬 클래스에서 접근하는 지역 변수는 final 변수처럼 운영된다.  
실제로 자바는 이 변수를 변경되지 않는 값으로 취급한다.

## 9. 로컬 클래스에서 지역 변수 수정을 막는 이유

메서드의 지역 변수는 원래 스택에 저장되고, 메서드가 종료되면 사라진다.

하지만 로컬 클래스 객체는 메서드가 끝난 뒤에도 사용될 수 있다.  
즉, 메서드의 생명 주기와 로컬 클래스 객체의 실제 호출 시점이 다를 수 있다.

그래서 자바는 로컬 클래스가 사용하는 지역 변수를 final처럼 다루어 안전하게 접근하도록 한다. 📌

즉, 읽기는 허용하지만 수정은 제한하는 방식이다.

## 10. 바깥 클래스 멤버 접근

중첩 클래스는 바깥 클래스의 멤버에 접근할 수 있다.

특히 인스턴스 멤버 클래스는 바깥 클래스 인스턴스와 연결되어 있으므로 접근 제한자와 관계없이 바깥 클래스의 멤버에 접근할 수 있다.

즉, 바깥 객체와 내부 객체가 서로 강하게 연결되어 있다고 볼 수 있다.

## 11. 정적 멤버 클래스의 접근 제한

정적 멤버 클래스는 바깥 클래스의 인스턴스와 연결되지 않는다.

따라서 바깥 클래스의 인스턴스 멤버에는 직접 접근할 수 없다.  
대신 static 필드나 static 메소드에는 접근할 수 있다.

즉,

- 인스턴스 멤버 클래스 → 바깥 인스턴스 멤버 접근 가능
- 정적 멤버 클래스 → 바깥 static 멤버 중심으로 접근 가능

으로 구분해야 한다. ⚠️

## 12. 이름 충돌과 바깥 객체 접근

중첩 클래스에서 이름이 같은 변수가 여러 개 있으면 가까운 범위에 있는 것이 우선된다.

즉, 지역 변수나 내부 클래스의 필드가 바깥 클래스의 필드보다 우선된다.

이때 바깥 클래스의 인스턴스를 명확히 가리키고 싶다면 다음 문법을 사용한다.

    바깥클래스이름.this

이 문법은 내부 클래스에서 바깥 객체를 참조할 때 사용한다.

## 13. 중첩 인터페이스

중첩 인터페이스는 클래스 내부에 선언된 인터페이스이다.

특정 클래스와 밀접하게 관련된 인터페이스를 내부에 선언해서 구조를 더 명확하게 만들 수 있다.

즉, 외부에 독립적으로 공개하기보다 해당 클래스 안에서 의미가 있는 규칙을 정의할 때 사용할 수 있다.

## 14. 익명 객체

익명 객체는 이름이 없는 객체이다.  
정확히는 인스턴스를 만들 때 동시에 클래스를 정의해서 객체를 생성하는 방식이다.

익명 객체는 상속 메커니즘을 사용한다.

기본 형식은 다음과 같다.

    new 부모생성자(매개값, ...) {
        // 자식 클래스 정의
    }

이때 리턴되는 객체 타입은 부모 클래스 타입이지만, 실제 객체는 익명 자식 클래스의 인스턴스이다.

즉,

- 타입 → 부모 타입
- 실체 → 익명 자식 객체

라고 이해하면 된다. 📌

## 15. 익명 구현 객체

익명 구현 객체는 인터페이스를 구현하는 이름 없는 객체이다.

기본 형식은 다음과 같다.

    new 인터페이스() {
        // 구현 객체
    }

인터페이스는 원래 직접 객체를 만들 수 없지만, 이 방식은 인터페이스를 구현한 익명 클래스를 즉석에서 만들어 객체를 생성하는 것이다.

즉, 일회성 구현체가 필요할 때 자주 사용된다. ✅

## 16. 익명 구현 객체를 사용하는 이유

익명 구현 객체는 바깥 함수의 멤버 변수에 자유롭게 접근하기 위해 사용될 수 있다.

또한 특정 구현 클래스를 따로 만들기에는 너무 간단하거나, 한 번만 사용할 구현이 필요할 때 유용하다.

즉, 별도의 클래스 파일을 만들지 않고 필요한 자리에서 바로 구현 객체를 만들 수 있다는 장점이 있다.

## 17. 익명 객체와 람다식

익명 구현 객체에서 구현해야 할 메소드가 하나뿐인 경우에는 람다식으로 표현할 수 있다.

즉, 메소드가 하나인 인터페이스는 람다 표현식으로 더 간단하게 작성할 수 있다.

정리하면 다음과 같다.

- 메소드 여러 개 → 익명 구현 객체 사용
- 메소드 한 개 → 람다식 사용 가능

이 부분은 자바의 함수형 인터페이스와도 연결된다. 📌

## 18. 주입과 템플릿 메소드 비교

익명 구현 객체는 주입에 의해 동작이 결정되는 방식으로 볼 수 있다.

즉, 필요한 구현체를 외부에서 넣어 주면 그 구현에 따라 동작이 달라진다.

반면 Template Method 패턴은 상속에 의해 동작이 결정된다.

정리하면 다음과 같다.

- 익명 구현 객체 → 주입에 의해 결정
- Template Method → 상속에 의해 결정

즉, 둘 다 동작을 바꾸는 방식이지만 구조가 다르다.

## 19. 익명 구현 객체 연습 필요

익명 구현 객체는 자바에서 자주 사용된다.  
특히 이벤트 처리, 콜백 처리, 인터페이스 기반 설계에서 많이 등장한다.

따라서 문법이 처음에는 낯설 수 있지만 반드시 연습이 필요하다. ✅

익명 구현 객체는 다음 흐름으로 이해하면 좋다.

1. 인터페이스 타입이 필요하다.
2. 별도 구현 클래스를 만들기 번거롭다.
3. 그 자리에서 바로 구현 객체를 만든다.
4. 필요한 메소드를 재정의한다.

## 20. 중요 포인트 📌

- 중첩 클래스는 클래스 내부에 정의하는 클래스이다.
- 중첩 클래스는 코드 복잡성을 줄이고 접근 범위를 제한할 수 있다.
- 멤버 클래스는 인스턴스 멤버 클래스와 정적 멤버 클래스로 나뉜다.
- 인스턴스 멤버 클래스는 바깥 클래스의 인스턴스가 필요하다.
- 정적 멤버 클래스는 바깥 인스턴스 없이 사용할 수 있다.
- 로컬 클래스는 메서드 내부에 정의하고 메서드 안에서만 사용한다.
- 로컬 클래스는 지역 변수에 접근할 수 있지만 수정은 할 수 없다.
- 내부 클래스에서 바깥 객체를 명확히 가리킬 때는 `바깥클래스이름.this`를 사용한다.
- 익명 객체는 인스턴스를 만들 때 동시에 클래스를 정의하는 방식이다.
- 익명 객체의 타입은 부모 타입이지만 실체는 자식 객체이다.
- 익명 구현 객체는 인터페이스를 즉석에서 구현한 객체이다.
- 메소드가 하나인 인터페이스는 람다식으로 표현할 수 있다.
- 익명 구현 객체는 자주 사용되므로 문법 연습이 필요하다.

## 정리 ✅

중첩 클래스는 클래스 내부에 클래스를 선언해서 관련 코드를 가까이 두고 접근 범위를 제한할 수 있는 문법이다.  
인스턴스 멤버 클래스는 바깥 객체가 필요하고, 정적 멤버 클래스는 바깥 객체 없이 사용할 수 있으며, 로컬 클래스는 메서드 내부에서만 사용할 수 있다.  
로컬 클래스는 외부 지역 변수에 접근할 수 있지만 수정은 불가능하며, 내부 클래스에서 바깥 객체를 가리킬 때는 `바깥클래스이름.this`를 사용한다.  
익명 객체는 클래스를 따로 만들지 않고 객체 생성 시점에 바로 정의하는 방식이고, 익명 구현 객체는 인터페이스를 즉석에서 구현하는 방식이다.  
시험 대비에서는 중첩 클래스의 종류, static 여부에 따른 차이, 로컬 클래스의 지역 변수 접근 제한, 익명 객체와 익명 구현 객체의 구조, 람다식과의 관계까지 함께 정리해 두는 것이 중요하다.
