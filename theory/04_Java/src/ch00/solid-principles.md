# ✨ 객체지향 설계원칙-SOLID

## 1. SOLID 설계 원칙

SOLID는 객체지향 설계에서 유지보수성과 확장성을 높이기 위해 사용하는 대표적인 설계 원칙이다.  
각 원칙의 앞 글자를 따서 SOLID라고 부른다.

SOLID는 다음 5가지 원칙으로 구성된다.

- SRP → 단일 책임 원칙
- OCP → 개방-폐쇄 원칙
- LSP → 리스코프 치환 원칙
- ISP → 인터페이스 분리 원칙
- DIP → 의존 역전 원칙

즉, SOLID는 객체지향 프로그램을 더 유연하고 변경에 강하게 만들기 위한 기준이라고 볼 수 있다. 📌

## 2. 단일 책임 원칙 SRP

SRP는 Single Responsibility Principle의 약자이다.  
단일 책임 원칙은 하나의 클래스가 하나의 책임만 가져야 한다는 원칙이다.

필기 기준으로는 다음 문장이 핵심이다.

- 클래스를 변경하는 이유는 단 한 개여야 한다.

즉, 어떤 클래스가 여러 책임을 가지고 있으면 변경 이유도 여러 개가 된다.  
이렇게 되면 유지보수가 어려워지고, 하나를 수정했을 때 다른 기능에 영향을 줄 가능성이 커진다.

그래서 SRP는 객체 지향의 기본이면서 가장 중요한 원칙으로 볼 수 있다. ✅

## 3. SRP가 중요한 이유

SRP를 지키면 클래스의 역할이 명확해진다.

즉,

- 수정해야 하는 이유가 명확함
- 코드 이해가 쉬움
- 테스트하기 쉬움
- 유지보수가 쉬움

이라는 장점이 있다.

반대로 하나의 클래스가 너무 많은 일을 하면 그 클래스는 수정에 약해지고, 다른 코드와 강하게 얽히기 쉽다. ⚠️

## 4. 개방-폐쇄 원칙 OCP

OCP는 Open-Closed Principle의 약자이다.  
개방-폐쇄 원칙은 기능 확장에는 열려 있고, 변경에는 닫혀 있어야 한다는 원칙이다.

즉, 새로운 기능을 추가할 수는 있어야 하지만 기존 코드를 자주 수정하지 않도록 설계해야 한다.

정리하면 다음과 같다.

- 기능 확장 → 열려 있어야 함
- 기존 코드 변경 → 닫혀 있어야 함

## 5. OCP 구현 방법

OCP는 주로 추상화와 다형성을 이용해서 구현한다.

즉, 구체적인 클래스에 직접 의존하기보다 상위 타입이나 인터페이스를 기준으로 설계한다.

필기 내용처럼 기능이 확장된다는 것은 구현체가 늘어난다는 의미로 볼 수 있다.  
이때 알고리즘이나 기능을 동일한 모양으로 추상화해서 전달하면, 기존 코드를 크게 바꾸지 않고 새로운 구현체를 추가할 수 있다.

즉, OCP는 "새 기능은 추가하되, 기존 코드는 덜 건드리게 만드는 설계"이다. 📌

## 6. 리스코프 치환 원칙 LSP

LSP는 Liskov Substitution Principle의 약자이다.  
리스코프 치환 원칙은 상위 타입 객체를 사용하는 코드에 하위 타입 객체를 넣어도 정상적으로 동작해야 한다는 원칙이다.

즉, 부모 타입 자리에 자식 타입 객체를 넣어도 프로그램의 의미가 깨지면 안 된다.

자바에서는 업캐스팅과 연결해서 이해할 수 있다.

    상위타입 변수 = 하위타입객체;

이 구조가 자연스럽게 동작하려면 자식 클래스가 부모 클래스의 규칙을 잘 지켜야 한다.

## 7. LSP가 깨지는 경우

LSP가 깨지는 대표적인 경우는 자식 클래스가 부모의 기본 동작 약속을 어기는 경우이다.

예를 들어 부모 타입으로 사용할 수 있다고 생각했는데, 특정 자식 객체를 넣었을 때 예외가 발생하거나 전혀 다른 방식으로 동작한다면 LSP를 지키지 못한 것이다.

즉, 상속은 단순히 코드 재사용이 아니라 부모 타입의 규격을 지키는 관계여야 한다. ⚠️

## 8. 인터페이스 분리 원칙 ISP

ISP는 Interface Segregation Principle의 약자이다.  
인터페이스 분리 원칙은 클라이언트가 자신이 사용하는 메서드에만 의존해야 한다는 원칙이다.

즉, 하나의 큰 인터페이스에 모든 기능을 몰아넣기보다, 사용하는 목적에 따라 작고 명확한 인터페이스로 나누는 것이 좋다.

필기 기준 핵심은 다음과 같다.

- 인터페이스는 그 인터페이스를 사용하는 클라이언트를 기준으로 분리해야 한다.

즉, 인터페이스는 제공자 기준이 아니라 사용자 기준으로 나누는 것이 중요하다. 📌

## 9. ISP가 필요한 이유

인터페이스가 너무 크면 사용하지 않는 메서드에도 의존하게 된다.

이렇게 되면 다음 문제가 생길 수 있다.

- 불필요한 구현 강제
- 변경 영향 범위 증가
- 클래스 역할 불명확
- 유지보수 어려움

따라서 필요한 기능만 모아 작은 인터페이스로 분리하는 것이 좋다. ✅

## 10. 의존 역전 원칙 DIP

DIP는 Dependency Inversion Principle의 약자이다.  
의존 역전 원칙은 구체적인 구현체보다 추상적인 타입에 의존해야 한다는 원칙이다.

즉, 클래스가 특정 구현 클래스에 직접 의존하면 강결합이 되고, 변경에 약해진다.  
반대로 인터페이스나 추상 클래스에 의존하면 약결합 구조를 만들 수 있다.

## 11. 강결합과 약결합

강결합은 한 객체가 다른 구체적인 객체에 강하게 의존하는 구조이다.  
구체 클래스가 바뀌면 사용하는 쪽 코드도 함께 바뀔 가능성이 크다.

약결합은 구체 클래스가 아니라 추상 타입에 의존하는 구조이다.  
이렇게 하면 실제 구현체가 바뀌어도 사용하는 쪽 코드는 크게 바뀌지 않는다.

필기 기준으로는 다음과 같이 연결해서 볼 수 있다.

- 약결합 → aggregation
- 강결합 → composition

즉, DIP는 강결합을 줄이고 약결합 구조를 만들기 위한 원칙이다. 📌

## 12. SOLID 원칙 간 연결

SOLID 원칙은 각각 따로 존재하지만 서로 연결되어 있다.

예를 들어 OCP를 지키려면 추상화와 다형성을 사용하게 되고, 그러면 DIP와도 연결된다.  
또한 ISP를 지키면 인터페이스가 작아지고, 클래스의 책임도 명확해지므로 SRP와도 연결된다.

즉, SOLID는 하나씩 따로 외우기보다 객체지향 설계를 좋게 만드는 하나의 흐름으로 이해하는 것이 좋다.

## 13. 중요 포인트 📌

- SOLID는 객체지향 설계의 대표적인 5가지 원칙이다.
- SRP는 클래스의 변경 이유가 하나여야 한다는 원칙이다.
- SRP는 객체 지향의 기본이며 가장 중요하다.
- OCP는 기능 확장에는 열려 있고 기존 코드 변경에는 닫혀 있어야 한다는 원칙이다.
- OCP는 추상화와 다형성을 이용해 구현한다.
- LSP는 상위 타입 자리에 하위 타입 객체가 들어가도 정상 동작해야 한다는 원칙이다.
- LSP는 업캐스팅과 연결된다.
- ISP는 클라이언트가 자신이 사용하는 메서드에만 의존해야 한다는 원칙이다.
- 인터페이스는 사용하는 클라이언트를 기준으로 분리해야 한다.
- DIP는 구체 구현체보다 추상 타입에 의존해야 한다는 원칙이다.
- DIP는 강결합을 줄이고 약결합을 만들기 위한 원칙이다.

## 정리 ✅

SOLID는 객체지향 설계를 더 유연하고 유지보수하기 쉽게 만들기 위한 5가지 설계 원칙이다.  
SRP는 클래스가 하나의 책임만 가져야 한다는 원칙이고, OCP는 기존 코드를 바꾸지 않고 기능을 확장할 수 있어야 한다는 원칙이다.  
LSP는 부모 타입 자리에 자식 타입 객체가 들어가도 정상 동작해야 한다는 원칙이며, ISP는 클라이언트가 필요한 메서드에만 의존하도록 인터페이스를 분리하는 원칙이다.  
DIP는 구체 클래스가 아니라 추상 타입에 의존해서 강결합을 줄이고 약결합 구조를 만드는 원칙이다.  
시험 대비에서는 각 원칙의 이름, 의미, 핵심 문장, 그리고 상속·인터페이스·다형성과 어떻게 연결되는지 함께 정리해 두는 것이 중요하다.
