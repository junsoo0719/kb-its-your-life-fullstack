# ✨ Iterator - 처리를 반복하다

## 1. Iterator 패턴의 개념

Iterator 패턴은 데이터를 순서대로 가리키면서 반복 처리할 수 있도록 만든 패턴이다.  
즉, 여러 데이터가 모여 있는 구조를 처음부터 끝까지 하나씩 탐색할 수 있게 해 주는 방식이다.

필기 내용처럼 보면, `for`문에서 사용하는 변수 `i`의 기능을 추상화해서 일반화한 것이라고 이해할 수 있다. 📌

즉, 배열이든 컬렉션이든 내부 구조를 직접 몰라도 "순서대로 접근하면서 반복 처리"할 수 있게 만드는 것이 Iterator 패턴의 핵심이다.

## 2. Iterator 패턴의 역할

Iterator 패턴은 크게 다음과 같은 역할을 가진다.

- 순서대로 가리킴
- 전체 검색
- 처리 반복

즉, 어떤 집합체 안에 들어 있는 요소들을 처음부터 끝까지 차례대로 확인하면서 같은 작업을 반복할 수 있게 한다.

예를 들어 "모든 원소 출력", "조건 검사", "합계 계산" 같은 작업은 Iterator 패턴이 잘 맞는 대표적인 예이다.

## 3. advanced for문과 Iterator 패턴

자바의 향상된 `for`문(advanced for문)도 Iterator 패턴과 연결된다.

    for (int i : arr) {
        // 반복 처리
    }

이 문법은 배열이나 반복 가능한 객체를 순서대로 꺼내서 처리하는 방식이다.  
즉, 내부적으로는 Iterator 패턴의 아이디어를 사용하고 있다고 볼 수 있다.

필기 내용 기준으로 보면, `arr`는 Iterator 패턴이 정의된 객체라고 이해할 수 있다.  
즉, 반복 가능한 구조이기 때문에 향상된 `for`문으로 순회할 수 있는 것이다. ✅

## 4. Iterable 인터페이스

`Iterable<E>`는 집합체를 나타내는 인터페이스이다.

여기서 집합체란 "처리를 반복할 대상"을 의미한다.  
즉, 여러 요소를 가지고 있어서 반복 접근이 가능한 구조를 표현하는 인터페이스이다.

정리하면 다음과 같다.

- `Iterable<E>` → 반복할 대상(집합체)
- 내부 요소를 순서대로 꺼낼 수 있는 기반 제공

즉, 어떤 클래스가 `Iterable`을 구현하면 "이 객체는 반복 가능한 대상이다"라고 볼 수 있다.

## 5. Iterator 인터페이스

`Iterator<E>`는 실제로 처리를 반복하는 반복자를 나타내는 인터페이스이다.

즉, `Iterable`이 반복할 대상을 나타낸다면, `Iterator`는 그 대상을 실제로 순회하는 역할을 담당한다.

정리하면 다음과 같이 구분할 수 있다.

- `Iterable<E>` → 반복할 대상
- `Iterator<E>` → 반복을 수행하는 도구

즉, 집합체와 반복자 역할이 분리되어 있다는 점이 Iterator 패턴의 중요한 특징이다. 📌

## 6. Iterator 패턴으로 구현된 클래스

Iterator 패턴으로 구현된 클래스는 향상된 `for`문을 사용할 수 있다.

즉, 반복 가능한 구조로 설계된 클래스라면 사용자는 내부 구현을 몰라도 다음처럼 간단하게 순회할 수 있다.

    for (T x : collection) {
        // 처리
    }

여기서 중요한 점은 사용자가 인덱스나 내부 저장 구조를 직접 다루지 않아도 된다는 것이다.

즉, 반복 방식이 표준화되어 있기 때문에 코드가 더 간단하고 읽기 쉬워진다.

## 7. Iterator 패턴을 사용하는 이유

Iterator 패턴을 사용하는 가장 큰 이유는 구현과 반복 처리를 분리할 수 있기 때문이다.

즉, 컬렉션 내부 구조가 배열이든 리스트든 다른 형태든, 사용하는 쪽의 반복문 구조는 거의 바뀌지 않는다.

예를 들어 다음과 같이 쓸 수 있다.

    for (T x : collection) {
        ...
    }

이 방식의 장점은 다음과 같다.

- 내부 구현을 몰라도 반복 가능
- 컬렉션 종류가 바뀌어도 반복 코드 변화가 적음
- 코드 재사용성과 유지보수성이 좋아짐

즉, Iterator 패턴은 "반복 방법을 통일해서 사용하는 패턴"이라고 이해하면 된다. ✅

## 8. 구현과 사용의 분리

Iterator 패턴의 핵심 장점 중 하나는 구현과 사용을 분리한다는 점이다.

예를 들어 내부 자료구조가 배열인지, 연결 리스트인지, 다른 컬렉션인지에 따라 실제 저장 방식은 달라질 수 있다.  
하지만 Iterator 패턴을 사용하면 외부에서는 같은 방식으로 순회할 수 있다.

즉,

- 내부 구현 → 클래스가 담당
- 반복 사용 방식 → Iterator가 담당

으로 역할이 나뉜다.

이 덕분에 내부 구조가 바뀌어도 외부 코드를 크게 수정하지 않아도 된다. 📌

## 9. for문과 Iterator 패턴 비교

일반 `for`문은 보통 인덱스를 직접 다루면서 반복한다.

예를 들면 다음과 같다.

    for (int i = 0; i < arr.length; i++) {
        ...
    }

이 방식은 배열 인덱스를 직접 사용하기 때문에 구조가 단순할 때는 편리하다.  
하지만 컬렉션 구조가 달라지거나 인덱스 접근이 적절하지 않은 경우에는 불편할 수 있다.

반면 Iterator 패턴은 인덱스를 직접 다루지 않고도 순차 접근이 가능하다.

즉,

- 일반 `for`문 → 인덱스 중심
- Iterator 패턴 → 반복자 중심

이라고 정리할 수 있다.

## 10. 중요 포인트 📌

- Iterator 패턴은 데이터를 순서대로 가리키며 반복 처리하는 패턴이다.
- `for`문의 변수 `i` 역할을 추상화하고 일반화한 것으로 볼 수 있다.
- Iterator 패턴은 전체 검색과 반복 처리에 적합하다.
- 향상된 `for`문은 Iterator 패턴과 연결된다.
- `Iterable<E>`는 반복할 대상인 집합체를 나타낸다.
- `Iterator<E>`는 실제 반복을 수행하는 반복자를 나타낸다.
- Iterator 패턴으로 구현된 클래스는 향상된 `for`문 사용이 가능하다.
- Iterator 패턴은 구현과 반복 사용 방식을 분리해 준다.
- 컬렉션의 종류가 달라도 반복 코드의 변화가 적다는 장점이 있다.

## 정리 ✅

Iterator 패턴은 여러 요소를 순서대로 접근하면서 같은 처리를 반복할 수 있도록 만든 패턴이다.  
이 패턴은 `for`문의 인덱스 역할을 추상화한 것으로 이해할 수 있으며, 집합체와 반복자를 분리해서 설계한다는 점이 핵심이다.  
자바에서는 `Iterable<E>`가 반복할 대상, `Iterator<E>`가 실제 반복을 수행하는 객체를 의미하며, 이런 구조로 구현된 클래스는 향상된 `for`문을 사용할 수 있다.  
Iterator 패턴의 가장 큰 장점은 내부 구현과 반복 사용 방식을 분리할 수 있다는 점이며, 덕분에 컬렉션의 종류가 바뀌더라도 반복문 코드는 거의 바뀌지 않는다.
