# ✨ 람다식

## 1. 람다식의 개념

람다식은 메서드가 1개인 클래스나 인터페이스의 구현을 간단하게 표현하는 문법이다.  
즉, 익명 구현 객체를 더 짧게 작성하는 방식이라고 볼 수 있다. 📌

기본 형식은 다음과 같다.

    (매개변수, ...) -> {
        처리 내용
    }

예를 들어 다음과 같은 인터페이스가 있다고 하자.

    public interface Calculate {
        void calculate(int x, int y);
    }

이 인터페이스는 추상 메소드가 하나이므로 람다식으로 구현할 수 있다.

    action((x, y) -> {
        int result = x + y;
        System.out.println(result);
    });

즉, 람다식은 익명 구현 객체에 대한 단축 표기이다.

## 2. 함수형 인터페이스

함수형 인터페이스는 단 하나의 추상 메소드만 가지는 인터페이스이다.

예를 들면 다음과 같다.

    @FunctionalInterface
    public interface Calculable {
        void calculate(int x, int y);
    }

이 인터페이스는 추상 메소드가 `calculate()` 하나뿐이므로 함수형 인터페이스이다.

람다식은 이런 함수형 인터페이스의 구현체를 정의하는 방법이다.

    (x, y) -> {
        ...
    }

즉, 람다식은 아무 인터페이스에나 사용할 수 있는 것이 아니라 추상 메소드가 하나인 함수형 인터페이스에 사용할 수 있다. ✅

## 3. @FunctionalInterface

`@FunctionalInterface`는 해당 인터페이스가 함수형 인터페이스임을 보장하는 어노테이션이다.

이 어노테이션을 붙이면 컴파일러가 추상 메소드가 정확히 하나인지 검사한다.

즉,

- 추상 메소드가 1개 → 정상
- 추상 메소드가 0개 또는 2개 이상 → 컴파일 에러

가 발생한다.

`@FunctionalInterface`는 필수는 아니지만, 실수를 줄이기 위해 붙이는 것이 좋다. 📌

## 4. 매개변수가 없는 람다식

매개변수가 없는 람다식은 소괄호를 비워서 작성한다.

    () -> {
        실행문;
    }

실행문이 하나라면 중괄호를 생략할 수 있다.

    () -> 실행문

즉, 매개변수가 없어도 `()`는 반드시 작성해야 한다.

## 5. 매개변수가 있는 람다식

매개변수가 있는 람다식은 소괄호 안에 매개변수를 작성한다.

    (x, y) -> {
        실행문;
    }

람다식은 타입 추론이 가능하므로 매개변수 타입을 생략할 수 있다.

예를 들어 다음처럼 작성할 수 있다.

    (x, y) -> {
        int result = x + y;
    }

또는 `var`를 사용할 수도 있다.

    (var x, var y) -> {
        int result = x + y;
    }

`var`는 타입을 컴파일러가 추론하도록 하는 문법으로, C++의 `auto`와 비슷한 개념으로 이해할 수 있다.

다만 람다 매개변수에서 `var`를 사용할 때는 모든 매개변수에 일관되게 사용해야 한다. ⚠️

## 6. 리턴값이 있는 람다식

리턴값이 있는 람다식에서는 `return`을 사용할 수 있다.

    (x, y) -> {
        return x + y;
    }

하지만 리턴문 하나만 있는 경우에는 중괄호와 `return` 키워드를 생략할 수 있다.

    (x, y) -> x + y

즉, 간단한 계산식이나 값 반환은 짧게 표현할 수 있다. ✅

## 7. 람다식의 핵심 의미

람다식은 메서드가 하나인 인터페이스의 구현체를 정의하는 방법이다.

즉, 다음 흐름으로 이해하면 된다.

1. 함수형 인터페이스가 있다.
2. 추상 메소드가 하나 있다.
3. 그 메소드의 구현 내용을 람다식으로 작성한다.
4. 컴파일러가 익명 구현 객체로 변환한다.

따라서 람다식은 객체지향 문법 위에서 동작하는 함수형 표현 방식이라고 볼 수 있다.

## 8. 메소드 참조

메소드 참조는 람다식이 단순히 기존 메소드를 호출하는 경우 더 간단하게 표현하는 문법이다.  
중요한 문법이므로 꼭 구분해서 이해해야 한다. 📌

예를 들어 다음 람다식이 있다고 하자.

    (left, right) -> Math.max(left, right)

이 경우 단순히 `Math.max()`를 호출하는 것이므로 다음처럼 줄일 수 있다.

    Math::max

여기서 `::`는 참조 연산자이다.

기본 형식은 다음과 같다.

    클래스명::메소드명

## 9. 정적 메소드 참조

정적 메소드를 참조할 때는 클래스명을 기준으로 작성한다.

    클래스::메소드

예를 들어 `Math.max()`는 정적 메소드이므로 다음처럼 표현할 수 있다.

    Math::max

즉, 기존 static 메소드를 그대로 람다식 자리에 전달하는 방식이다.

## 10. 인스턴스 메소드 참조

인스턴스 메소드를 참조할 때는 참조 변수가 필요하다.

형식은 다음과 같다.

    참조변수::메소드

즉, 이미 생성된 객체의 메소드를 람다식 대신 사용하는 방식이다.

정리하면 다음과 같다.

- 정적 메소드 참조 → `클래스::메소드`
- 인스턴스 메소드 참조 → `참조변수::메소드`

## 11. 매개변수의 메소드 참조

람다식에서 첫 번째 매개변수의 인스턴스 메소드를 호출하고, 두 번째 매개변수를 그 메소드의 매개값으로 사용하는 경우가 있다.

형식은 다음과 같다.

    (a, b) -> {
        a.instanceMethod(b);
    }

이런 경우 다음처럼 줄일 수 있다.

    클래스::instanceMethod

예를 들어 문자열 비교를 생각해 보자.

    int compare(String a, String b) {
        return a.compareTo(b);
    }

람다식으로 쓰면 다음과 같다.

    (a, b) -> a.compareTo(b)

메소드 참조를 사용하면 다음처럼 축약할 수 있다.

    String::compareTo

즉, 첫 번째 매개변수 객체의 메소드를 호출하는 구조라면 `클래스::인스턴스메소드` 형태로 줄일 수 있다. 📌

## 12. static 메소드와 인스턴스 메소드 구분

메소드 참조를 사용할 때는 메소드가 static인지 인스턴스 메소드인지 판단해야 한다.

특히 메소드 매개변수가 2개이고 인스턴스 메소드인 경우에는 헷갈리기 쉽다.

예를 들어

    String::compareTo

는 `String` 클래스의 static 메소드를 호출하는 것이 아니라, 첫 번째 매개변수인 String 객체의 `compareTo()`를 호출하는 형태이다. ⚠️

즉, `클래스::메소드` 형태라고 해서 항상 static 메소드 참조는 아니다.  
메소드의 선언 형태와 람다식의 매개변수 구조를 함께 보고 판단해야 한다.

## 13. 생성자 참조

생성자 참조는 람다식이 단순히 객체를 생성해서 반환하는 경우 사용할 수 있다.

예를 들어 다음 람다식이 있다고 하자.

    (a, b) -> {
        return new 클래스(a, b);
    }

이 경우 다음처럼 줄일 수 있다.

    클래스::new

여기서 `new`는 생성자를 의미한다.

즉, 생성자 참조는 매개변수를 받아 그대로 생성자의 매개변수로 전달하는 방식이다.

## 14. 생성자 결정 방식

생성자 참조에서 어떤 생성자가 호출될지는 람다식의 매개변수 형태에 의해 결정된다.

즉,

    클래스::new

라고만 작성해도, 함수형 인터페이스의 추상 메소드 매개변수에 따라 호출할 생성자가 결정된다.

만약 해당 매개변수에 맞는 생성자가 없으면 컴파일 에러가 발생한다. ⚠️

즉, 생성자 참조는 간단하지만, 반드시 함수형 인터페이스의 메소드 형태와 생성자의 매개변수 형태가 맞아야 한다.

## 15. 중요 포인트 📌

- 람다식은 익명 구현 객체의 단축 표기이다.
- 람다식은 추상 메소드가 하나인 함수형 인터페이스에 사용할 수 있다.
- `@FunctionalInterface`는 함수형 인터페이스임을 보장한다.
- 매개변수가 없는 람다식은 `()`를 사용한다.
- 실행문이 하나이면 중괄호를 생략할 수 있다.
- 매개변수 타입은 타입 추론으로 생략할 수 있다.
- `var`를 사용할 수도 있지만 일관되게 사용해야 한다.
- 리턴문 하나만 있으면 중괄호와 `return`을 생략할 수 있다.
- 메소드 참조는 기존 메소드 호출만 하는 람다식을 줄인 문법이다.
- `::`는 참조 연산자이다.
- 정적 메소드 참조는 `클래스::메소드` 형태이다.
- 인스턴스 메소드 참조는 `참조변수::메소드` 형태이다.
- 첫 번째 매개변수의 인스턴스 메소드를 호출하는 경우 `클래스::인스턴스메소드` 형태를 사용할 수 있다.
- 생성자 참조는 `클래스::new` 형태이다.
- 생성자 참조는 함수형 인터페이스의 매개변수 형태와 맞는 생성자가 있어야 한다.

## 정리 ✅

람다식은 추상 메소드가 하나인 함수형 인터페이스의 구현체를 간단하게 표현하는 문법이다.  
기본 형식은 `(매개변수) -> { 실행문 }`이며, 매개변수 타입 생략, 중괄호 생략, `return` 생략 등을 통해 코드를 짧게 작성할 수 있다.  
`@FunctionalInterface`는 해당 인터페이스가 함수형 인터페이스인지 컴파일러가 검사하도록 해 주며, 람다식은 결국 익명 구현 객체의 단축 표현으로 동작한다.  
또한 메소드 참조는 기존 메소드를 호출하는 람다식을 `::` 연산자로 더 간단히 표현하는 문법이고, 생성자 참조는 객체 생성을 `클래스::new` 형태로 표현한다.  
시험 대비에서는 함수형 인터페이스의 조건, 람다식 생략 규칙, 메소드 참조의 종류, `String::compareTo` 같은 매개변수 메소드 참조, 생성자 참조의 결정 방식을 함께 정리하는 것이 중요하다.
