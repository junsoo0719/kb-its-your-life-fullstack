# ✨ 상속2

## 1. 객체 타입 확인

자바에서는 객체가 어떤 타입인지 확인할 때 `instanceof` 연산자를 사용한다.  
`instanceof`는 좌항의 객체가 우항의 타입에 해당하면 `true`, 아니면 `false`를 반환한다.

즉, 부모 타입으로 선언된 참조 변수가 실제로 어떤 자식 객체를 가리키는지 확인할 때 자주 사용한다.

    if (parent instanceof Child) {
        Child child = (Child) parent;
    }

위 코드의 흐름은 다음과 같다.

- `parent` 변수의 타입은 `Parent`이다.
- 따라서 `Child`에만 있는 기능은 바로 사용할 수 없다.
- 그래서 먼저 `instanceof`로 실제 객체가 `Child`인지 확인한다.
- 확인이 끝나면 강제 타입 변환을 해서 `Child` 타입 변수에 담아 사용한다.

이 과정을 거치는 이유는 잘못된 형변환을 막기 위해서이다.  
만약 실제 객체가 `Child`가 아닌데도 강제로 형변환하면 예외가 발생한다. ⚠️

## 2. ClassCastException

부모 타입을 자식 타입으로 강제 변환할 때 실제 객체가 해당 자식 타입이 아니면 `ClassCastException`이 발생할 수 있다.

즉, 형변환은 문법적으로 가능해 보여도 실제 객체 타입이 맞지 않으면 실행 중 오류가 생긴다.

예를 들어 다음과 같은 상황이다.

- 변수 타입은 `Parent`
- 실제 객체는 `Parent`
- 그런데 이를 `Child`로 강제 형변환

이 경우에는 자식 객체가 아닌데 자식처럼 다루려고 했기 때문에 예외가 발생한다.

그래서 자바에서는 보통 `instanceof`로 먼저 확인한 뒤 형변환하는 방식이 안전하다. 📌

## 3. Java 12 이후의 instanceof

Java 12부터는 `instanceof` 결과가 `true`일 경우 우측 타입의 변수를 바로 사용할 수 있는 방식이 지원된다.

즉, 예전처럼 검사 후 다시 강제 타입 변환 코드를 따로 작성하지 않아도 되는 경우가 생겼다.

이 기능의 핵심은 다음과 같다.

- 타입 검사와 변수 선언을 한 번에 처리할 수 있음
- 코드가 더 짧아짐
- 형변환 실수를 줄일 수 있음

즉, 최신 자바에서는 `instanceof`를 더 편리하고 안전하게 사용할 수 있다.

## 4. 추상 클래스

추상 클래스는 객체를 직접 생성할 수 있는 실체 클래스들의 공통 필드나 메소드를 뽑아내어 선언한 클래스이다.

추상 클래스는 클래스 선언 앞에 `abstract` 키워드를 붙여서 만든다.

추상 클래스의 특징은 다음과 같다.

- 실체 클래스들의 부모 역할을 한다.
- 공통적인 필드와 메소드를 물려줄 수 있다.
- `new` 연산자로 직접 객체를 만들 수 없다.
- 반드시 상속을 통해 자식 클래스가 사용한다.

즉, 추상 클래스는 공통 기능을 미리 정리해 두는 "설계용 부모 클래스"라고 이해하면 된다.

## 5. 추상 클래스가 필요한 이유

여러 자식 클래스가 공통된 속성과 기능을 가지고 있다면, 그 공통 부분을 추상 클래스로 묶어 둘 수 있다.

이렇게 하면 다음과 같은 장점이 있다.

- 중복 코드 감소
- 공통 기능 재사용 가능
- 클래스 구조를 더 명확하게 설계 가능
- 자식 클래스들의 공통 성격을 부모 클래스로 표현 가능

즉, 추상 클래스는 단순히 상속을 위한 문법이 아니라 공통 구조를 정리하기 위한 중요한 도구이다. ✅

## 6. 추상 메소드와 재정의

자식 클래스들이 공통적으로 가져야 하는 메소드가 있지만, 실행 내용은 자식마다 달라야 할 때 추상 메소드를 사용한다.

추상 메소드는 메소드의 선언부만 있고 실행 내용은 없다.  
즉, 자식 클래스가 반드시 재정의해서 사용해야 하는 메소드이다.

추상 메소드의 특징은 다음과 같다.

- `abstract` 키워드를 사용한다.
- 메소드 몸체인 `{}`가 없다.
- 자식 클래스에서 반드시 오버라이딩해야 한다.

즉, 추상 메소드는 "이 기능은 반드시 있어야 하지만, 구현은 자식이 알아서 해야 한다"는 의미를 가진다.

## 7. 일반 메소드와 추상 메소드 차이

일반 메소드는 선언과 구현이 함께 있다.  
반면 추상 메소드는 선언만 있고 구현이 없다.

정리하면 다음과 같다.

- 일반 메소드 → 선언 + 실행 내용 존재
- 추상 메소드 → 선언만 존재, 실행 내용 없음

따라서 추상 메소드를 가진 클래스는 완전한 클래스가 아니므로 보통 추상 클래스로 선언해야 한다.

## 8. 추상 메소드와 오버라이딩 관계

추상 메소드는 자식 클래스에서 반드시 재정의해야 한다.  
즉, 추상 메소드는 오버라이딩을 전제로 만들어진 메소드라고 볼 수 있다.

이 구조의 의미는 다음과 같다.

- 부모는 메소드의 형식만 정해 줌
- 자식은 그 형식에 맞게 내용을 구현함
- 공통된 메소드 이름을 유지하면서 동작은 다르게 만들 수 있음

이것은 다형성과도 연결되는 중요한 개념이다. 📌

## 9. 전략 패턴

전략 패턴은 알고리즘을 추상화해서 상황에 따라 다른 방식으로 동작하게 만드는 패턴이다.

즉, 공통된 인터페이스나 추상 구조를 두고 실제 동작 방식은 각각 다른 클래스로 분리해서 사용하는 방식이다.

이 패턴은 다음과 같은 장점이 있다.

- 알고리즘을 쉽게 교체할 수 있음
- 코드 수정 없이 새로운 전략 추가 가능
- 역할 분리가 명확해짐

즉, "무엇을 할지"와 "어떻게 할지"를 분리하는 설계 방식이라고 이해하면 된다.

## 10. 전략 패턴과 SRP

전략 패턴은 SRP(Single Responsibility Principle, 단일 책임 원칙)와 연결된다.

SRP는 하나의 클래스는 하나의 책임만 가져야 한다는 원칙이다.

전략 패턴을 사용하면 알고리즘이나 동작 방식을 별도 클래스로 분리할 수 있으므로, 하나의 클래스에 여러 기능이 몰리지 않게 된다.

즉, 전략 패턴은 다음과 같은 점에서 SRP와 잘 맞는다.

- 기능별 역할 분리 가능
- 변경 이유를 분리할 수 있음
- 유지보수성과 확장성이 좋아짐

## 11. 중요 포인트 📌

- `instanceof`는 객체의 실제 타입을 확인하는 연산자이다.
- 부모 타입 참조 변수는 자식의 기능을 바로 사용할 수 없으므로 필요하면 형변환해야 한다.
- 잘못된 강제 형변환은 `ClassCastException`을 발생시킬 수 있다.
- Java 12부터는 `instanceof` 검사 결과가 참일 때 타입 변수를 더 편하게 사용할 수 있다.
- 추상 클래스는 공통 필드와 메소드를 정리한 부모 클래스이다.
- 추상 클래스는 `new`로 직접 객체를 생성할 수 없다.
- 추상 메소드는 선언만 있고 실행 내용이 없다.
- 추상 메소드는 자식 클래스가 반드시 재정의해야 한다.
- 전략 패턴은 알고리즘을 추상화해서 교체 가능하게 만드는 방식이다.
- 전략 패턴은 SRP와 연결되어 역할 분리에 도움이 된다.

## 정리 ✅

상속에서는 부모 타입과 자식 타입의 관계를 정확히 이해하는 것이 중요하다.  
`instanceof`는 객체의 실제 타입을 확인할 때 사용하며, 안전한 형변환을 위해 꼭 필요한 연산자이다.  
또한 추상 클래스는 공통 구조를 정리하는 부모 클래스이고, 추상 메소드는 자식 클래스가 반드시 구현해야 하는 메소드이다.  
이 개념은 단순한 문법이 아니라 상속, 오버라이딩, 다형성, 설계 원칙까지 연결된다.  
특히 전략 패턴은 알고리즘을 추상화해서 역할을 분리하는 방식이며, SRP와도 밀접하게 연결되는 중요한 설계 개념이다.
