# ✨ 상속

## 1. 상속의 개념

상속은 기존 클래스의 기능을 물려받아 새로운 클래스를 만드는 객체 지향 문법이다.  
자식 클래스는 부모 클래스의 멤버를 사용할 수 있고, 필요한 기능을 추가하거나 변경할 수 있다.

UML에서는 상속 관계를 세모 화살표로 표현한다.

- 세모 화살표 → 상속 관계
- 일반 화살표 → 사용 관계(use)
- 세모가 가리키는 쪽 → 부모 클래스

자바에서 상속은 `extends` 키워드를 사용한다.

    class Child extends Parent {
        ...
    }

즉, 상속은 부모 클래스를 기반으로 자식 클래스의 기능을 확장하는 방식이다. 📌

## 2. 상속의 장점과 특징

상속의 가장 큰 장점은 코드 재사용이다.

부모 클래스에 공통 기능을 작성해 두면 자식 클래스에서 다시 작성하지 않고 사용할 수 있다.  
즉, 중복 코드를 줄이고 클래스 구조를 더 체계적으로 만들 수 있다.

하지만 자바는 단일 상속만 지원한다.

- 하나의 클래스는 하나의 부모 클래스만 상속 가능
- 장점: 구조가 단순하고 충돌이 적음
- 단점: 여러 클래스를 동시에 상속할 수 없음

이 단점은 인터페이스를 통해 어느 정도 극복할 수 있다.

## 3. 부모 생성자 호출

자식 객체를 생성하면 부모 객체가 먼저 생성된 다음 자식 객체가 생성된다.  
즉, 부모가 먼저 초기화되고 그 다음 자식이 초기화된다.

실제로는 부모 부분과 자식 부분이 함께 구성된 인스턴스가 만들어진다고 이해하면 된다.

자식 클래스에는 부모를 참조하는 `super`가 있고, 자기 자신을 참조하는 `this`가 있다.

- `this` → 자기 자신 참조
- `super` → 부모 참조

## 4. this()와 super()

생성자 안에서 `this()`를 사용하면 자기 자신의 다른 생성자를 호출한다.

    this(...);

반면 `super()`를 사용하면 부모 생성자를 호출한다.

    super(...);

자식 생성자에서 `super()`를 생략하면 컴파일러가 자동으로 부모의 기본 생성자를 호출하는 코드를 넣는다.

즉, 다음 코드가 자동으로 들어간다고 이해하면 된다.

    super();

따라서 부모 클래스에 기본 생성자가 반드시 있어야 한다.  
만약 부모에게 기본 생성자가 없고, 자식 생성자에서 명시적으로 부모 생성자를 호출하지 않으면 컴파일 에러가 발생한다. ⚠️

## 5. 메소드 오버라이딩

메소드 오버라이딩은 부모 클래스의 메소드를 자식 클래스에서 재정의하는 것이다.

여기서 중요한 점은 "덮어써서 부모 메소드가 사라지는 것"이 아니라는 점이다.  
부모와 자식 모두 메소드를 가지고 있지만, 실행 시에는 실제 객체의 메소드가 호출된다.

즉, 타입보다는 실제 참조하고 있는 인스턴스가 중요하다. 📌

## 6. 오버라이딩 규칙

오버라이딩할 때는 부모 메소드와 같은 형태로 재정의해야 한다.

또한 접근 제한자는 변경할 수 있지만, 더 강하게 제한할 수는 없다.

예를 들어

- `public` → `private` 불가
- 부모보다 좁은 접근 범위로 변경 불가

오버라이딩 실수를 줄이기 위해 `@Override` 어노테이션을 사용한다.

    @Override
    public void method() {
        ...
    }

`@Override`를 붙이면 컴파일러가 오버라이딩 규칙에 맞는지 검사해 준다.  
오타나 매개변수 실수 등을 잡을 수 있어서 사용하는 것이 좋다. ✅

## 7. 부모 메소드 호출

자식 클래스에서 부모 클래스의 메소드를 호출하고 싶다면 `super.메소드명()`을 사용한다.

    super.method();

즉, 자식에서 오버라이딩한 메소드 안에서도 부모의 원래 기능을 호출할 수 있다.

이 방식은 부모 기능을 유지하면서 자식에서 기능을 추가할 때 유용하다.

## 8. final 클래스

`final`이 붙은 클래스는 더 이상 상속할 수 없다.

즉, 마지막 클래스라는 의미이며 부모 역할을 할 수 없다.

대표적인 예는 `String` 클래스이다.  
`String`은 final 클래스이기 때문에 사용자가 상속해서 새로운 String 클래스를 만들 수 없다.

즉,

- `final class` → 상속 불가
- 부모 클래스로 사용 불가

이다.

## 9. final 메소드

`final`은 메소드에도 붙일 수 있다.

`final` 메소드는 자식 클래스에서 오버라이딩할 수 없다.

즉, 부모가 정의한 기능을 자식이 변경하지 못하게 막고 싶을 때 사용한다.

- `final class` → 상속 불가
- `final method` → 오버라이딩 불가

로 정리할 수 있다.

## 10. protected 접근 제한자

`protected`는 상속과 관련된 접근 제한자이다.

특히 패키지가 다른 경우에도 자식 클래스가 부모의 멤버에 접근해야 할 때 사용할 수 있다.

정리하면 다음과 같다.

- 같은 패키지 → 접근 가능
- 다른 패키지 → 상속 관계라면 접근 가능

단, `private` 멤버는 자식 클래스에서도 직접 접근할 수 없다. ⚠️

## 11. 자동 타입 변환

자동 타입 변환은 자식 타입 객체를 부모 타입 변수에 대입하는 것이다.  
이를 업캐스팅이라고도 한다.

    부모타입 변수 = 자식타입객체;

예를 들면 다음과 같다.

    Cat cat = new Cat();
    Animal animal = cat;

이 경우 `cat`과 `animal`은 같은 인스턴스를 참조한다.

    cat == animal   // true

자식 객체는 부모 타입으로 자동 변환될 수 있다.  
정보 손실이 없기 때문에 자동으로 허용된다. 📌

## 12. 자동 타입 변환 시 사용 가능한 멤버

자동 타입 변환이 일어나면 실제 객체는 자식 객체이지만, 변수 타입은 부모 타입이다.

따라서 부모 타입 변수로는 부모 클래스에 정의된 멤버만 사용할 수 있다.

예를 들어

- `cat` 변수 → Cat이 가진 모든 메소드 사용 가능
- `animal` 변수 → Animal에 정의된 메소드만 사용 가능

즉, 실제 객체가 Cat이어도 변수 타입이 Animal이면 Cat에만 있는 메소드는 바로 사용할 수 없다.

## 13. 오버라이딩된 메소드 호출

부모 타입 변수로 자식 객체를 참조하더라도, 부모와 자식 양쪽에 모두 존재하는 메소드라면 실제 객체의 메소드가 호출된다.

즉, 실체 객체가 Cat이면 Cat에서 오버라이딩한 메소드가 실행된다.

핵심은 다음과 같다.

- 변수 타입 → 사용할 수 있는 메소드 범위 결정
- 실제 객체 → 실행될 메소드 결정

이 개념은 다형성을 이해하는 데 매우 중요하다. ✅

## 14. 강제 타입 변환

부모 타입으로 변환된 객체를 다시 자식 타입으로 사용하려면 강제 타입 변환이 필요하다.

    자식타입 변수 = (자식타입) 부모타입객체;

하지만 항상 가능한 것은 아니다.  
실제 객체가 자식 타입일 때만 가능하다.

즉, 부모 타입 변수에 담겨 있어도 실체가 자식 객체라면 자식 타입으로 다시 변환할 수 있다.

강제 타입 변환은 자식 클래스에만 있는 멤버를 잠깐 사용해야 할 때 사용한다. ⚠️

## 15. 다형성

다형성은 사용 방법은 동일하지만 실행 결과가 다양하게 나오는 성질이다.

상속에서 다형성은 다음 구조로 이해할 수 있다.

- 부모 → 메소드 모양 정의
- 자식 → 실제 할 일 정의
- 사용자는 부모 타입으로 사용
- 실제 실행 결과는 자식 객체에 따라 달라짐

즉, 부모는 규격 또는 표준 역할을 하고, 자식은 그 규격에 맞게 실제 동작을 구현한다.

## 16. 매개변수 다형성

메소드가 클래스 타입의 매개변수를 가지고 있을 경우, 그 타입의 자식 객체도 전달할 수 있다.

즉, 메소드 매개변수가 부모 타입이면 자식 객체를 넣을 수 있다.

    void method(Animal animal) {
        ...
    }

이 메소드는 다음과 같이 호출할 수 있다.

    method(new Cat());
    method(new Dog());

이때 어떤 자식 객체가 전달되느냐에 따라 실행 결과가 달라질 수 있다.

즉, 매개변수 다형성은 하나의 메소드가 다양한 자식 객체를 처리할 수 있게 해 주는 중요한 개념이다. 📌

## 17. 중요 포인트 📌

- 상속은 `extends` 키워드를 사용한다.
- UML에서 상속은 세모 화살표로 표현하고, 세모가 가리키는 쪽이 부모이다.
- 상속의 장점은 코드 재사용이다.
- 자바는 단일 상속만 지원한다.
- 자식 객체 생성 시 부모가 먼저 초기화된다.
- `this()`는 같은 클래스의 다른 생성자를 호출한다.
- `super()`는 부모 생성자를 호출한다.
- 자식 생성자에서 `super()`를 생략하면 부모 기본 생성자가 자동 호출된다.
- 메소드 오버라이딩은 부모 메소드를 자식에서 재정의하는 것이다.
- 오버라이딩 시 접근 제한자는 더 강하게 줄일 수 없다.
- `@Override`는 오버라이딩 규칙을 검사해 준다.
- `final` 클래스는 상속할 수 없고, `final` 메소드는 오버라이딩할 수 없다.
- 자식 객체는 부모 타입으로 자동 타입 변환될 수 있다.
- 부모 타입 변수로는 부모에 정의된 멤버만 사용할 수 있다.
- 오버라이딩된 메소드는 실제 객체 기준으로 실행된다.
- 강제 타입 변환은 실제 객체가 자식 타입일 때만 가능하다.
- 다형성은 같은 사용 방법으로 다양한 실행 결과가 나오는 성질이다.
- 매개변수 타입이 부모 클래스이면 자식 객체도 전달할 수 있다.

## 정리 ✅

상속은 부모 클래스의 기능을 자식 클래스가 물려받아 코드 재사용과 기능 확장을 가능하게 하는 객체 지향 문법이다.  
자식 객체가 생성될 때는 부모가 먼저 초기화되며, `super()`를 통해 부모 생성자를 호출할 수 있다.  
메소드 오버라이딩은 부모의 메소드를 자식이 재정의하는 것이며, 실행 시에는 변수 타입이 아니라 실제 객체의 메소드가 호출된다.  
자동 타입 변환과 강제 타입 변환은 다형성과 연결되는 핵심 개념이며, 부모 타입 변수로 자식 객체를 다루면 같은 사용 방법으로 다양한 실행 결과를 만들 수 있다.  
시험 대비에서는 `extends`, `super`, `this`, 오버라이딩 규칙, `final`, 자동 타입 변환, 강제 타입 변환, 매개변수 다형성을 함께 정리하는 것이 중요하다.
