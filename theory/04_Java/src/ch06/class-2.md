# ✨ 클래스2

## 1. 패키지의 개념

패키지는 클래스를 구분하고 관리하기 위한 이름 공간이다.  
파일을 식별하는 기본 정보가 경로(path)인 것처럼, 자바에서는 클래스를 패키지와 함께 구분한다.

즉, 패키지는 클래스가 어디에 속하는지를 나타내는 주소 역할을 한다. 📌

패키지는 전 세계적으로도 식별 가능하게 만드는 것이 좋기 때문에 보통 회사나 조직의 도메인 이름을 역순으로 사용한다.

예를 들면 다음과 같은 방식이다.

- `com.company.project`
- `org.example.app`

즉, 패키지는 클래스 충돌을 막고 체계적으로 관리하기 위한 구조이다.

## 2. 패키지 선언

패키지를 선언할 때는 `package` 키워드를 사용한다.

즉, 클래스 파일의 맨 위쪽에서 이 클래스가 어떤 패키지에 속하는지를 적어 준다.

필기에는 `pakage`라고 적혀 있지만, 정확한 키워드는 `package`이다. ⚠️

## 3. import 규칙

같은 패키지 안에 있는 클래스는 `import` 없이 바로 사용할 수 있다.  
하지만 다른 패키지에 있는 클래스를 사용하려면 반드시 `import`가 필요하다.

즉,

- 같은 패키지 → import 없이 사용 가능
- 다른 패키지 → import 필요

로 이해하면 된다.

이 규칙은 자바에서 클래스를 찾는 기본 방식이다.

## 4. 이름이 같은 클래스 충돌

다른 패키지에 같은 이름의 클래스가 존재할 수 있다.

이 경우에는 이름 충돌이 발생하므로 `import`만으로는 구분할 수 없다.  
따라서 전체 클래스 경로명을 직접 써야 한다.

예를 들면 다음과 같다.

    com.hanbok.Tire tire = new com.hanbok.Tire();

즉, 패키지명까지 포함한 전체 이름으로 정확히 어떤 클래스를 쓸지 지정해야 한다. ✅

## 5. 접근 제한자

접근 제한자는 캡슐화를 구현하기 위한 핵심 문법이다.

즉, 클래스나 멤버에 대해 외부 접근 범위를 제한해서 데이터를 보호하고, 필요한 기능만 공개할 수 있게 해 준다.

접근 제한자는 클래스, 멤버, 생성자에 붙일 수 있다.

## 6. protected와 default

필기에서 강조된 접근 제한자는 다음과 같다.

### 6-1. protected

`protected`는 같은 패키지 안에서는 접근 가능하고, 다른 패키지라도 상속 관계라면 접근 가능하다.

즉,

- 같은 패키지 → 가능
- 다른 패키지 → 상속 관계일 때 가능

이다.

### 6-2. default

`default`는 접근 제한자를 생략한 경우를 말한다.  
이 경우 같은 패키지의 클래스에서만 접근할 수 있다.

즉,

- 같은 패키지 → 가능
- 다른 패키지 → 불가능

이다.

## 7. 접근 제한자 권장 방식

필기 기준으로 정리하면 다음처럼 사용하는 것을 권장한다.

- 필드 → `private` 권장
- 부모로 쓸 경우 일부 필드 → `protected`
- 메서드/생성자 → `public`
- 내부에서만 쓰는 함수 → `private`

즉, 데이터는 숨기고 필요한 기능만 공개하는 방향이 객체 지향 설계에 더 적합하다. 📌

## 8. getter와 setter

getter와 setter는 private 필드에 간접적으로 접근하기 위해 사용하는 메소드이다.

즉,

- getter → 값을 읽어 오는 메소드
- setter → 값을 변경하는 메소드

이다.

이 방식을 사용하는 이유는 단순히 값을 꺼내고 넣기 위해서만이 아니다.

### 8-1. setter의 장점

setter에서는 대입하려는 값이 유효한 값인지 검증할 수 있다.

즉, 잘못된 값이 들어오는 것을 막을 수 있다. ⚠️

### 8-2. getter의 장점

getter에서는 원래 값을 그대로 주는 대신, 필요한 형태로 가공해서 반환할 수 있다.

즉, 데이터 보호와 가공이 가능하다는 점이 getter/setter의 핵심 장점이다.

## 9. property 개념

property는 getter와 setter에 의해 관리되는 정보를 말한다.

즉, 필드 그 자체보다 "getter/setter를 통해 다뤄지는 값"이라는 관점으로 보는 개념이다.

property name은 보통 메소드 이름에서 `get`, `set`을 제외한 부분으로 본다.

예를 들어

- `getName()`
- `setName()`

이라면 property name은 `name`이다.

## 10. boolean 타입의 getter

boolean 타입에 대해서는 getter 이름을 `getXxxx()` 대신 `isXxxx()` 형태로 많이 사용한다.

즉, 예를 들어 상태가 `stop`이라면 getter는 다음처럼 만들 수 있다.

    isStop()

setter는 그대로 `setStop()`처럼 사용한다.

즉,

- boolean getter → `isXxxx()`
- setter → `setXxxx()`

형태를 기억하면 된다.

## 11. 생성자 권장 구성

필기 기준으로는 다음 두 생성자를 기본적으로 만들어 두는 것을 권장한다.

- 디폴트 생성자
- 모든 멤버를 받는 생성자

즉, 객체를 비어 있는 상태로도 만들 수 있고, 필요한 값을 한 번에 초기화해서도 만들 수 있도록 준비하는 방식이다. ✅

## 12. 싱글톤 패턴의 개념

싱글톤 패턴은 객체를 하나만 생성해서 프로그램 전체에서 공유하도록 만드는 패턴이다.

즉, 어떤 클래스의 인스턴스가 오직 하나만 존재하도록 보장하는 방식이다.

이 패턴은 전역적으로 하나의 객체만 있으면 되는 경우에 많이 사용된다.  
예를 들어 DB 연결 관리 객체가 대표적인 예이다.

## 13. 싱글톤 패턴 구현 방법

싱글톤 패턴에서는 생성자를 `private`으로 막아서 외부에서 `new`를 사용할 수 없게 만든다.

즉, 외부에서는 직접 객체를 생성할 수 없다.  
대신 클래스 내부에 미리 하나의 객체를 만들어 두고, 정적 메소드를 통해 그 객체를 반환한다.

형식은 다음과 같다.

    private static 클래스 singleton = new 클래스();

그리고 getter 역할의 정적 메소드를 만든다.

    public static 클래스 getInstance() {
        return singleton;
    }

즉, 객체 하나를 내부에서만 만들고, 외부는 그 객체를 받아서 쓰기만 하는 구조이다. 📌

## 14. 싱글톤 패턴의 사용 방식

외부에서는 다음처럼 사용한다.

    클래스 변수1 = 클래스.getInstance();
    클래스 변수2 = 클래스.getInstance();

이렇게 하면 두 변수는 결국 같은 객체를 참조하게 된다.

즉,

- 객체는 하나만 존재
- 모든 사용자가 같은 참조를 공유

하게 된다.

이것이 싱글톤 패턴의 핵심이다. ✅

## 15. 싱글톤 패턴이 필요한 경우

DB를 연동하는 애플리케이션이라면 DB 접속을 관리하는 객체를 여러 개 만들 필요가 없을 수 있다.

이럴 때 싱글톤 패턴을 사용하면 하나의 객체만 만들어서 모두가 공유하게 할 수 있다.

즉, 싱글톤은 일종의 전역 객체 또는 전역 상태 관리 방식으로 볼 수 있다.

## 16. 자바스크립트/Node와 싱글톤

필기 내용 기준으로 보면 자바스크립트와 Node의 모듈은 기본적으로 싱글톤처럼 동작한다고 이해할 수 있다.

즉, 한 번 로드된 모듈 객체를 여러 곳에서 공유하는 방식이다.

또한 enum의 각 객체 멤버들도 전부 싱글톤처럼 만들어진다고 볼 수 있다.

즉, 열거 상수 하나하나가 각각 하나의 인스턴스로만 존재한다는 뜻이다.

## 17. 중요 포인트 📌

- 패키지는 클래스를 구분하고 관리하기 위한 이름 공간이다.
- 패키지는 보통 도메인 이름을 역순으로 사용해 만든다.
- 같은 패키지의 클래스는 import 없이 사용할 수 있다.
- 다른 패키지의 클래스는 import가 필요하다.
- 이름이 같은 클래스가 충돌하면 전체 클래스 경로명을 사용해야 한다.
- 접근 제한자는 캡슐화를 위한 핵심 문법이다.
- `protected`는 같은 패키지 + 상속 관계에서 접근 가능하다.
- `default`는 같은 패키지에서만 접근 가능하다.
- 필드는 보통 `private`으로 두고 getter/setter로 관리하는 것이 좋다.
- boolean getter는 `isXxxx()` 형태를 사용한다.
- 디폴트 생성자와 전체 멤버 생성자를 함께 만드는 것이 실무적으로 편하다.
- 싱글톤 패턴은 객체를 하나만 생성해서 공유하는 방식이다.
- 싱글톤은 생성자를 `private`으로 막고 `getInstance()`로 객체를 얻는다.
- enum 객체들도 각각 싱글톤처럼 동작한다.

## 정리 ✅

클래스2에서는 패키지, 접근 제한자, getter/setter, property 개념, 싱글톤 패턴이 핵심이다.  
패키지는 클래스를 체계적으로 구분하기 위한 주소 역할을 하며, import 규칙과 이름 충돌 처리 방식도 함께 이해해야 한다.  
또한 접근 제한자는 캡슐화를 실현하기 위한 중요한 도구이고, 필드는 private으로 숨긴 뒤 getter/setter로 관리하는 것이 기본적인 설계 방식이다.  
싱글톤 패턴은 객체를 하나만 생성해서 공유하는 대표적인 패턴으로, 생성자를 private으로 막고 정적 메소드로 객체를 반환하는 구조를 가진다.  
시험 대비에서는 패키지 규칙, 접근 제한자 차이, getter/setter의 의미, boolean getter 이름, 싱글톤 구현 방식을 함께 정리해 두는 것이 중요하다.
