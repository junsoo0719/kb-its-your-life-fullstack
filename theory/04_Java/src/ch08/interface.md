# ✨ 인터페이스

## 1. 인터페이스의 개념

인터페이스는 두 객체를 연결하는 역할을 한다.  
또한 자바에서 다형성을 구현할 때 사용하는 대표적인 기술이다.

Java 7까지는 보통 추상 메소드로만 이루어진 형태를 인터페이스라고 이해했다.  
즉, 인터페이스는 객체가 어떤 기능을 제공해야 하는지 "규칙"을 정하는 역할을 한다고 보면 된다. 📌

## 2. 인터페이스 선언

인터페이스는 `class` 키워드 대신 `interface` 키워드를 사용해서 선언한다.

접근 제한자는 클래스와 비슷하다.

- `default` → 같은 패키지 내에서만 사용 가능
- `public` → 패키지와 상관없이 사용 가능

즉, 인터페이스도 하나의 참조 타입이며, 클래스처럼 별도의 타입으로 다룬다.

## 3. 구현 클래스

인터페이스 자체는 객체를 직접 생성할 수 없다.  
대신 인터페이스에 선언된 추상 메소드를 실제로 구현한 클래스를 만들어 사용한다.

구현 클래스는 인터페이스에 선언된 추상 메소드와 동일한 선언부를 가진 메소드를 재정의해야 한다.

흐름은 다음과 같다.

- 객체 A → 인터페이스의 추상 메소드를 호출
- 객체 B → 그 추상 메소드를 실제로 구현한 메소드를 실행

즉, 인터페이스는 호출 규칙을 제공하고, 구현 클래스는 실제 동작을 담당한다.

## 4. 변수 선언과 구현 객체 대입

인터페이스는 참조 타입이므로 변수 선언이 가능하다.  
또한 인터페이스 변수에는 `null`도 대입할 수 있다.

하지만 인터페이스는 추상적인 규칙이기 때문에 `new` 연산자로 직접 객체를 만들 수는 없다. ⚠️

인터페이스를 통해 구현 객체를 사용하려면 인터페이스 변수에 구현 객체의 번지를 대입해야 한다.

    인터페이스 변수 = 구현객체;

즉, 인터페이스 타입 변수는 구현 객체를 참조하면서 인터페이스에 선언된 메소드를 통해 객체를 사용하게 된다.

## 5. 상속과 인터페이스의 목적

상속의 목적은 다형성만이 아니라 코드 재사용도 포함한다.  
인터페이스는 특히 다형성 구현에 더 초점을 둔다.

즉,

- 클래스 상속 → 공통 기능 재사용 + 다형성
- 인터페이스 → 다형성 중심의 설계

라고 정리할 수 있다.

## 6. 상수 필드

인터페이스는 상수 필드를 멤버로 가질 수 있다.  
이 필드는 모두 `public static final` 특성을 가진다.

즉, 인터페이스에 선언된 필드는 자동으로 불변 상수가 된다.

특징은 다음과 같다.

- `public static final` 생략 가능
- 값 변경 불가
- 상수명은 보통 대문자로 작성
- 여러 단어면 언더바(`_`)로 연결

즉, 인터페이스의 필드는 일반 변수처럼 사용하는 것이 아니라 공통 상수처럼 사용한다.

## 7. 추상 메소드

추상 메소드는 리턴 타입, 메소드명, 매개변수만 있고 실행 내용은 없는 메소드이다.

즉, 중괄호 `{}`가 없다.

인터페이스의 추상 메소드는 `public abstract`가 자동으로 붙는다.  
따라서 직접 쓰지 않아도 컴파일 과정에서 자동 적용된다.

추상 메소드는 객체 A가 인터페이스를 통해 어떤 방식으로 메소드를 호출해야 하는지 알려주는 역할을 한다.

즉, "무엇을 해야 하는지"는 정하지만 "어떻게 할지"는 구현 클래스가 정한다. ✅

## 8. 디폴트 메소드

인터페이스에는 완전한 실행 코드를 가진 디폴트 메소드를 선언할 수 있다.

추상 메소드와의 차이는 다음과 같다.

- 추상 메소드 → 실행부 없음
- 디폴트 메소드 → 실행부 있음

디폴트 메소드는 리턴 타입 앞에 `default` 키워드가 붙는다.

또한 디폴트 메소드 안에서는 다음과 같은 작업이 가능하다.

- 상수 필드 읽기
- 추상 메소드 호출
- `this` 사용 가능

즉, 디폴트 메소드는 인터페이스 안에서도 어느 정도 공통 기능을 직접 제공할 수 있게 해 준다.

## 9. 정적 메소드

인터페이스는 정적 메소드도 가질 수 있다.

정적 메소드는 구현 객체가 없어도 인터페이스 이름만으로 호출할 수 있다.

즉, 다음과 같은 특징이 있다.

- 객체 생성 없이 호출 가능
- `public` 생략 가능
- 컴파일 과정에서 자동으로 `public`이 붙음

다만 정적 실행부를 작성할 때는 제약이 있다.

- 상수 필드를 제외한 추상 메소드 호출 불가
- 디폴트 메소드 호출 불가
- private 인스턴스 메소드 호출 불가

즉, 정적 메소드는 객체 없이 동작해야 하므로 사용할 수 있는 대상이 제한된다. ⚠️

## 10. private 메소드

인터페이스의 상수 필드, 추상 메소드, 디폴트 메소드, 정적 메소드는 기본적으로 외부에서 접근 가능한 `public` 성격을 가진다.

하지만 인터페이스 내부에서만 사용할 수 있는 `private` 메소드도 선언할 수 있다.

종류는 다음과 같다.

- `private 메소드` → 구현 객체가 필요한 메소드
- `private static 메소드` → 구현 객체가 필요 없는 메소드

호출 가능한 위치도 다르다.

- `private 메소드` → 디폴트 메소드 안에서만 호출 가능
- `private static 메소드` → 정적 메소드 안에서도 호출 가능

즉, 인터페이스 내부의 중복 코드를 줄이기 위해 private 메소드를 사용할 수 있다.

## 11. 다중 인터페이스 구현

하나의 구현 객체는 여러 개의 인터페이스를 통해 사용될 수 있다.

구현 클래스는 `implements` 뒤에 여러 인터페이스를 쉼표로 구분해서 작성한다.

즉, 하나의 클래스가 인터페이스 A와 인터페이스 B를 동시에 구현할 수 있다.

이 경우 구현 클래스는 모든 인터페이스가 가진 추상 메소드를 재정의해야 한다.

여기서 중요한 점은 인터페이스 분리 원칙이다. 📌  
즉, 너무 큰 인터페이스 하나를 만드는 것보다 역할별로 인터페이스를 나누는 것이 중요하다.

## 12. 인터페이스 상속

인터페이스도 다른 인터페이스를 상속할 수 있다.  
그리고 클래스와 달리 다중 상속도 허용된다.

상속할 때는 `extends` 키워드를 사용하고, 여러 인터페이스를 나열할 수 있다.

즉, 자식 인터페이스는 부모 인터페이스의 추상 메소드도 함께 물려받는다.

따라서 자식 인터페이스를 구현하는 클래스는 다음을 모두 재정의해야 한다.

- 자식 인터페이스의 메소드
- 부모 인터페이스의 모든 추상 메소드

또한 구현 객체는 자식 인터페이스 변수뿐 아니라 부모 인터페이스 변수에도 대입될 수 있다.

보통 구현 클래스가 하나일 경우에는 이름 뒤에 `Impl`을 붙이기도 한다.

## 13. 자동 타입 변환

부모 클래스가 어떤 인터페이스를 구현하고 있다면 자식 클래스도 그 인터페이스 타입으로 자동 타입 변환될 수 있다.

    인터페이스 변수 = 구현객체;

즉, 구현 객체는 자동으로 인터페이스 타입으로 변환되어 저장될 수 있다.

이때 인터페이스 변수로는 인터페이스에 선언된 메소드만 사용할 수 있다.  
즉, 실제 객체가 더 많은 기능을 가지고 있어도 인터페이스 기준으로만 접근 가능하다.

## 14. 강제 타입 변환

인터페이스 타입으로 자동 변환된 객체를 다시 구현 클래스 타입으로 바꾸려면 강제 타입 변환이 필요하다.

    구현클래스 변수 = (구현클래스) 인터페이스변수;

이렇게 하면 구현 클래스에만 있는 고유 기능도 사용할 수 있다.

하지만 실제 객체가 해당 구현 클래스 타입이 아닐 경우 예외가 발생할 수 있으므로 주의해야 한다. ⚠️

## 15. 인터페이스와 다형성

다형성이란 사용 방법은 같지만 실행 결과는 다양한 성질을 말한다.

인터페이스 역시 다형성을 구현하기 위해 재정의와 자동 타입 변환 기능을 활용한다.

즉, 같은 인터페이스 타입으로 메소드를 호출해도 실제로 어떤 구현 객체가 대입되어 있느냐에 따라 실행 결과가 달라진다.

이것이 인터페이스가 다형성 구현의 핵심 기술이라고 하는 이유이다. ✅

## 16. 약결합과 강결합

다음과 같이 특정 구현 클래스를 직접 사용하는 방식은 결합도가 높아질 수 있다.

    Tire tire1 = new HankookTire();
    Tire tire2 = new HankookTire();

이처럼 구현 객체에 직접 의존하는 구조를 강결합이라고 볼 수 있다.  
강결합 구조에서는 구현 클래스가 바뀌면 사용하는 쪽 코드도 함께 수정될 가능성이 커진다.

반대로 약결합은 인터페이스를 기준으로 의존하는 구조이다.

예를 들면 다음과 같이 볼 수 있다.

    Tire tire = new HankookTire();

또는 상황에 따라

    Tire tire = new KumhoTire();

처럼 구현 객체만 바꿔 끼울 수 있다.

즉, 사용하는 쪽은 `Tire` 인터페이스만 알면 되고, 실제 구현 객체는 자유롭게 교체할 수 있다.  
이것이 인터페이스를 사용하는 중요한 이유 중 하나이다. 📌

## 17. 매개변수의 다형성

메소드의 매개변수 타입을 인터페이스로 선언하면, 호출할 때 다양한 구현 객체를 전달할 수 있다.

즉, 같은 메소드가 서로 다른 구현 객체를 받아서 동작할 수 있다.

예를 들어

    Vehicle vehicle = bus;

와 같이 자동 타입 변환이 발생할 수 있다.

이 방식은 코드 재사용성과 확장성을 높여 준다.  
즉, 메소드를 하나만 만들어 두고 다양한 구현 객체를 받아 처리할 수 있게 된다.

## 18. instanceof 연산자

인터페이스 타입 변수에 들어 있는 실제 객체가 어떤 구현 클래스인지 확인할 때 `instanceof` 연산자를 사용한다.

    if (vehicle instanceof Bus) {
        Bus bus = (Bus) vehicle;
        // bus 변수 사용
    }

이 코드는 `vehicle`에 대입된 객체가 `Bus`일 경우에만 `Bus` 타입으로 강제 변환하는 방식이다.

이렇게 하면 잘못된 형변환을 방지할 수 있다.

## 19. Java 12 이후의 instanceof

Java 12부터는 `instanceof` 결과가 `true`일 경우 우측 타입 변수를 바로 사용할 수 있다.

    if (vehicle instanceof Bus bus) {
        // bus 변수 사용
    }

즉, 예전처럼 검사 후 다시 강제 타입 변환 코드를 따로 작성하지 않아도 된다.  
이 방식은 코드가 더 짧고 안전하다.

## 20. 중요 포인트 📌

- 인터페이스는 두 객체를 연결하고 다형성을 구현하는 핵심 기술이다.
- 인터페이스는 `interface` 키워드로 선언한다.
- 인터페이스는 직접 객체를 생성할 수 없고 구현 클래스를 통해 사용한다.
- 인터페이스의 필드는 모두 `public static final` 상수이다.
- 추상 메소드는 `public abstract`가 자동으로 붙는다.
- 디폴트 메소드는 실행부가 있는 공통 메소드이다.
- 정적 메소드는 객체 없이 인터페이스 이름으로 호출할 수 있다.
- private 메소드는 인터페이스 내부 코드 재사용을 위해 사용한다.
- 하나의 구현 클래스는 여러 인터페이스를 구현할 수 있다.
- 인터페이스도 다중 상속이 가능하다.
- 구현 객체는 인터페이스 타입으로 자동 타입 변환된다.
- 필요하면 구현 클래스 타입으로 강제 타입 변환할 수 있다.
- 인터페이스는 약결합 구조를 만드는 데 매우 중요하다.
- 매개변수 타입을 인터페이스로 선언하면 다형성을 쉽게 구현할 수 있다.
- `instanceof`는 안전한 형변환을 위해 사용한다.

## 정리 ✅

인터페이스는 객체 간의 연결 규칙을 정의하고, 자바에서 다형성을 구현하는 핵심 도구이다.  
구현 클래스는 인터페이스의 추상 메소드를 재정의해서 실제 동작을 제공하며, 인터페이스 타입 변수는 다양한 구현 객체를 참조할 수 있다.  
또한 인터페이스는 상수 필드, 추상 메소드, 디폴트 메소드, 정적 메소드, private 메소드까지 가질 수 있어 예전보다 더 다양한 기능을 제공한다.  
인터페이스를 사용하면 강결합을 줄이고 약결합 구조를 만들 수 있으며, 매개변수의 다형성도 쉽게 구현할 수 있다.  
시험 대비에서는 인터페이스 선언과 구현, 자동 타입 변환과 강제 타입 변환, 다중 인터페이스, 인터페이스 상속, 디폴트 메소드, 그리고 `instanceof` 활용까지 함께 정리하는 것이 중요하다.
