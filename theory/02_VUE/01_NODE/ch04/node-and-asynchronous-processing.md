# 노드와 비동기 처리

## 1. 스레드

스레드(thread)는 하나의 작업이 실행되는 최소 단위이다.

프로그램은 하나 이상의 스레드를 이용해 작업을 처리할 수 있다.  
여러 작업을 동시에 처리하려면 보통 여러 스레드가 필요하다.

---

## 2. I/O 작업과 비동기 처리

I/O(Input / Output) 작업은 다음과 같은 외부 자원과 데이터를 주고받는 작업을 말한다.

- 파일 읽기 / 쓰기
- 네트워크 통신
- 데이터베이스 접근

이런 작업은 처리 시간이 오래 걸릴 수 있다.

일반적으로 **I/O 작업이 많이 발생할수록 비동기 처리 방식이 성능상 유리**하다.  
이유는 I/O가 끝날 때까지 프로그램이 멈춰 있지 않고, 다른 작업을 먼저 계속 수행할 수 있기 때문이다.

---

## 3. 동기 처리와 비동기 처리의 trade-off

동기 처리와 비동기 처리는 각각 장단점이 있다.

| 구분   | 동기 | 비동기 |
| ------ | ---- | ------ |
| 난이도 | 낮음 | 높음   |
| 성능   | 낮음 | 높음   |

### 동기 처리의 특징

- 흐름이 단순해서 이해하기 쉽다
- 순서대로 실행되므로 코드 추적이 쉽다
- I/O 작업이 길어지면 그동안 다른 작업을 하지 못한다

### 비동기 처리의 특징

- I/O 대기 시간 동안 다른 작업을 수행할 수 있다
- 전체 처리 효율이 좋아질 수 있다
- 콜백, Promise, async/await 등으로 인해 코드 구조가 더 복잡해질 수 있다

Node.js는 특히 **비동기 I/O 처리에 강점이 있는 환경**이다.

---

## 4. 블로킹 I/O

블로킹 I/O는 I/O 작업을 수행하는 동안 **코드 실행이 멈추는 방식**이다.

즉, 앞의 작업이 끝날 때까지 다음 코드가 실행되지 않는다.

Node.js에서는 보통 **동기 함수가 블로킹 I/O 방식**으로 동작한다.  
이 함수들은 보통 이름이 `Sync()`로 끝난다.

예:

```js
fs.readFileSync();
fs.writeFileSync();
fs.readdirSync();
```

### 블로킹 I/O의 특징

- I/O 결과 데이터를 바로 반환한다
- 에러가 발생하면 예외를 던진다
- 처리 흐름이 단순하다

### 블로킹 I/O의 단점

- I/O 작업 시간이 오래 걸릴 수 있다
- 그 시간 동안 다른 작업을 수행할 수 없다

---

## 5. 논블로킹 I/O

논블로킹 I/O는 I/O 작업을 요청한 뒤,  
그 작업이 끝날 때까지 기다리지 않고 **다음 코드를 계속 실행하는 방식**이다.

즉, 작업을 비동기로 처리한다.

예:

```js
fs.readFile('test.txt', 'utf8', (err, data) => {
  if (err) {
    console.log(err);
    return;
  }

  console.log(data);
});

console.log('다음 작업 실행');
```

위 코드에서는 파일 읽기 작업이 끝나기 전에  
`console.log('다음 작업 실행')`이 먼저 실행될 수 있다.

### 논블로킹 I/O의 장점

- I/O 대기 시간 동안 다른 작업 수행 가능
- 전체 처리 효율 향상
- Node.js 환경에서 특히 유리함

---

## 6. 콜 스택

콜 스택(call stack)은 **동기 함수 호출 정보가 쌓이는 자료 구조**이다.

함수가 호출되면 스택에 쌓이고,  
실행이 끝나면 스택에서 제거된다.

예:

```js
function a() {
  b();
}

function b() {
  c();
}

function c() {
  console.log('실행');
}

a();
```

실행 순서에 따라 콜 스택에는 다음과 같이 쌓일 수 있다.

1. `a()`
2. `b()`
3. `c()`

이처럼 동기 함수는 콜 스택을 중심으로 순서대로 실행된다.

---

## 7. 이벤트 루프와 비동기 처리

Node.js는 이벤트 루프(event loop)를 이용해 비동기 작업을 처리한다.

비동기 I/O 작업을 요청하면 즉시 결과를 반환하지 않고,  
작업이 끝난 뒤 실행해야 할 콜백을 따로 관리한다.

이때 **I/O 완료 후 실행해야 할 콜백은 libuv의 큐를 이용해 관리**된다.  
이 큐를 보통 **콜백 큐(callback queue)** 라고 부른다.

처리 흐름은 대략 다음과 같다.

1. 비동기 I/O 작업 요청
2. Node.js가 작업 처리를 맡김
3. 작업이 완료되면 콜백이 큐에 들어감
4. 이벤트 루프가 콜 스택이 비어 있는지 확인
5. 콜 스택이 비어 있으면 큐에 있는 콜백을 스택으로 옮겨 실행

즉, **비동기 작업 자체는 바로 끝나지 않지만, 완료 후 실행할 콜백은 큐에서 대기하다가 나중에 실행**된다.

---

## 8. 정리

- 스레드는 하나의 작업이 실행되는 최소 단위이다.
- I/O 작업이 많을수록 비동기 처리가 성능상 유리하다.
- 동기 처리는 이해하기 쉽지만, I/O 대기 시간 동안 다른 작업을 하지 못한다.
- 비동기 처리는 성능에 유리하지만 코드 구조가 더 복잡해질 수 있다.
- 블로킹 I/O는 작업이 끝날 때까지 코드 실행이 멈춘다.
- 논블로킹 I/O는 작업을 요청한 뒤 다음 코드를 계속 실행한다.
- 콜 스택은 동기 함수 호출 정보를 저장하는 구조이다.
- Node.js는 이벤트 루프와 libuv의 큐를 이용해 비동기 콜백을 관리한다.
- 비동기 작업이 완료되면 콜백 큐에 들어가고, 이벤트 루프가 이를 실행한다.
