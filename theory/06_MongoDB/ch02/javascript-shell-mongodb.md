# ✨ 자바스크립트 셸을 통한 MongoDB

## 1. 데이터베이스의 개념

MongoDB에서 데이터베이스는 컬렉션들의 집합이다.  
컬렉션을 구분하기 위한 단순 네임스페이스 역할을 한다.

즉, MongoDB에서 데이터를 조회하거나 조작하려면 대상 도큐먼트가 어느 데이터베이스와 어느 컬렉션에 있는지 알아야 한다. 📌

정리하면 다음과 같다.

- 데이터베이스 → 컬렉션들의 집합
- 컬렉션 → 도큐먼트들의 집합
- 도큐먼트 → 실제 데이터 단위

## 2. 데이터베이스 선택

MongoDB 셸에서 사용할 데이터베이스를 선택할 때는 `use` 명령을 사용한다.

    use 데이터베이스명

예를 들면 다음과 같다.

    use testdb

현재 사용 중인 데이터베이스는 `db`라는 전역 변수에 설정된다.

즉, `use`로 데이터베이스를 선택한 뒤에는 `db`를 통해 현재 데이터베이스의 컬렉션에 접근할 수 있다. ✅

## 3. 삽입과 질의 기본 구조

MongoDB 셸에서는 다음 형식으로 컬렉션의 메서드를 호출한다.

    db.컬렉션명.메서드

대표적인 메서드는 다음과 같다.

- `insert()` → 문서 삽입
- `find()` → 문서 조회
- `count()` → 문서 개수 확인

예를 들면 다음과 같다.

    db.users.insert({username: "smith"});
    db.users.find();
    db.users.count();

MongoDB 셸은 자바스크립트 기반이므로 필드명에 특수기호나 공백이 포함되지 않은 경우에는 따옴표를 생략할 수 있다.

    {username: "smith"}

하지만 특수기호나 공백이 포함되면 문자열로 감싸야 한다.

## 4. \_id 필드

MongoDB의 각 도큐먼트에는 `_id` 필드가 존재한다.

`_id`는 프라이머리 키 역할을 한다.  
즉, 컬렉션 안에서 각 도큐먼트를 식별하는 고유한 값이다.

도큐먼트를 삽입할 때 `_id`를 직접 지정하지 않으면 MongoDB가 `ObjectId`라는 특별한 값을 자동으로 생성한다. 📌

정리하면 다음과 같다.

- `_id` → 프라이머리 키
- 직접 지정 가능
- 지정하지 않으면 `ObjectId` 자동 생성

## 5. 질의 술어와 쿼리 셀렉터

MongoDB에서 조회 조건으로 전달하는 도큐먼트를 쿼리 셀렉터라고 한다.

쿼리 셀렉터는 컬렉션에 있는 모든 도큐먼트에 대해 일치 여부를 검사하기 위한 조건으로 사용된다.

예를 들면 다음과 같다.

    db.users.find({username: "smith"});

이 코드는 `username` 값이 `"smith"`인 도큐먼트를 조회한다.

## 6. 비어 있는 술어

비어 있는 술어는 모든 문서를 리턴한다.

다음 두 문장은 같은 의미이다.

    db.users.find();

    db.users.find({});

즉, 조건을 주지 않으면 컬렉션의 모든 도큐먼트를 조회한다.

## 7. AND 조건 검사

MongoDB에서 여러 조건을 하나의 도큐먼트 안에 작성하면 기본적으로 AND 조건으로 처리된다.

    db.users.find({
        _id: ObjectId("4bf9bec50e32f82523389314"),
        username: "smith"
    });

위 코드는 `_id` 조건과 `username` 조건을 모두 만족하는 도큐먼트를 조회한다.

명시적으로 `$and` 연산자를 사용할 수도 있다.

    db.users.find({
        $and: [
            {_id: ObjectId("4bf9bec50e32f82523389314")},
            {username: "smith"}
        ]
    });

즉, MongoDB에서는 기본 조건 나열이 AND로 동작한다. 📌

## 8. OR 조건 검사

OR 조건을 사용하려면 `$or` 연산자를 사용한다.

    db.users.find({
        $or: [
            {username: "smith"},
            {username: "jones"}
        ]
    });

이 코드는 `username`이 `"smith"`이거나 `"jones"`인 도큐먼트를 조회한다.

즉, 여러 조건 중 하나만 만족해도 조회하고 싶을 때 `$or`를 사용한다.

## 9. 도큐먼트 업데이트

MongoDB에서 도큐먼트를 수정할 때는 `update()`를 사용할 수 있다.

기본 형식은 다음과 같다.

    컬렉션.update(쿼리문서, 갱신문서, upsert여부, 다중적용여부)

업데이트 유형은 크게 두 가지이다.

- 부분 업데이트
- 대체 업데이트

즉, 도큐먼트의 일부 필드만 수정할 수도 있고, 도큐먼트 전체를 다른 내용으로 대체할 수도 있다.

## 10. $set 연산자

`$set`은 문서의 한 부분만 수정할 때 사용하는 연산자이다.

형식은 다음과 같다.

    {$set: {키: 값, ...}}

예를 들면 다음과 같다.

    db.users.update(
        {username: "smith"},
        {$set: {country: "Canada"}}
    );

이 코드는 `username`이 `"smith"`인 도큐먼트에 `country` 필드를 `"Canada"`로 설정한다.

만약 해당 키가 없으면 새로 추가된다. ✅

## 11. 대체 업데이트

대체 업데이트는 기존 도큐먼트를 다른 도큐먼트로 대체하는 방식이다.

예를 들면 다음과 같다.

    db.users.replaceOne(
        {username: "smith"},
        {country: "Canada"}
    );

또는 다음처럼 `update()`를 사용할 수도 있다.

    db.users.update(
        {country: "Canada"},
        {username: "smith", country: "Canada"}
    );

주의할 점은 대체 업데이트는 기존 도큐먼트의 일부만 바꾸는 것이 아니라 전체 구조를 대체할 수 있다는 점이다. ⚠️

## 12. $unset 연산자

`$unset`은 특정 키를 삭제할 때 사용하는 연산자이다.

형식은 다음과 같다.

    {$unset: {키: 1, ...}}

예를 들면 다음과 같다.

    db.users.update(
        {username: "smith"},
        {$unset: {country: 1}}
    );

이 코드는 `username`이 `"smith"`인 도큐먼트에서 `country` 필드를 삭제한다.

## 13. 내부 문서 검색

MongoDB에서는 도큐먼트 안에 또 다른 도큐먼트가 들어갈 수 있다.

내부 문서의 필드를 검색할 때는 점 표기법을 사용한다.

    "부모키.자식키"

예를 들어 다음과 같이 작성한다.

    "favorites.movies"

점 표기법을 사용할 때는 반드시 문자열로 표시해야 한다. 📌

## 14. 배열 검색

배열 안에 특정 요소가 포함되어 있는지 검색할 수도 있다.

예를 들면 다음과 같다.

    db.users.find({"favorites.movies": "Casablanca"}).pretty();

이 코드는 `favorites.movies` 배열 안에 `"Casablanca"`가 포함된 도큐먼트를 조회한다.

`pretty()`는 조회 결과를 보기 좋게 출력하는 메서드이다.

## 15. 더 발전된 업데이트

`update()`의 세 번째 파라미터는 upsert 여부이다.

- `true` → 조건에 맞는 문서가 없으면 새로 삽입
- `false` → 조건에 맞는 문서가 없으면 아무 작업도 하지 않음

기본값은 `false`이다.

네 번째 파라미터는 다중 업데이트 여부이다.

- `true` → 조건에 맞는 여러 문서 수정
- `false` → 기본적으로 하나의 문서만 수정

기본값은 `false`이다. ⚠️

## 16. 배열에 요소 추가

배열에 요소를 추가할 때는 `$push` 또는 `$addToSet`을 사용할 수 있다.

### 16-1. $push

`$push`는 배열에 요소를 무조건 추가한다.

중복을 허용한다.

    {$push: {배열키: 값}}

### 16-2. $addToSet

`$addToSet`은 배열에 요소를 추가하되 중복 없이 추가한다.

    {$addToSet: {배열키: 값}}

즉,

- `$push` → 중복 가능
- `$addToSet` → 중복 방지

로 구분하면 된다. ✅

## 17. 데이터 삭제

도큐먼트를 삭제할 때는 `remove()`를 사용할 수 있다.

기본 형식은 다음과 같다.

    컬렉션.remove(쿼리문서)

예를 들면 다음과 같다.

    db.users.remove({"favorites.cities": "Cheyenne"});

이 코드는 `favorites.cities`에 `"Cheyenne"`이 포함된 도큐먼트를 삭제한다.

조건에 해당하는 모든 문서가 삭제되지만, 컬렉션 자체는 유지된다.

## 18. 전체 문서 삭제와 컬렉션 삭제

컬렉션 안의 모든 문서를 삭제하려면 빈 조건을 전달한다.

    db.users.remove({});

이 경우 모든 문서는 삭제되지만 컬렉션은 유지된다.

컬렉션 자체를 삭제하려면 `drop()`을 사용한다.

    db.users.drop();

즉,

- `remove({})` → 문서 전체 삭제, 컬렉션 유지
- `drop()` → 컬렉션 자체 삭제

로 구분한다. 📌

## 19. 대용량 컬렉션 생성

반복문을 사용해서 대량의 문서를 생성할 수 있다.

예를 들어 `numbers` 컬렉션에 많은 문서를 삽입하려면 다음과 같이 작성할 수 있다.

    for (let i = 0; i < 200000; i++) {
        db.numbers.insert({num: i});
    }

이 코드는 `num` 값이 0부터 199999까지인 문서를 생성한다.

대량 데이터를 만들 때는 시스템 성능과 디스크 용량에 주의해야 한다. ⚠️

## 20. 범위 쿼리

MongoDB에서는 비교 연산자를 사용해서 범위 조건을 작성할 수 있다.

대표적인 연산자는 다음과 같다.

- `$gt` → greater than, 초과
- `$gte` → greater than or equal, 이상
- `$lt` → less than, 미만
- `$lte` → less than or equal, 이하

예를 들면 다음과 같다.

    db.numbers.find({num: {"$gt": 199995}});

또는 범위를 함께 지정할 수도 있다.

    db.numbers.find({num: {"$gt": 20, "$lt": 25}});

이 코드는 `num`이 20보다 크고 25보다 작은 문서를 조회한다.

## 21. 인덱싱과 explain()

`explain()`은 쿼리 수행 성능 통계 자료를 출력하는 메서드이다.

예를 들면 다음과 같다.

    db.numbers.find({num: {"$gt": 199995}}).explain("executionStats");

이 명령은 해당 쿼리가 어떻게 실행되었는지, 성능 통계가 어떤지 확인할 때 사용한다.

즉, 쿼리 최적화나 인덱스 효과 확인에 유용하다. 📌

## 22. 인덱스 생성

인덱스는 특정 키를 기준으로 조회 성능을 높이기 위해 생성한다.

기본 형식은 다음과 같다.

    컬렉션.createIndex({키: 1, ...})

예를 들면 다음과 같다.

    db.numbers.createIndex({num: 1});

`1`은 오름차순 인덱스를 의미한다.  
내림차순 인덱스를 생성하려면 `-1`을 사용한다.

여러 개의 키를 제시하면 조합 키에 대한 인덱스가 생성된다.

필기에는 `ensureIndex()`도 나오는데, 최신 방식으로는 `createIndex()`를 사용하는 것이 좋다. ✅

## 23. 인덱스 확인

컬렉션에 생성된 인덱스를 확인하려면 `getIndexes()`를 사용한다.

    db.numbers.getIndexes();

이 명령은 `numbers` 컬렉션에 설정된 인덱스 목록을 보여준다.

인덱스가 제대로 생성되었는지 확인할 때 사용한다.

## 24. 인덱스 쿼리 explain 결과 확인

인덱스를 생성한 뒤 다시 `explain()`을 실행하면 인덱스가 쿼리에 사용되는지 확인할 수 있다.

    db.numbers.find({num: {"$gt": 199995}}).explain("executionStats");

인덱스 생성 전후의 실행 통계를 비교하면 쿼리 성능 차이를 확인할 수 있다.

즉, `explain()`은 인덱스 효과를 검증하는 데 중요한 도구이다. 📌

## 25. 데이터베이스 정보 얻기

MongoDB 셸에서는 데이터베이스와 컬렉션 정보를 확인하는 명령을 제공한다.

데이터베이스 목록은 다음 명령으로 확인한다.

    show dbs

현재 사용 중인 데이터베이스의 컬렉션 목록은 다음 명령으로 확인한다.

    show collections

즉, 현재 MongoDB 안에 어떤 데이터베이스와 컬렉션이 있는지 확인할 수 있다.

## 26. 데이터베이스와 컬렉션 상태 확인

현재 사용 중인 데이터베이스의 상태를 확인할 때는 다음 명령을 사용할 수 있다.

    db.status()

컬렉션 상태를 확인할 때는 다음처럼 작성할 수 있다.

    db.numbers.status()

다만 일반적으로 MongoDB에서는 상태 확인 메서드로 `stats()`를 많이 사용한다.

    db.stats()
    db.numbers.stats()

필기에는 `status()`라고 적혀 있지만, 실제 MongoDB 셸에서는 `stats()`를 사용하는 경우가 일반적이다. ⚠️

## 27. 중요 포인트 📌

- MongoDB 데이터베이스는 컬렉션들의 집합이다.
- `use 데이터베이스명`으로 사용할 데이터베이스를 선택한다.
- 현재 데이터베이스는 `db` 전역 변수에 설정된다.
- `db.컬렉션명.메서드` 형식으로 컬렉션을 조작한다.
- `_id`는 프라이머리 키 역할을 한다.
- `_id`를 지정하지 않으면 `ObjectId`가 자동 생성된다.
- `find()`와 `find({})`는 모든 문서를 조회한다.
- 여러 조건을 나열하면 기본적으로 AND 조건이다.
- OR 조건은 `$or`를 사용한다.
- `$set`은 필드를 추가하거나 수정한다.
- 대체 업데이트는 도큐먼트 전체를 바꿀 수 있으므로 주의해야 한다.
- `$unset`은 필드를 삭제한다.
- 내부 문서 검색은 `"부모키.자식키"` 형태를 사용한다.
- 배열 요소 검색도 점 표기법으로 가능하다.
- `$push`는 배열에 중복 가능하게 추가한다.
- `$addToSet`은 배열에 중복 없이 추가한다.
- `remove({})`는 모든 문서를 삭제하지만 컬렉션은 유지한다.
- `drop()`은 컬렉션 자체를 삭제한다.
- 범위 쿼리는 `$gt`, `$gte`, `$lt`, `$lte`를 사용한다.
- `explain("executionStats")`는 쿼리 성능 통계를 확인할 때 사용한다.
- 인덱스 생성은 `createIndex()`를 사용한다.
- 인덱스 확인은 `getIndexes()`를 사용한다.
- 데이터베이스 목록은 `show dbs`, 컬렉션 목록은 `show collections`로 확인한다.

## 정리 ✅

자바스크립트 셸을 통한 MongoDB에서는 데이터베이스 선택, 컬렉션 조작, 도큐먼트 삽입·조회·수정·삭제가 핵심이다.  
`use`로 데이터베이스를 선택하면 현재 데이터베이스가 `db` 전역 변수에 설정되고, `db.컬렉션명.메서드` 형식으로 컬렉션을 다룰 수 있다.  
조회에서는 쿼리 셀렉터를 사용하며, 기본 조건 나열은 AND로 처리되고 OR 조건은 `$or`를 사용한다.  
수정에서는 `$set`, `$unset`, `$push`, `$addToSet` 같은 연산자를 사용하며, 대체 업데이트는 기존 문서 전체를 바꿀 수 있으므로 주의해야 한다.  
또한 범위 쿼리는 `$gt`, `$gte`, `$lt`, `$lte`를 사용하고, 인덱스 생성과 `explain()`을 통해 쿼리 성능을 확인할 수 있다.
