# ✨ 쿼리 작성하기

## 1. 질의 조건과 셀렉터

MongoDB에서 데이터를 조회할 때는 `find()` 메서드에 질의 조건을 전달한다.  
이때 조건으로 사용하는 도큐먼트를 셀렉터라고 한다.

기본 형식은 다음과 같다.

    db.컬렉션명.find({조건})

예를 들어 `last_name`이 `"Banker"`인 문서를 조회하려면 다음과 같이 작성한다.

    db.users.find({'last_name': "Banker"})

즉, 셀렉터는 어떤 문서를 조회할지 결정하는 조건 도큐먼트이다. 📌

## 2. AND 조건

MongoDB에서 여러 조건을 하나의 조건 도큐먼트 안에 함께 작성하면 기본적으로 AND 조건으로 처리된다.

예를 들면 다음과 같다.

    db.users.find({'first_name': "Smith", birth_year: 1975})

이 쿼리는 다음 조건을 모두 만족하는 문서를 조회한다.

- `first_name`이 `"Smith"`
- `birth_year`가 `1975`

즉, 조건을 나열하면 모든 조건을 만족해야 조회된다. ✅

## 3. 범위 조건

범위 조건을 작성할 때는 비교 연산자를 사용한다.

대표적으로 다음 연산자를 사용할 수 있다.

- `$gte` → 크거나 같음
- `$lte` → 작거나 같음

예를 들어 `birth_year`가 1985 이상 2015 이하인 문서를 조회하고 싶다면 다음처럼 작성한다.

    db.users.find({'birth_year': {'$gte': 1985, '$lte': 2015}})

주의할 점은 같은 키를 두 번 쓰면 앞 조건이 덮어써질 수 있다는 것이다. ⚠️

다음처럼 쓰는 방식은 좋지 않다.

    db.users.find({'birth_year': {'$gte': 1985}, 'birth_year': {'$lte': 2015}})

같은 필드에 여러 조건을 줄 때는 하나의 객체 안에 함께 작성해야 한다.

## 4. 타입에 따른 범위 검사

MongoDB는 값의 타입을 구분한다.

예를 들어 정수 값에 대한 범위 검사는 정수 데이터만 대상으로 한다.

    db.items.find({'value': {'$gte': 97}})

이 쿼리는 `value`가 정수 기준으로 97 이상인 데이터를 조회한다.

반면 문자열 기준으로 검사하면 문자열 데이터가 대상이 된다.

    db.items.find({'value': {'$gte': "a"}})

즉, 같은 필드라도 값의 타입에 따라 비교 결과가 달라질 수 있다. 📌

## 5. 집합 연산자

집합 연산자는 여러 값의 묶음과 비교할 때 사용한다.

대표적인 집합 연산자는 다음과 같다.

- `$in`
- `$all`
- `$nin`

## 6. $in

`$in`은 어떤 인수든 하나라도 참고 집합에 있는 경우 일치한다.

예를 들어 특정 값 목록 중 하나와 일치하는 문서를 찾을 때 사용한다.

    db.users.find({username: {$in: ["smith", "jones"]}})

이 쿼리는 `username`이 `"smith"` 또는 `"jones"`인 문서를 조회한다.

즉, 여러 후보 중 하나라도 일치하면 조회된다. ✅

## 7. $all

`$all`은 모든 인수가 참고 집합에 있는 경우 일치한다.

주로 배열이 포함된 도큐먼트에서 사용된다.

예를 들어 어떤 배열 필드가 여러 값을 모두 포함해야 할 때 사용할 수 있다.

    db.users.find({tags: {$all: ["java", "mongodb"]}})

이 쿼리는 `tags` 배열 안에 `"java"`와 `"mongodb"`가 모두 포함된 문서를 조회한다.

## 8. $nin

`$nin`은 그 어떤 인수도 참고 집합에 있지 않을 경우 일치한다.

즉, 지정한 목록에 포함되지 않는 데이터를 조회할 때 사용한다.

    db.users.find({username: {$nin: ["smith", "jones"]}})

이 쿼리는 `username`이 `"smith"`도 아니고 `"jones"`도 아닌 문서를 조회한다.

## 9. 부울 연산자

부울 연산자는 조건의 참과 거짓을 조합하거나 반전할 때 사용한다.

대표적인 부울 연산자는 다음과 같다.

- `$ne`
- `$not`
- `$or`
- `$nor`
- `$and`
- `$exists`

## 10. $ne

`$ne`는 인수가 요소와 같지 않은 경우 일치한다.

    db.users.find({username: {$ne: "smith"}})

이 쿼리는 `username`이 `"smith"`가 아닌 문서를 조회한다.

즉, 같지 않음 조건을 표현할 때 사용한다.

## 11. $not

`$not`은 일치 결과를 반전시킨다.

즉, 특정 조건의 반대 결과를 조회하고 싶을 때 사용한다.

    db.users.find({birth_year: {$not: {$gte: 1985}}})

이 쿼리는 `birth_year`가 1985 이상이라는 조건을 반대로 적용한다.

## 12. $or

`$or`는 제공된 검색어 집합 중 하나라도 `TRUE`인 경우 일치한다.

    db.users.find({
        $or: [
            {username: "smith"},
            {username: "jones"}
        ]
    })

즉, 여러 조건 중 하나만 만족해도 조회하고 싶을 때 사용한다. 📌

## 13. $nor

`$nor`는 제공된 검색어 집합 중 어느 것도 `TRUE`가 아닌 경우 일치한다.

즉, 여러 조건을 모두 만족하지 않는 문서를 찾을 때 사용한다.

    db.users.find({
        $nor: [
            {username: "smith"},
            {username: "jones"}
        ]
    })

이 쿼리는 `username`이 `"smith"`도 아니고 `"jones"`도 아닌 문서를 조회한다.

## 14. $and

`$and`는 제공된 검색어 집합이 모두 `TRUE`인 경우 일치한다.

    db.users.find({
        $and: [
            {first_name: "Smith"},
            {birth_year: 1975}
        ]
    })

다만 MongoDB에서는 조건을 같은 객체 안에 나열하면 기본적으로 AND처럼 동작하므로, 단순한 AND 조건에서는 `$and`를 생략할 수 있다.

## 15. $exists

`$exists`는 특정 요소가 도큐먼트 안에 존재할 경우 일치한다.

    db.users.find({email: {$exists: true}})

이 쿼리는 `email` 필드가 존재하는 문서를 조회한다.

반대로 존재하지 않는 문서를 찾고 싶다면 다음처럼 작성할 수 있다.

    db.users.find({email: {$exists: false}})

즉, 필드 존재 여부를 기준으로 조회할 때 사용한다. ✅

## 16. 배열 조건

배열 필드를 조회할 때는 배열 전용 연산자를 사용할 수 있다.

대표적인 연산자는 다음과 같다.

- `$elemMatch`
- `$size`

배열 안의 값이나 하위 도큐먼트 조건을 검사할 때 유용하다.

## 17. $elemMatch

`$elemMatch`는 제공된 모든 조건이 동일한 하위 도큐먼트에 있는 경우 일치한다.

즉, 배열 안의 여러 하위 도큐먼트 중 하나가 여러 조건을 동시에 만족해야 할 때 사용한다.

    db.users.find({
        scores: {
            $elemMatch: {type: "quiz", score: {$gte: 80}}
        }
    })

이 쿼리는 `scores` 배열 안의 같은 요소가 `type`은 `"quiz"`이고 `score`는 80 이상인 경우를 찾는다. 📌

## 18. $size

`$size`는 배열의 크기가 제공된 리터럴 값과 같으면 일치한다.

    db.users.find({tags: {$size: 3}})

이 쿼리는 `tags` 배열의 요소 개수가 3개인 문서를 조회한다.

즉, 배열 길이를 기준으로 검색할 때 사용한다.

## 19. 조회 필드 제한

`find()`의 두 번째 인자는 조회 결과에 포함하거나 제외할 필드를 지정하는 필드 목록이다.

기본 형식은 다음과 같다.

    db.컬렉션명.find(조건, 필드목록)

예를 들어 `a`와 `b`만 보고 싶다면 다음처럼 작성한다.

    db.collection.find({...}, {a: 1, b: 1})

여기서 `1`은 해당 필드를 포함한다는 의미이다.

## 20. 특정 필드 제외

특정 필드만 빼고 보고 싶다면 `0`을 사용한다.

예를 들어 `c`만 제외하고 보고 싶다면 다음처럼 작성한다.

    db.collection.find({...}, {c: 0})

여기서 `0`은 해당 필드를 제외한다는 의미이다.

## 21. 필드 포함과 제외 주의점

필드 목록에서는 일반적으로 `1`과 `0`을 혼용하면 안 된다.

예를 들어 다음처럼 작성하면 안 된다.

    db.collection.find({...}, {a: 1, b: 0})

즉, 포함 방식과 제외 방식을 섞지 않는 것이 원칙이다. ⚠️

다만 `_id`는 예외적으로 제외할 수 있다.

    db.collection.find({...}, {_id: 0, a: 1})

이 쿼리는 `_id`는 제외하고 `a`만 포함한다.

## 22. 중요 포인트 📌

- MongoDB의 조회 조건 도큐먼트를 셀렉터라고 한다.
- 조건을 하나의 도큐먼트 안에 나열하면 기본적으로 AND 조건이다.
- 같은 필드에 여러 범위 조건을 줄 때는 하나의 객체 안에 함께 작성해야 한다.
- MongoDB는 값의 타입을 구분하므로 정수 비교와 문자열 비교 결과가 달라질 수 있다.
- `$in`은 목록 중 하나와 일치할 때 사용한다.
- `$all`은 배열에 지정한 값들이 모두 포함될 때 사용한다.
- `$nin`은 목록 중 어떤 값과도 일치하지 않을 때 사용한다.
- `$ne`는 같지 않음 조건이다.
- `$not`은 조건 결과를 반전한다.
- `$or`는 조건 중 하나라도 참이면 일치한다.
- `$nor`는 조건 중 어느 것도 참이 아니면 일치한다.
- `$and`는 모든 조건이 참이면 일치한다.
- `$exists`는 필드 존재 여부를 검사한다.
- `$elemMatch`는 배열의 동일 요소가 여러 조건을 동시에 만족할 때 사용한다.
- `$size`는 배열 크기를 검사한다.
- `find()`의 두 번째 인자로 출력 필드를 제한할 수 있다.
- 필드 포함은 `1`, 제외는 `0`으로 표시한다.
- 일반 필드에서는 `1`과 `0`을 혼용하면 안 된다.
- `_id`는 예외적으로 제외할 수 있다.

## 정리 ✅

MongoDB 쿼리 작성에서는 셀렉터를 이용해 조회 조건을 정확히 작성하는 것이 중요하다.  
기본적으로 조건을 하나의 도큐먼트 안에 나열하면 AND 조건으로 처리되며, 범위 조건은 `$gte`, `$lte` 같은 비교 연산자를 하나의 필드 객체 안에 함께 작성해야 한다.  
집합 연산자인 `$in`, `$all`, `$nin`은 여러 값과 비교할 때 사용하고, 부울 연산자인 `$ne`, `$not`, `$or`, `$nor`, `$and`, `$exists`는 조건을 조합하거나 반전할 때 사용한다.  
배열 검색에서는 `$elemMatch`와 `$size`를 사용할 수 있으며, `find()`의 두 번째 인자를 이용해 출력할 필드를 포함하거나 제외할 수 있다.  
시험 대비에서는 AND 조건 작성 방식, 같은 필드의 범위 조건 작성법, 집합 연산자와 부울 연산자 의미, 배열 검색 연산자, 필드 제한 규칙을 함께 정리해 두는 것이 중요하다.
