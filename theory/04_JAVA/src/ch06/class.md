# ✨ 클래스

## 1. 객체의 개념

객체는 물리적으로 존재하는 것뿐 아니라 개념적인 것 중에서도 다른 것과 식별 가능한 것을 말한다.

객체는 보통 다음 두 가지 요소로 구성된다.

- 상태(정보) → 데이터
- 행동 → 메서드

즉, 객체는 "정보를 가지고 있고, 동작도 할 수 있는 대상"이라고 이해하면 된다. 📌

## 2. 추상화

대상을 정의하는 과정을 추상화라고 한다.

즉, 여러 대상의 공통점을 뽑아내고 필요한 특징만 남겨서 일반화하는 과정이다.  
클래스는 이런 추상화 결과를 바탕으로 만들어진다.

예를 들어 학생 객체를 만든다면 이름, 학번, 전공 같은 공통 속성을 뽑아내는 것이 추상화이다.

## 3. 객체 지향 프로그래밍

객체 지향 프로그래밍은 객체들을 먼저 만들고, 이 객체들을 하나씩 조립해서 완성된 프로그램을 만드는 기법이다.

즉, 프로그램을 기능 중심으로만 보는 것이 아니라 "역할을 가진 객체들의 모임"으로 바라보는 방식이다.  
자바는 대표적인 객체 지향 프로그래밍 언어이다.

## 4. 객체 지향 프로그래밍의 가장 큰 특징

객체 지향 프로그래밍의 가장 큰 특징은 객체의 상호작용이다.

객체는 혼자 동작하는 것이 아니라 서로 다른 여러 객체가 정보를 주고받으면서 동작한다.  
이때 정보 교환은 보통 메서드를 통해 이루어진다.

즉,

- 메서드의 매개변수 → 데이터를 전달
- 메서드의 리턴값 → 처리 결과를 전달

하는 방식으로 객체 간 상호작용이 이루어진다. ✅

## 5. 객체 지향 프로그래밍의 특징

객체 지향 프로그래밍의 대표적인 특징은 다음과 같다.

### 5-1. 캡슐화

데이터(상태)와 행위(메서드)를 하나로 묶는 것이다.

또한 접근 제한을 통해 외부에서 함부로 접근하지 못하도록 제어할 수 있다.  
즉, 데이터 보호와 구조화에 도움이 된다.

### 5-2. 상속

기존 클래스의 필드와 메서드를 새로운 클래스가 물려받는 것이다.  
공통 기능을 재사용할 수 있게 해 준다.

### 5-3. 다형성

매우 중요한 개념이다.  
사용 방법은 같지만 실행 결과가 다양하게 나오는 성질을 말한다.

즉, 같은 메서드 호출이라도 실제 객체에 따라 다른 결과가 나올 수 있다.

### 5-4. 클래스와 인스턴스

클래스는 객체를 만들기 위한 설계도이고,  
인스턴스는 실제로 생성된 실체 객체이다.

즉,

- 클래스 → 설계도
- 인스턴스 → 실제 객체

로 이해하면 된다. 📌

## 6. 클래스 선언

클래스를 선언할 때 `public` 클래스는 한 파일에 하나만 존재해야 한다.  
또한 파일명과 클래스명은 같아야 한다.

즉, 다음 규칙을 기억해야 한다.

- `public class Student` → 파일명은 `Student.java`
- 대소문자도 정확히 일치해야 함

이 규칙은 자바에서 매우 기본적인 문법 규칙이다. ⚠️

## 7. 클래스 변수와 객체 참조 변수

클래스 변수를 만든다는 것은 실제로는 클래스 객체를 참조할 변수를 선언하는 것이다.

즉, 변수 안에 클래스 그 자체가 들어가는 것이 아니라 생성된 객체의 참조값이 저장된다.

예를 들어

    Student s1 = new Student();

에서 `s1`은 `Student` 객체를 참조하는 변수이다.

## 8. 라이브러리 클래스와 실행 클래스

클래스는 역할에 따라 다음처럼 나눌 수 있다.

- 라이브러리 클래스 → 단독 실행 불가
- 실행 클래스 → `main()` 메소드가 있어서 실행 가능

즉, 라이브러리 클래스는 기능 제공용이고, 실행 클래스는 프로그램 시작점 역할을 한다.

## 9. 객체 생성과 지역 변수

다음 코드를 보자.

    Student s1 = new Student();

이때 `s1`은 `main` 메소드 안의 지역 변수이므로 스택에 저장된다.  
그리고 실제 `Student` 객체는 힙에 생성된다.

지역 변수는 메서드가 종료되면 함께 사라진다.  
즉, `s1`의 생명주기는 해당 메서드 실행 범위 안으로 제한된다.

## 10. 클래스의 구성 멤버

클래스는 보통 다음 세 가지 멤버로 구성된다.

- 필드 → 데이터, 변수
- 메서드 → 행동, 함수
- 생성자 → 객체 생성 시 호출되는 특별한 메서드

즉, 클래스는 상태와 동작, 그리고 생성 시 초기화 기능까지 포함하는 구조이다.

## 11. 생성자

생성자는 `new` 연산자로 객체를 만들 때 호출되는 특별한 메서드이다.

생성자의 특징은 다음과 같다.

- 클래스명과 동일하다.
- 리턴 타입이 없다.
- 객체 생성 시 자동 호출된다.

즉, 생성자는 객체 초기화 담당이라고 이해하면 된다. ✅

## 12. 필드의 초기화

필드는 초기값을 주지 않으면 기본값으로 초기화된다.  
이유는 객체가 항상 `new`로 생성되고 힙 영역에 올라가기 때문이다.

즉, 힙 영역은 자동 초기화가 이루어진다.

예를 들어 숫자 타입은 0, boolean은 false, 참조 타입은 null로 초기화된다.

## 13. this의 의미

클래스 내부에서 필드를 사용할 때는 `this.`가 생략되어 있는 경우가 많다.

즉, 클래스 내부에서는

    this.name

과

    name

이 같은 의미일 수 있다.

반면 외부에서 접근할 때는 반드시 참조 변수로 접근해야 한다.

즉,

- 클래스 내부 → `this.` 생략 가능
- 클래스 외부 → `참조변수.` 필요

이다.

## 14. new 연산자

`new` 연산자는 객체 생성을 위해 메모리를 할당한다.

동작 순서는 다음과 같다.

1. 힙에 메모리 할당
2. 생성자 호출
3. 객체 주소(참조값) 반환

여기서 중요한 점은 힙에는 필드 정보가 들어가고, 메서드는 메서드 영역에 존재한다는 것이다.  
메서드는 코드이므로 하나만 있으면 되고 읽기 전용처럼 사용된다. 📌

## 15. 기본 생성자

모든 클래스는 생성자를 가진다.

만약 생성자를 하나도 작성하지 않으면 컴파일러가 기본 생성자를 자동으로 추가한다.  
하지만 생성자를 하나라도 직접 작성하면 기본 생성자는 자동 추가되지 않는다. ⚠️

즉,

- 생성자 없음 → default 생성자 자동 생성
- 생성자 직접 작성함 → default 생성자 자동 생성 안 됨

으로 정리하면 된다.

## 16. 생성자에서 변수 찾는 순서

생성자 안에서 어떤 이름의 변수를 사용할 때 찾는 순서는 다음과 같다.

1. 지역 변수
2. 필드 변수 (`this`로 구분 가능)

즉, 지역 변수명이 필드명과 같다면 지역 변수가 우선된다.  
필드를 구분해서 사용하려면 `this.필드명` 형태를 사용해야 한다.

## 17. 생성자 오버로딩

생성자 오버로딩은 매개변수를 다르게 한 생성자를 여러 개 선언하는 것이다.

중요한 점은 자바가 변수명은 보지 않고 타입만 본다는 것이다.

즉, 생성자 구분 기준은 다음이다.

- 매개변수 개수
- 매개변수 타입
- 매개변수 순서

반대로 변수명은 달라도 타입 구성이 같으면 오버로딩이 아니다.

`new` 연산자로 생성자를 호출할 때는 전달된 매개값의 타입과 개수에 따라 실행될 생성자가 결정된다.

## 18. this()를 이용한 생성자 호출

생성자 오버로딩이 많아지면 코드가 중복되기 쉽다.  
이때 생성자 안에서 다른 생성자를 호출해서 중복 코드를 줄일 수 있다.

이때 사용하는 것이 `this(...)`이다.

즉, 같은 클래스의 다른 생성자를 호출하는 문법이다.

주의할 점은 다음과 같다.

- `this(...)`는 생성자의 첫 번째 줄에 있어야 한다.

이 제약은 시험에서도 자주 나오는 포인트이다. ⚠️

## 19. 메소드 선언과 호출

메소드는 객체의 행동을 정의한다.  
객체 간 상호작용도 메소드 호출을 통해 이루어진다.

즉, 메소드는 단순한 함수가 아니라 객체가 외부와 소통하는 창구 역할을 한다.

## 20. 가변길이 매개변수

자바에서는 매개변수 개수가 정해지지 않은 메소드를 만들 수 있다.

예를 들면 다음과 같다.

    int sum(int ... values)

이 방식은 전달된 값들이 내부적으로 배열에 저장되는 구조이다.

주의할 점은 가변길이 매개변수는 항상 마지막 매개변수로 선언해야 한다는 것이다. 📌

## 21. 메소드 오버로딩

메소드 오버로딩은 메소드 이름은 같지만 매개변수 타입, 개수, 순서가 다른 메소드를 여러 개 선언하는 것이다.

중요한 점은 리턴 타입은 오버로딩 판단 기준이 아니라는 것이다.

즉, 자바는 다음만 본다.

- 메소드 이름
- 매개변수 타입
- 매개변수 개수
- 매개변수 순서

리턴 타입만 다르면 오버로딩이 아니다. ✅

## 22. 인스턴스 멤버

인스턴스 멤버는 인스턴스마다 가지는 멤버이다.

즉,

- 인스턴스 필드
- 인스턴스 메소드

가 여기에 해당한다.

특징은 다음과 같다.

- 객체를 생성해야 사용 가능
- 인스턴스로 접근
- `this`로 구분 가능

즉, 인스턴스와 함께 존재하는 멤버라고 이해하면 된다.

## 23. 정적(static) 멤버

정적 멤버는 인스턴스에 배정되지 않고 클래스 자체에 속하는 멤버이다.

특징은 다음과 같다.

- 메서드 영역에 하나만 존재
- 객체 없이 사용 가능
- `new` 없이 사용 가능
- 클래스가 로드될 때 생성됨

즉, 모든 인스턴스가 공유하는 공통 멤버이다. 📌

## 24. 자바의 동적 로딩

자바는 동적 로딩(Dynamic Loading)을 사용한다.

즉, 프로그램 시작 시 모든 클래스를 한 번에 메모리에 올리는 것이 아니라, 해당 클래스가 실제로 사용될 때 메모리에 올린다.

이 방식의 장점은 메모리 효율이 좋다는 것이다.

클래스가 로드될 때 할당되는 대표적인 것들은 다음과 같다.

- 정적 필드
- 정적 메소드

즉, static 멤버는 클래스가 메모리에 올라오는 시점에 생성된다.

## 25. static 멤버 접근

정적 필드와 정적 메소드는 클래스명으로 접근하는 것이 기본이다.

즉,

    클래스명.정적필드
    클래스명.정적메소드()

형태로 사용한다.

이유는 정적 멤버가 인스턴스가 아니라 클래스 자체에 속하기 때문이다.  
즉, 메서드 영역의 멤버를 참조하는 방식이다.

## 26. static 메소드와 this

정적 메소드에서는 지역 변수 사용은 문제없다.  
하지만 인스턴스 변수는 바로 사용할 수 없다.

그 이유는 정적 메소드 안에는 `this`가 없기 때문이다. ⚠️  
인스턴스 멤버는 원래 `this`가 생략된 형태라고 볼 수 있는데, static 영역에는 특정 인스턴스가 정해져 있지 않다.

즉,

- static 메소드 → this 없음
- 인스턴스 멤버 직접 사용 불가

이다.

## 27. 정적 블록

정적 블록은 `static`이 붙은 코드 블록이다.

    static {
        ...
    }

이 블록은 클래스가 로드될 때 딱 한 번 실행된다.  
주로 static 멤버 초기화에 많이 사용된다.

즉, 인스턴스 생성용 생성자는 아니지만 "클래스 초기화용 생성자 같은 역할"로 이해할 수 있다. ✅

## 28. static 영역에서 인스턴스 멤버 사용

정적 메소드나 정적 블록에서 인스턴스 멤버를 사용하고 싶다면 먼저 객체를 생성해야 한다.

즉, 다른 객체의 인스턴스 멤버는 참조 변수로 접근하면 사용할 수 있다.

정리하면 다음과 같다.

- 자기 자신의 인스턴스 멤버 직접 사용 불가
- 객체를 만든 뒤 참조 변수로 접근하면 사용 가능

## 29. final 필드

`final` 필드는 한 번 초기화되면 값을 바꿀 수 없는 읽기 전용 필드이다.

초기화 방법은 두 가지가 있다.

- 필드 선언 시 초기값 대입
- 생성자에서 초기값 대입

즉,

- 모두 같은 값이면 선언할 때 초기화
- 객체마다 다른 값이면 생성자에서 초기화

하는 방식으로 나누어 생각하면 된다.

## 30. 상수 선언

상수는 보통 `static final`로 선언한다.

이 조합의 의미는 다음과 같다.

- `final` → 읽기 전용
- `static` → 하나만 생성

즉, 상수는 메서드 영역에 하나만 존재하면서 값을 바꿀 수 없는 공통 데이터이다.

계산을 통해 초기화해야 한다면 static 코드 블록에서 초기화할 수도 있다.

## 31. static object와 싱글톤 패턴

정적 객체(static object)는 싱글톤 패턴처럼 운영될 수 있다.

즉,

- 객체를 하나만 생성
- 프로그램 전체에서 공유
- 인스턴스 하나를 보장

하는 구조이다.

이 경우 실제 객체는 힙에 만들어지고, 그 객체를 가리키는 static 참조가 메서드 영역에 유지된다고 이해하면 된다. 📌

## 32. 중요 포인트 📌

- 객체는 상태와 행동을 가진 식별 가능한 대상이다.
- 추상화는 대상의 공통 특징을 뽑아내는 과정이다.
- 객체 지향 프로그래밍은 객체를 조립해서 프로그램을 만드는 방식이다.
- 객체 지향의 핵심은 객체 간 상호작용이다.
- 캡슐화, 상속, 다형성은 대표적인 객체 지향 특징이다.
- 클래스는 설계도, 인스턴스는 실제 객체이다.
- `public` 클래스는 파일명과 클래스명이 같아야 한다.
- 생성자는 클래스명과 같고 리턴 타입이 없다.
- 생성자를 직접 만들면 기본 생성자는 자동 생성되지 않는다.
- 생성자와 메소드 오버로딩은 매개변수 기준으로 구분한다.
- `this(...)`는 생성자의 첫 줄에서만 사용할 수 있다.
- 인스턴스 멤버는 객체마다 따로 존재하고, static 멤버는 클래스에 하나만 존재한다.
- static 메소드에서는 `this`를 사용할 수 없다.
- 정적 블록은 클래스 로드 시 한 번 실행된다.
- `final` 필드는 읽기 전용이고, 상수는 보통 `static final`로 선언한다.
- static 객체는 싱글톤 패턴처럼 하나만 운영할 수 있다.

## 정리 ✅

클래스는 객체를 만들기 위한 설계도이고, 객체는 상태와 행동을 가진 실체이다.  
자바의 객체 지향 프로그래밍은 이런 객체들을 만들고 서로 상호작용하게 하여 프로그램을 구성하는 방식이다.  
클래스는 필드, 메소드, 생성자로 구성되며, 생성자 오버로딩과 메소드 오버로딩을 통해 다양한 초기화와 기능 제공이 가능하다.  
또한 인스턴스 멤버와 static 멤버의 차이, 정적 블록, final 필드, 상수 선언 방식은 클래스 구조를 이해할 때 매우 중요하다.  
시험 대비에서는 객체 개념, 클래스 구성, 생성자 규칙, 오버로딩, static과 instance의 차이, final과 static final 의미를 함께 묶어서 정리해 두는 것이 좋다.
