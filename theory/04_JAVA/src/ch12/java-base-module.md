# ✨ java.base 모듈

## 1. java.base 모듈의 개념

`java.base` 모듈은 자바 프로그램이 기본적으로 사용하는 핵심 모듈이다.  
자바의 가장 기본적인 클래스들이 포함되어 있으며, 별도의 설정 없이 사용할 수 있다.

대표적으로 `java.lang` 패키지는 기본으로 제공되기 때문에 `import`가 필요 없다. 📌

즉, 자바 프로그램에서 자주 사용하는 기본 클래스들은 대부분 `java.base` 모듈에 포함되어 있다고 이해하면 된다.

## 2. java.lang 패키지

`java.lang` 패키지는 자바에서 가장 기본이 되는 클래스들을 제공한다.

이 패키지의 특징은 다음과 같다.

- 기본 제공 패키지
- `import` 없이 사용 가능
- 자바 프로그램에서 자주 사용하는 핵심 클래스 포함

대표적인 클래스는 다음과 같다.

- `Object`
- `String`
- `StringBuilder`
- `System`
- `Class`

즉, `java.lang`은 자바 프로그램의 기본 도구 모음이라고 볼 수 있다. ✅

## 3. 주요 클래스 정리

`java.base` 모듈에서 자주 사용하는 클래스들은 다음과 같다.

### 3-1. Object

`Object`는 자바의 최상위 클래스이다.

즉, 자바의 모든 클래스는 직접 또는 간접적으로 `Object`를 상속한다.

### 3-2. String

`String`은 문자열을 다루는 클래스이다.  
한 번 생성되면 내용을 바꿀 수 없는 불변 객체이다.

### 3-3. StringBuilder

`StringBuilder`는 문자열을 수정하면서 새로운 문자열을 만들어낼 때 사용한다.

`String`과 달리 원본 데이터를 변경하는 방식으로 동작하므로, 문자열 조작이 많을 때 유용하다.

### 3-4. StringTokenizer

`java.util.StringTokenizer`는 문자열을 구분자를 기준으로 분리할 때 사용한다.  
`split()`과 비슷한 역할을 한다.

### 3-5. Wrapper 클래스

Wrapper 클래스는 기본 타입의 값을 객체로 포장하는 클래스이다.

예를 들어 다음과 같이 대응된다.

- `int` → `Integer`
- `double` → `Double`
- `boolean` → `Boolean`

즉, 기본 타입을 참조 타입처럼 다룰 때 사용한다.

### 3-6. Class

`Class`는 리플렉션(reflection) 기능과 관련된 클래스이다.  
클래스 정보를 실행 중에 확인하거나 다룰 때 사용한다.

## 4. Object 클래스

클래스를 선언할 때 `extends` 키워드로 다른 클래스를 상속하지 않으면, 자동으로 `java.lang.Object` 클래스를 상속한다.

즉, 다음 클래스가 있다고 하자.

    class Member {
    }

이 클래스는 사실상 다음과 비슷하게 동작한다.

    class Member extends Object {
    }

따라서 자바의 모든 클래스는 `Object`의 자식이거나 자손 클래스이다. 📌

## 5. 객체 동등 비교

`Object` 클래스에는 `equals()` 메소드가 있다.

기본 `equals()` 메소드는 객체의 번지를 비교하고 boolean 값을 반환한다.

    obj1.equals(obj2)

기본 구현 기준에서는 다음 비교와 결과가 동일하다.

    obj1 == obj2

즉, `Object`의 기본 `equals()`는 객체의 내용이 아니라 참조 주소를 비교한다. ⚠️

다만 `String`처럼 일부 클래스는 `equals()`를 오버라이딩해서 내용 비교가 되도록 만들어져 있다.

## 6. 객체 해시코드

객체 해시코드는 객체를 식별하기 위한 정수값이다.

기본적으로 객체의 메모리 번지를 이용해서 해시코드를 생성하므로, 객체마다 다른 정수값이 반환될 수 있다.

해시코드는 다음 메소드로 확인할 수 있다.

    hashCode()

특히 해시코드는 `HashSet`, `HashMap` 같은 컬렉션에서 객체를 빠르게 찾거나 중복 여부를 판단하는 데 사용된다.

## 7. Set과 중복 처리

`Set`은 중복을 허용하지 않는 자료구조이다.

즉, 같은 데이터가 여러 번 들어오더라도 하나만 저장한다.

이때 객체의 중복 여부를 판단할 때 `equals()`와 `hashCode()`가 함께 사용된다. 📌

따라서 객체를 기준으로 중복을 판단해야 하는 경우에는 `equals()`와 `hashCode()`를 함께 재정의하는 것이 중요하다.

## 8. equals(), hashCode(), toString() 자동 생성

IntelliJ에서는 `Alt + Insert`를 이용해 다음 메소드들을 자동 생성할 수 있다.

- `hashCode()`
- `equals()`
- `toString()`

이 메소드들은 객체 비교, 해시 기반 컬렉션 사용, 객체 정보 출력에 자주 사용된다. ✅

## 9. toString() 메소드

`toString()`은 객체의 문자 정보를 반환하는 메소드이다.

기본 `toString()`은 클래스명과 해시코드 기반 문자열을 반환한다.  
하지만 필요에 따라 오버라이딩해서 객체의 필드 정보를 보기 좋게 출력할 수 있다.

예를 들어 객체를 출력할 때

    System.out.println(member);

처럼 작성하면 내부적으로 `toString()` 결과가 출력된다.

## 10. 레코드

레코드(record)는 데이터 전달을 위한 DTO 작성 시 반복되는 코드를 줄이기 위해 도입된 문법이다.

DTO는 Data Transfer Object의 약자로, 데이터를 전달하기 위해 사용하는 객체이다.

레코드를 사용하면 다음 코드들이 자동으로 추가된다.

- 생성자
- getter 역할의 메소드
- `hashCode()`
- `equals()`
- `toString()`

즉, 단순히 데이터를 담고 전달하기 위한 객체를 더 간단하게 만들 수 있다. 📌

## 11. System 클래스

`System` 클래스는 표준 입출력, 에러 출력, 프로그램 종료 등 시스템 관련 기능을 제공한다.

대표적인 필드는 다음과 같다.

- `System.out` → 표준 출력
- `System.err` → 에러 출력
- `System.in` → 표준 입력, 키보드 입력

필기 내용 기준으로 번호를 붙이면 다음과 같이 볼 수 있다.

- `out` → 1, 표준 출력
- `err` → 2, 에러 출력
- `in` → 0, 키보드 입력

## 12. System.out과 System.err

`System.out`은 buffering을 한다.  
반면 `System.err`는 buffering을 하지 않는다.

그래서 다음과 같이 작성하면

    System.out.print(1);
    System.err.print(2);

실제 출력 순서가 코드 순서와 다르게 보일 수 있다.

예를 들어 `2 1` 순서로 출력될 수도 있다. ⚠️

이유는 `out`은 버퍼에 모였다가 출력될 수 있고, `err`는 즉시 출력되는 성격이 있기 때문이다.

## 13. 리다이렉션

터미널에서는 표준 출력과 에러 출력을 파일로 보낼 수 있다.

예를 들어 다음 명령은 표준 출력을 `out.txt`로 보낸다.

    dir > out.txt

에러 출력은 다음과 같이 리다이렉션할 수 있다.

    2> err.txt

즉,

- `>` → 표준 출력 리다이렉션
- `2>` → 표준 에러 리다이렉션

으로 이해하면 된다.

## 14. 파이프

파이프(`|`)는 한 프로그램의 표준 출력을 다른 프로그램의 표준 입력으로 연결하는 기능이다.

형식은 다음과 같다.

    a | b

이 의미는 다음과 같다.

- `a`의 표준 출력
- `b`의 표준 입력으로 전달

즉, 한 명령의 결과를 다른 명령의 입력으로 연결할 때 사용한다.

## 15. System.exit()

`System.exit()`는 현재 프로세스를 강제로 종료하는 메소드이다.

형식은 다음과 같다.

    System.exit(0);

종료 코드의 의미는 보통 다음과 같다.

- `0` → 정상 종료
- 0이 아닌 값 → 개발자가 지정한 비정상 종료 또는 특정 종료 상태

즉, 프로그램을 즉시 끝내야 할 때 사용할 수 있지만, 일반적인 흐름에서는 신중하게 사용해야 한다. ⚠️

## 16. 중요 포인트 📌

- `java.base`는 자바의 기본 핵심 모듈이다.
- `java.lang` 패키지는 import 없이 사용할 수 있다.
- `Object`는 자바의 최상위 클래스이다.
- 다른 클래스를 상속하지 않으면 자동으로 `Object`를 상속한다.
- `String`은 불변 객체이다.
- `StringBuilder`는 문자열을 수정하면서 처리할 때 사용한다.
- `StringTokenizer`는 문자열 분리에 사용한다.
- Wrapper 클래스는 기본 타입을 객체로 포장한다.
- `Class`는 reflection 기능과 관련된다.
- Object의 기본 `equals()`는 참조 주소를 비교한다.
- `hashCode()`는 객체 식별 정수값을 반환한다.
- `Set`은 중복을 허용하지 않는다.
- `equals()`와 `hashCode()`는 함께 재정의하는 것이 중요하다.
- `toString()`은 객체의 문자 정보를 반환한다.
- record는 DTO 작성 시 반복 코드를 줄여 준다.
- `System.out`은 버퍼링을 하고, `System.err`는 버퍼링하지 않는다.
- `System.exit()`는 현재 프로세스를 강제 종료한다.

## 정리 ✅

`java.base` 모듈은 자바의 가장 기본적인 기능을 제공하는 핵심 모듈이다.  
그중 `java.lang` 패키지는 import 없이 사용할 수 있으며, `Object`, `String`, `StringBuilder`, `System`, `Class` 같은 기본 클래스가 포함된다.  
자바의 모든 클래스는 `Object`의 자식이거나 자손이며, `equals()`, `hashCode()`, `toString()` 같은 메소드는 객체 비교와 출력에서 매우 중요하다.  
또한 record는 DTO 작성 시 반복 코드를 줄여 주고, `System` 클래스는 표준 입출력, 에러 출력, 프로세스 종료 기능을 제공한다.  
시험 대비에서는 `Object` 클래스의 역할, `equals()`와 `hashCode()`의 의미, `String`과 `StringBuilder` 차이, record, `System.out`과 `System.err`의 차이를 함께 정리해 두는 것이 좋다.
