# ✨ 데이터 입출력

## 1. 입출력 스트림의 개념

입력 스트림과 출력 스트림의 기준은 프로그램이다.

즉, 프로그램으로 데이터가 들어오면 입력이고, 프로그램에서 데이터가 나가면 출력이다.  
프로그램이 다른 프로그램과 데이터를 교환하려면 양쪽 모두 입력 스트림과 출력 스트림이 필요하다. 📌

정리하면 다음과 같다.

- 입력 스트림 → 프로그램으로 데이터가 들어옴
- 출력 스트림 → 프로그램에서 데이터가 나감

## 2. 바이트 스트림과 문자 스트림

자바의 입출력 스트림은 처리하는 데이터 종류에 따라 크게 두 가지로 나눌 수 있다.

- 바이트 스트림
- 문자 스트림

### 2-1. 바이트 스트림

바이트 스트림은 그림, 멀티미디어, 문자 등 모든 종류의 데이터를 입출력할 때 사용한다.

바이트 스트림 클래스는 보통 `Stream`으로 끝난다.

대표적인 추상 클래스는 다음과 같다.

- `InputStream`
- `OutputStream`

### 2-2. 문자 스트림

문자 스트림은 문자 데이터만 입출력할 때 사용한다.

문자 스트림 클래스는 보통 `Reader` 또는 `Writer`로 끝난다.

즉,

- 바이트 스트림 → `~Stream`
- 문자 스트림 → `~Reader`, `~Writer`

로 구분할 수 있다. ✅

## 3. OutputStream

`OutputStream`은 바이트 출력 스트림의 최상위 추상 클래스이다.

대표적인 출력 메소드는 다음과 같다.

    write(int b)
    write(byte[] b)
    write(byte[] b, int off, int len)

각 메소드의 의미는 다음과 같다.

- `write(int b)` → 1byte 출력
- `write(byte[] b)` → 배열의 모든 바이트 출력
- `write(byte[] b, int off, int len)` → 배열 일부 출력

즉, 출력할 데이터의 크기와 방식에 따라 메소드를 선택해서 사용한다.

## 4. write(int b)

`write(int b)`는 1byte를 출력하는 메소드이다.

매개값은 `int` 타입이지만 실제로 출력되는 것은 끝 1byte뿐이다.

즉, `int`는 4byte이지만 그중 마지막 1byte만 출력 스트림으로 내보낸다. 📌

    outputStream.write(65);

이 경우 65에 해당하는 1byte 값이 출력된다.

## 5. 출력 버퍼와 flush()

입출력 장치는 보통 프로그램보다 속도가 느리다.  
그래서 데이터를 쓸 때마다 바로 장치로 보내는 것이 아니라, 버퍼에 모아 두었다가 한 번에 내보내는 방식이 사용된다.

이때 중요한 메소드가 `flush()`이다.

    outputStream.flush();

`flush()`는 출력 버퍼에 남아 있는 모든 바이트를 강제로 출력한다.  
즉, 버퍼를 비워서 장치로 데이터를 내보내는 역할을 한다.

출력 작업에서 가장 신경 써야 하는 작업 중 하나가 바로 `flush()`이다. ⚠️

## 6. 파일 경로 작성 주의

윈도우 파일 경로에서 `\`를 사용할 때는 주의가 필요하다.

예를 들어 `\t`는 탭 문자로 인식될 수 있다.  
따라서 경로를 작성할 때는 다음 두 방식 중 하나를 사용하면 된다.

    C:\\temp\\test.db

또는

    C:/temp/test.db

즉, 백슬래시를 쓰려면 `\\`처럼 두 개를 사용하거나, 슬래시(`/`)를 사용하는 것이 안전하다. 📌

## 7. FileOutputStream 특징

파일에 데이터를 출력할 때는 `FileOutputStream`을 사용할 수 있다.

특징은 다음과 같다.

- 파일이 없으면 새로 만든다.
- 파일이 있으면 기존 데이터를 버리고 새로 쓴다.
- 파일은 새로 만들 수 있지만 디렉토리는 자동으로 만들지 않는다.
- 해당 디렉토리에 쓰기 권한이 있어야 한다.

즉, 파일 출력은 파일 생성뿐 아니라 경로와 권한도 함께 고려해야 한다. ⚠️

## 8. IOException

입출력 관련 예외의 대표적인 최상위 클래스는 `IOException`이다.

`IOException`은 `Exception`의 하위 클래스이다.  
따라서 파일 입출력 작업에서는 예외 처리가 필요하다.

즉, 파일이 없거나, 권한이 없거나, 입출력 도중 문제가 생기면 `IOException` 계열 예외가 발생할 수 있다.

## 9. close()와 finally

입출력 스트림을 사용한 뒤에는 반드시 `close()`로 닫아야 한다.

하지만 `try` 블록 중간에 예외가 발생하면 `close()`가 실행되지 않을 수 있다.  
그래서 전통적으로는 `finally` 블록에서 `close()`를 호출했다.

    try {
        // 입출력 작업
    } catch (IOException e) {
        // 예외 처리
    } finally {
        // close 처리
    }

즉, 리소스 정리는 예외 발생 여부와 상관없이 실행되어야 한다.

## 10. try-with-resources

자바에서는 리소스를 자동으로 닫기 위해 try-with-resources 방식을 사용할 수 있다.

    try (OutputStream os = new FileOutputStream("C:/temp/test1.db")) {
        // 출력 작업
    }

이 방식은 `try` 블록을 벗어날 때 자동으로 `close()`가 호출된다.  
따라서 직접 `finally`에서 닫는 방식보다 안전하고 간결하다. ✅

## 11. 바이트 배열 출력

바이트 배열 전체를 출력할 때는 다음 메소드를 사용한다.

    write(byte[] b)

배열의 일부만 출력하고 싶다면 다음 메소드를 사용한다.

    write(byte[] b, int off, int len)

의미는 다음과 같다.

- `b` → 출력할 바이트 배열
- `off` → 출력 시작 위치
- `len` → 출력할 바이트 수

여러 번 `write()`를 호출하는 것보다 한 번에 배열로 출력하는 것이 훨씬 빠르다. 📌

## 12. BufferedOutputStream과 BufferedInputStream

`BufferedOutputStream`과 `BufferedInputStream`은 버퍼 기능이 내장된 보조 스트림이다.

- `BufferedOutputStream` → 출력 버퍼 제공
- `BufferedInputStream` → 입력 버퍼 제공

버퍼를 사용하면 입출력 장치에 직접 접근하는 횟수를 줄일 수 있어 성능을 높일 수 있다.

즉, 많은 데이터를 입출력할 때는 버퍼 스트림을 사용하는 것이 효율적이다.

## 13. InputStream

`InputStream`은 바이트 입력 스트림의 최상위 추상 클래스이다.

대표적인 입력 메소드는 다음과 같다.

    int read()
    int read(byte[] b)
    close()

각 메소드의 의미는 다음과 같다.

- `read()` → 1byte를 읽고 읽은 바이트를 리턴
- `read(byte[] b)` → 읽은 바이트를 배열에 저장하고 읽은 바이트 수 리턴
- `close()` → 입력 스트림 닫기

즉, 입력 스트림은 데이터를 읽어 오고 사용이 끝나면 닫아야 한다.

## 14. read()

`read()`는 입력 스트림으로부터 1byte를 읽고 `int` 타입으로 리턴한다.

리턴 타입은 `int`이지만 실제 데이터는 마지막 1byte에 들어 있다.

    int data = inputStream.read();

더 이상 입력 스트림으로부터 읽을 바이트가 없으면 `-1`을 리턴한다.

이 `-1`은 반복문 종료 조건으로 자주 사용된다. ✅

예를 들면 다음과 같다.

    int data;
    while ((data = inputStream.read()) != -1) {
        // 읽은 데이터 처리
    }

## 15. read(byte[] b)

`read(byte[] b)`는 입력 스트림에서 여러 바이트를 읽어 배열에 저장한다.

리턴값은 실제로 읽은 바이트 수이다.

    byte[] buffer = new byte[1024];
    int readByteNum = inputStream.read(buffer);

이 방식은 1byte씩 읽는 것보다 훨씬 효율적이다.  
특히 파일처럼 많은 데이터를 읽을 때는 배열을 이용해 한 번에 읽는 것이 좋다. 📌

## 16. 입력과 출력의 기본 흐름

파일 입출력의 기본 흐름은 다음과 같다.

1. 스트림을 연다.
2. 데이터를 읽거나 쓴다.
3. 필요하면 `flush()`한다.
4. 스트림을 닫는다.

출력에서는 버퍼에 데이터가 남을 수 있으므로 `flush()`가 중요하고, 입력과 출력 모두 사용이 끝난 뒤 `close()`가 중요하다.

## 17. 중요 포인트 📌

- 입력과 출력의 기준은 프로그램이다.
- 바이트 스트림은 모든 종류의 데이터를 처리할 수 있다.
- 문자 스트림은 문자 데이터만 처리한다.
- 바이트 스트림은 `InputStream`, `OutputStream` 계열이다.
- 문자 스트림은 `Reader`, `Writer` 계열이다.
- `OutputStream`의 `write(int b)`는 끝 1byte만 출력한다.
- 출력 작업에서는 `flush()`가 중요하다.
- 파일 경로에서 `\`는 이스케이프 문자로 해석될 수 있으므로 `\\` 또는 `/`를 사용한다.
- `FileOutputStream`은 파일이 없으면 만들고, 있으면 기존 내용을 덮어쓴다.
- 파일은 만들지만 디렉토리는 자동 생성하지 않는다.
- 입출력 예외의 대표 클래스는 `IOException`이다.
- 스트림은 사용 후 반드시 닫아야 한다.
- try-with-resources를 사용하면 자동으로 `close()`된다.
- 배열 단위 입출력이 1byte씩 처리하는 것보다 빠르다.
- `read()`는 더 이상 읽을 데이터가 없으면 `-1`을 리턴한다.
- `BufferedInputStream`, `BufferedOutputStream`은 버퍼 기능을 제공한다.

## 정리 ✅

데이터 입출력은 프로그램을 기준으로 데이터가 들어오는 입력과 데이터가 나가는 출력으로 나뉜다.  
자바의 스트림은 바이트 스트림과 문자 스트림으로 구분되며, 바이트 스트림은 모든 종류의 데이터를 처리하고 문자 스트림은 문자 데이터 처리에 사용된다.  
`OutputStream`은 데이터를 출력할 때 사용하며, `write()`와 `flush()`가 중요하고, `InputStream`은 데이터를 읽을 때 사용하며 `read()`가 더 이상 읽을 데이터가 없을 때 `-1`을 리턴한다.  
파일 입출력에서는 `IOException` 처리가 필요하고, 스트림을 안전하게 닫기 위해 try-with-resources 사용이 권장된다.  
시험 대비에서는 입력/출력 기준, 바이트 스트림과 문자 스트림 차이, `write()`와 `read()`의 동작, `flush()`와 `close()`, try-with-resources, 버퍼 스트림의 역할을 함께 정리해 두는 것이 중요하다.
