# ✨ 제네릭

## 1. 제네릭이 필요한 이유
어떤 타입이든 저장할 수 있게 하려면 가장 먼저 떠올릴 수 있는 방법은 `Object` 타입을 사용하는 것이다.

`Object` 타입은 모든 클래스의 최상위 타입이므로 어떤 객체든 담을 수 있다.  
즉, 값을 저장할 때는 업캐스팅이 자동으로 일어나기 때문에 큰 문제가 없다.

하지만 꺼내서 실제로 사용할 때는 문제가 생긴다.

- 저장할 때 → 업캐스팅이라 문제 없음
- 꺼낼 때 → 원래 타입으로 다운캐스팅 필요
- 무엇이 들어 있는지 확실하지 않으면 안전하지 않음 ⚠️

즉, `Object`를 사용하면 "아무거나 담을 수는 있지만", 꺼내 쓸 때 타입 안정성이 떨어진다.  
이 문제를 해결하기 위해 제네릭을 사용한다. 📌

## 2. 제네릭의 개념
제네릭은 결정되지 않은 타입을 파라미터처럼 처리하는 문법이다.

즉, 클래스를 만들 때 타입을 미리 확정하지 않고, 실제 사용할 때 구체적인 타입으로 대체하는 방식이다.

대표적인 예시는 다음과 같다.

    public class Box<T> {
        public T content;
    }

여기서 `T`는 타입 파라미터이다.  
보통 대문자 한 글자로 작성한다.

즉, `T`는 아직 정해지지 않은 타입을 의미하고, 실제 객체를 만들 때 구체적인 타입으로 바뀐다.

## 3. 제네릭 클래스 사용 방법
제네릭 클래스를 사용할 때는 실제 타입을 지정해야 한다.

예를 들면 다음과 같다.

    Box<Integer> box = new Box<Integer>();

이 코드는 `Box` 안의 `T`가 `Integer`로 결정된다는 뜻이다.  
즉, 이제 `content`에는 `Integer` 타입만 저장할 수 있다.

자바에서는 생성자 쪽 타입을 생략해서 더 짧게 쓸 수도 있다.

    Box<Integer> box = new Box<>();

이것을 타입 추론이라고 볼 수 있다.  
즉, 왼쪽 선언을 보고 오른쪽 타입을 자동으로 판단하는 방식이다.

## 4. primitive 타입 사용 불가
제네릭에는 `int`, `double`, `char` 같은 primitive 타입을 직접 사용할 수 없다.

즉, 다음과 같은 코드는 불가능하다.

    Box<int> box;

대신 Wrapper 클래스를 사용해야 한다.

- `int` → `Integer`
- `double` → `Double`
- `char` → `Character`

즉, 제네릭에서는 기본 타입이 아니라 참조 타입을 사용해야 한다는 점을 꼭 기억해야 한다. ✅

## 5. 클래스와 인터페이스 레벨의 제네릭
제네릭은 클래스와 인터페이스 선언에서도 사용할 수 있다.

기본 형식은 다음과 같다.

    public class 클래스명<A, B, ...> { ... }

즉, 타입 파라미터를 하나만 쓰는 것이 아니라 여러 개를 동시에 사용할 수도 있다.

또한 외부에서 제네릭 타입을 사용할 때 타입 파라미터에 구체적인 타입을 지정하지 않으면 `Object` 타입이 암묵적으로 사용된다.

즉, 타입을 생략하면 결국 안전성이 떨어질 수 있으므로 가능한 한 구체적인 타입을 명시하는 것이 좋다. ⚠️

## 6. 제네릭 메소드
제네릭은 클래스 레벨뿐 아니라 메소드 레벨에서도 사용할 수 있다.

제네릭 메소드는 메소드를 호출할 때 타입이 결정된다.  
즉, 타입 파라미터가 메소드 선언부에 정의된다.

형식은 다음과 같다.

    public <A, B, ...> 리턴타입 메소드명(매개변수, ...) { ... }

예를 들면 다음과 같다.

    public <T> Box<T> boxing(T t) { ... }

여기서 `<T>`는 메소드 자체의 타입 파라미터이다.  
즉, 이 메소드를 호출할 때 전달한 값의 타입에 따라 `T`가 결정된다.

## 7. 제네릭 메소드 내부 동작
제네릭 메소드 안에서는 결정된 타입 파라미터를 일반 타입처럼 사용할 수 있다.

예를 들면 다음과 같이 작성할 수 있다.

    Box<T> box = new Box<T>();
    return box;

즉, 메소드 안에서는 `T`가 하나의 실제 타입처럼 동작한다.

사용 예시는 다음과 같다.

    Box<Integer> box1 = boxing(100);

이 경우 `100`이 `Integer`로 해석되므로 `T`는 `Integer`가 된다.  
즉, 컴파일 과정에서 구체적인 타입으로 대체되어 동작한다. 📌

## 8. 제한된 타입 파라미터
제네릭은 모든 타입을 무조건 허용하는 것이 아니라, 특정 타입 범위로 제한할 수도 있다.

즉, 특정 상위 타입과 그 자식 타입 또는 구현 타입만 사용할 수 있게 만들 수 있다.

형식은 다음과 같다.

    public <T extends 상위타입> 리턴타입 메소드(매개변수, ...) { ... }

여기서 `extends`는 클래스 상속뿐 아니라 인터페이스 구현 관계에도 사용할 수 있다.

즉,

- 특정 클래스의 자식만 허용
- 특정 인터페이스 구현체만 허용

하는 방식으로 타입 범위를 제한할 수 있다.

이 기능은 타입 안정성을 더 높이고, 필요한 기능이 있는 타입만 받도록 만들 때 유용하다.

## 9. 와일드카드 타입 파라미터
와일드카드는 제네릭 타입을 매개값이나 리턴 타입으로 사용할 때, 허용할 타입 범위를 표현하는 방법이다.

즉, "정확히 하나의 타입"이 아니라 "일정 범위 안의 여러 타입"을 허용할 때 사용한다.

대표적인 형태는 다음과 같다.

    리턴타입 메소드명(제네릭타입<? extends Student> 변수) { ... }
    리턴타입 메소드명(제네릭타입<? super Worker> 변수) { ... }
    리턴타입 메소드명(제네릭타입<?> 변수) { ... }

## 10. extends 와일드카드
`<? extends Student>`는 `Student` 또는 그 하위 타입만 허용한다.

즉, 상한 제한이 있는 와일드카드이다.

이 구조는 다음처럼 이해하면 된다.

- Student 가능
- Student의 자식 타입 가능
- 그보다 상위 타입은 불가

즉, 특정 타입 이하의 범위를 허용하고 싶을 때 사용한다.

## 11. super 와일드카드
`<? super Worker>`는 `Worker` 또는 그 상위 타입을 허용한다.

즉, 하한 제한이 있는 와일드카드이다.

이 구조는 다음처럼 이해하면 된다.

- Worker 가능
- Worker의 부모 타입 가능
- Worker의 자식 타입은 기준이 아님

즉, 특정 타입 이상 범위를 허용하고 싶을 때 사용한다.

## 12. ? 와일드카드
`<?>`는 모든 타입을 허용한다.

즉, 타입을 구체적으로 알 수는 없지만 어떤 타입이든 받을 수 있게 하는 방식이다.

다만 모든 타입을 허용하는 만큼, 내부에서 사용할 수 있는 기능은 제한적일 수 있다.  
즉, "무엇이 들어 있는지는 모르지만 제네릭 구조 자체는 유지하고 싶다"는 상황에서 사용한다.

## 13. 제네릭의 장점
제네릭을 사용하면 다음과 같은 장점이 있다.

- 타입 안정성 향상
- 불필요한 다운캐스팅 감소
- 코드 재사용성 증가
- 컴파일 단계에서 타입 오류를 더 빨리 발견 가능

즉, 제네릭은 단순히 문법을 복잡하게 만드는 기능이 아니라, 안전하고 재사용 가능한 코드를 만들기 위한 도구이다. ✅

## 14. 중요 포인트 📌
- `Object` 타입은 아무 객체나 담을 수 있지만 꺼낼 때 다운캐스팅이 필요해서 안전하지 않다.
- 제네릭은 결정되지 않은 타입을 파라미터처럼 처리하는 문법이다.
- `T`는 타입 파라미터이며 보통 대문자 한 글자로 작성한다.
- 제네릭 클래스는 실제 사용할 때 구체적인 타입으로 대체된다.
- 생성자 쪽 타입은 `new Box<>()`처럼 생략할 수 있다.
- primitive 타입은 제네릭에 직접 사용할 수 없고 Wrapper 클래스를 사용해야 한다.
- 제네릭은 클래스, 인터페이스, 메소드 레벨에서 모두 사용할 수 있다.
- 타입 파라미터를 지정하지 않으면 `Object`가 암묵적으로 사용된다.
- 제한된 타입 파라미터는 특정 상위 타입과 그 하위 타입만 허용한다.
- 와일드카드는 제네릭 타입의 허용 범위를 표현할 때 사용한다.
- `? extends`는 상한 제한, `? super`는 하한 제한, `?`는 전체 허용이다.

## 정리 ✅
제네릭은 타입을 미리 고정하지 않고 실제 사용할 때 구체적인 타입으로 결정하는 기능이다.  
`Object`를 사용하는 방식보다 더 안전하며, 불필요한 다운캐스팅을 줄일 수 있다는 장점이 있다.  
제네릭은 클래스, 인터페이스, 메소드에서 사용할 수 있고, 제한된 타입 파라미터와 와일드카드를 통해 허용 범위를 세밀하게 조절할 수도 있다.  
시험 대비에서는 제네릭의 필요성, 타입 파라미터 의미, 제네릭 메소드, 제한된 타입 파라미터, 와일드카드의 차이를 구분해서 정리하는 것이 중요하다.
