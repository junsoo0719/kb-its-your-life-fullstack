# ✨ 참조 타입

## 1. 참조 타입의 개념

참조 타입은 객체가 저장된 번지를 참조하는 타입이다.  
즉, 변수 안에 실제 데이터가 직접 들어가는 것이 아니라 객체가 있는 위치 정보가 저장된다.

대표적인 참조 타입은 다음과 같다.

- 배열
- 열거
- 클래스
- 인터페이스

여기서 객체는 보통 다음 두 가지로 구성된다고 이해하면 된다.

- 데이터(필드)
- 기능(메소드)

즉, 참조 타입은 객체 자체를 다루기 위한 타입이다. 📌

## 2. 메모리 영역과 객체

객체는 동적 메모리 영역인 힙(Heap)에 생성된다.  
반면 지역 변수는 스택(Stack) 영역에서 관리된다.

정리하면 다음과 같다.

- 힙 → 객체 인스턴스 저장
- 스택 → 지역 변수 저장

즉, 참조 타입 변수는 스택에 존재하지만, 실제 객체는 힙에 존재한다.

## 3. 자바 프로그램 실행 과정

`java.exe`가 실행되면 JVM이 먼저 `.class` 파일을 찾는다.  
예를 들어 `Hello.class` 파일을 먼저 찾고, 파일명과 동일한 클래스를 확인한다.

그 다음 과정은 다음과 같다.

1. 클래스를 메모리로 가져온다.
2. 클래스 정보는 메소드 영역에 올라간다.
3. `main()` 메소드를 찾는다.
4. `main()`을 호출한다.
5. 스택이 생성된다.
6. 스택 프레임 안에서 지역 변수가 운영된다.
7. 참조 타입 값인 객체 인스턴스는 힙 영역에 생성된다.

메소드 영역에는 클래스의 데이터, 메소드, 상수 등이 올라간다.  
그리고 이 영역은 기본적으로 읽기 중심으로 사용된다고 이해하면 된다.

## 4. 스레드와 메모리 영역

노드나 자바스크립트는 보통 단일 스레드 구조로 많이 설명된다.  
반면 자바는 멀티 스레드 환경을 지원한다.

자바에서 메모리 구조를 스레드 기준으로 보면 다음과 같다.

- 스레드마다 스택은 따로 가짐
- 메소드 영역과 힙 영역은 공유함

즉, 지역 변수는 스레드마다 따로 관리되지만, 객체와 클래스 정보는 여러 스레드가 함께 사용할 수 있다.

## 5. 스택과 힙의 초기화 차이

힙 영역은 `new`로 객체를 생성할 때 기본값으로 초기화된다.  
즉, 객체 생성 시 내부 값들이 0 또는 기본값으로 채워진다.

반면 스택 영역의 지역 변수는 자동 초기화되지 않는다. ⚠️  
그래서 초기화하지 않은 지역 변수를 사용하면 컴파일 에러가 발생한다.

정리하면 다음과 같다.

- 힙 → 기본값으로 초기화됨
- 스택 → 자동 초기화되지 않음

## 6. null 값

`null`은 아무 객체도 참조하지 않는 상태를 의미한다.

즉, 참조 타입 변수가 어떤 객체도 가리키지 않을 때 `null` 값을 가진다.  
숫자 개념으로 비유하면 0처럼 이해할 수 있지만, 실제 의미는 "참조 없음"이다.

`null`은 참조 타입의 초기값으로 자주 사용된다.  
또한 쓰레기값 대신 안전하게 초기 상태를 표현하기 위해 사용하기도 한다.

`null`에 대해서는 다음 연산만 가능하다.

- 같다(`==`)
- 다르다(`!=`)

즉, 참조 여부 비교만 가능하다고 이해하면 된다.

## 7. NullPointerException

`null`에 대해 객체처럼 접근하면 `NullPointerException`이 발생한다.

예를 들면 다음과 같은 경우이다.

- `null` 변수로 메소드 호출
- `null` 변수로 필드 접근

즉, 참조 대상이 없는데도 뭔가 작업을 하려 하면 예외가 발생한다. ⚠️  
단, `==`, `!=` 같은 비교 연산은 가능하다.

## 8. 가비지와 가비지 컬렉터

자바에는 `delete` 키워드가 없다.  
즉, 더 이상 사용하지 않는 객체를 직접 삭제하지 않는다.

어떤 객체를 더 이상 참조하지 않게 만들고 싶다면 보통 `null`을 대입한다.

    ref = null;

이렇게 하면 기존 객체는 더 이상 참조되지 않을 수 있고, 이 상태의 객체를 garbage라고 한다.

Garbage Collector는 이런 객체를 자동으로 회수해서 메모리를 반납하는 역할을 한다. ✅

garbage가 되는 경우는 대표적으로 다음과 같다.

- `null`을 강제로 대입한 경우
- 다른 객체를 참조하게 바꿔서 기존 참조가 끊긴 경우

## 9. String 타입과 불변 객체

`String` 타입은 대표적인 참조 타입이며, 불변 객체이다.

불변 객체라는 뜻은 한 번 생성되면 내용을 수정할 수 없다는 의미이다.  
즉, 문자열을 바꾸는 것처럼 보여도 실제로는 새로운 문자열 객체가 만들어진다.

문자열 리터럴은 상수처럼 처리된다.  
그래서 같은 리터럴은 기존 객체를 재사용할 수 있고, 같은 참조를 가질 수 있다.

반대로 서로 다른 참조로 분리하고 싶다면 `new`를 사용해 명시적으로 객체를 생성할 수 있다.

즉,

- 리터럴 사용 → 같은 문자열이면 기존 객체 재사용 가능
- `new String()` 사용 → 별도 객체 생성

이다. 📌

## 10. 문자열 비교

참조가 아니라 실제 문자열 내용을 비교하고 싶다면 `equals()`를 사용해야 한다.

    str1.equals(str2)

`==`는 참조를 비교하고, `equals()`는 실제 데이터를 비교한다.  
즉, 문자열 비교에서는 `equals()`가 기본이라고 생각하면 된다.

## 11. 문자 추출과 문자열 길이

자바 문자열은 인덱스 연산자 `[]`로 접근하지 않는다.  
문자를 꺼낼 때는 `charAt(index)` 메소드를 사용한다.

    str.charAt(0)

문자열 길이는 `length()` 메소드로 구한다.

    str.length()

즉,

- 문자 추출 → `charAt()`
- 문자열 길이 → `length()`

로 정리하면 된다.

## 12. 문자열 대체

문자열 일부를 다른 문자열로 바꾸고 싶을 때는 `replace()`를 사용한다.

    str.replace("기존문자열", "변경문자열")

여기서 중요한 점은 원본 문자열이 바뀌지 않는다는 것이다.  
`String`은 불변 객체이므로, 대체된 새로운 문자열이 만들어져서 반환된다. ⚠️

## 13. 문자열 잘라내기

문자열 일부를 잘라낼 때는 `substring()`을 사용한다.

    substring(int beginIndex)
    substring(int beginIndex, int endIndex)

의미는 다음과 같다.

- `substring(beginIndex)` → beginIndex부터 끝까지
- `substring(beginIndex, endIndex)` → beginIndex부터 endIndex 앞까지

즉, 두 번째 방식은 `endIndex - 1`까지 잘린다고 이해하면 된다.

## 14. 문자열 찾기

문자열 안에서 특정 문자열의 위치를 찾을 때는 `indexOf()`를 사용한다.

    str.indexOf("문자열")

결과는 다음과 같다.

- 찾으면 시작 인덱스 반환
- 못 찾으면 `-1` 반환

또한 `lastIndexOf()`는 뒤에서부터 찾는다.  
다만 반환값은 뒤에서 처음 발견한 위치의 인덱스이다.

## 15. 문자열 분리와 시작/끝 검사

문자열을 구분자를 기준으로 나누려면 `split()`을 사용한다.

    str.split("구분자")

이 메소드는 잘라진 문자열 배열을 반환한다.  
즉, 반환값은 배열이므로 인덱스로 접근할 수 있다.

문자열의 시작과 끝을 검사할 때는 다음 메소드를 사용한다.

- `startsWith()`
- `endsWith()`

이 메소드들은 `true` 또는 `false`를 반환한다.

## 16. 배열의 필요성

배열은 여러 개의 데이터를 하나의 변수명으로 관리할 수 있게 해 준다.

즉, 같은 타입의 데이터를 여러 개 저장하고, 인덱스를 통해 접근할 수 있다.  
그래서 반복문과 함께 사용하기 좋다. 📌

## 17. 배열의 특징

배열은 다음과 같은 특징을 가진다.

- 타입이 고정됨
- 크기가 고정됨
- 인덱스로 접근 가능
- 검색 속도가 빠름

즉, 데이터 크기와 타입이 일정할 때 효율적이다.

하지만 크기를 미리 정해야 하므로 유연성은 떨어질 수 있다.  
스크립트 언어의 배열처럼 크기가 자유롭게 바뀌지 않는다는 점도 특징이다.

## 18. 배열 선언과 초기화

배열은 다음과 같이 선언할 수 있다.

    타입[] 변수;

선언과 동시에 초기값을 줄 때는 `new`를 생략할 수 있다.

    int[] scores = {95, 85, 90};

하지만 이미 선언된 변수에 나중에 `{}`만 사용해서 대입하면 컴파일 에러가 발생한다.

    int[] scores;
    scores = {95, 85, 90};   // 컴파일 에러

이유는 `{}`가 일반 문장에서는 코드 블록으로 해석되기 때문이다.  
이 경우에는 반드시 `new`를 붙여야 한다.

    scores = new int[] {95, 85, 90};

## 19. 메소드 호출 시 배열 전달

배열을 매개변수로 넘길 때도 `{}`만 단독으로 사용할 수 없다.

예를 들면 다음과 같다.

    void printItem(int[] scores) { ... }

    printItem({95, 85, 90});   // 컴파일 에러
    printItem(new int[] {95, 85, 90});   // 가능

즉, 선언과 동시에 초기화하는 경우가 아니라면 `new 타입[] { ... }` 형태를 사용해야 한다.

## 20. new 연산자로 배열 생성

배열 길이만 정하고 값을 따로 주지 않으려면 `new`로 생성한다.

    타입[] 변수 = new 타입[길이];

이 경우에는 공간만 확보되고 기본값으로 초기화된다.

초기값은 타입에 따라 다르다.

- 숫자 타입 → 0
- `boolean` → `false`
- 참조 타입 → `null`

즉, 배열도 객체이기 때문에 힙에 생성되고 기본값이 자동으로 채워진다.

## 21. 배열 길이

배열 길이는 `length`로 확인한다.

    scores.length

여기서 `length`는 메소드가 아니라 상수 같은 속성이다.  
즉, 괄호 `()`를 붙이지 않는다.

또한 `length` 값은 읽기 전용이므로 직접 바꿀 수 없다.  
변경하려고 하면 컴파일 에러가 발생한다.

## 22. 다차원 배열

다차원 배열은 배열 안에 배열이 들어 있는 구조이다.

예를 들어 2차원 배열은 다음처럼 표현할 수 있다.

    int[][] scores = { { ... }, { ... } }

여기서 고차원 배열은 저차원 배열 객체를 참조하는 변수라고 이해할 수 있다.  
즉, 바깥 배열 안에 안쪽 배열의 참조값이 들어 있다.

그래서 각 배열의 길이가 서로 다를 수도 있다.

    scores[0].length

처럼 각 행의 길이를 따로 확인할 수도 있다.

## 23. new를 이용한 다차원 배열 생성

다차원 배열도 `new`를 이용해 만들 수 있다.

    int[][] scores = new int[2][3];

이 코드는 2행 3열 형태의 배열을 만든다.

다음과 같이 일부 차원만 먼저 만들 수도 있다.

    String[][] names = new String[2][];

이 경우에는 바깥 배열만 생성되고, 안쪽 배열은 아직 `null` 상태이다.  
즉, 각 행의 길이를 다르게 만들 수 있다.

    names[0] = new String[3];
    names[1] = new String[2];

이처럼 각 배열 길이를 다르게 주는 것도 가능하다. ✅

## 24. 배열 복사

배열은 길이를 바꿀 수 없다.  
그래서 더 큰 배열이나 다른 길이의 배열이 필요하면 새 배열을 만들고 기존 값을 복사해야 한다.

대표적인 방법은 `System.arraycopy()`이다.

    System.arraycopy(Object src, int srcPos, Object dest, int destPos, int length);

의미는 다음과 같다.

- 원본 배열
- 원본 시작 인덱스
- 새 배열
- 새 배열 붙여넣기 시작 인덱스
- 복사할 항목 수

즉, 원하는 구간만 빠르게 복사할 수 있다.

남는 공간은 기본값으로 초기화된다.

## 25. 얕은 복사

배열 복사에서 중요한 개념 중 하나는 깊은 복사와 얕은 복사이다.

필기 내용 기준으로 `System.arraycopy()`는 깊은 복사가 아니라 얕은 복사로 이해하면 된다.

얕은 복사는 다음 의미를 가진다.

- 원본은 그대로 존재
- 참조값만 복사될 수 있음
- 복사 속도가 빠름

즉, 참조 타입 배열에서는 내부 객체까지 새로 복제하는 것이 아니라 참조만 복사된다고 이해해야 한다. ⚠️

## 26. 중요 포인트 📌

- 참조 타입은 객체의 번지를 저장하는 타입이다.
- 객체는 힙에 생성되고, 지역 변수는 스택에 생성된다.
- 자바는 멀티 스레드 환경이며, 스택은 스레드마다 따로 가진다.
- 힙은 기본값으로 초기화되지만 스택은 자동 초기화되지 않는다.
- `null`은 아무것도 참조하지 않는 상태이다.
- `null`에 대해 메소드 호출이나 필드 접근을 하면 `NullPointerException`이 발생한다.
- 더 이상 사용하지 않는 객체는 garbage가 되고, Garbage Collector가 자동 회수한다.
- `String`은 불변 객체이다.
- 문자열 비교는 `==`가 아니라 `equals()`를 사용한다.
- 문자열 처리는 `charAt()`, `length()`, `replace()`, `substring()`, `indexOf()`, `split()` 등을 자주 사용한다.
- 배열은 같은 타입의 데이터를 하나의 이름으로 관리할 수 있다.
- 배열은 크기가 고정되어 있다.
- 배열 길이는 `length`로 확인하며 변경할 수 없다.
- 다차원 배열은 배열 안에 배열이 들어 있는 구조이다.
- 배열 복사는 보통 새 배열을 만든 뒤 진행하며, `System.arraycopy()`를 사용할 수 있다.

## 정리 ✅

참조 타입은 객체의 실제 데이터를 직접 저장하는 것이 아니라 객체가 있는 위치를 저장하는 타입이다.  
객체는 힙에 생성되고 참조 변수는 스택에서 관리되며, `null`, 가비지, 가비지 컬렉터 개념도 함께 이해해야 한다.  
특히 `String`은 대표적인 참조 타입이자 불변 객체이므로, 문자열을 조작할 때는 항상 새로운 문자열이 만들어진다는 점이 중요하다.  
배열 역시 참조 타입이며, 같은 타입의 데이터를 효율적으로 관리할 수 있지만 크기가 고정되어 있다는 특징이 있다.  
시험 대비에서는 참조 타입의 메모리 구조, `null`과 예외, 문자열 메소드, 배열 선언과 초기화, 다차원 배열, 배열 복사 개념까지 함께 정리해 두는 것이 좋다.
