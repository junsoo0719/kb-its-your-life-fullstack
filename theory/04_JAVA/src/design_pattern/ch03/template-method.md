# ✨ Template Method - 하위 클래스에서 구체적으로 처리한다

## 1. 템플릿의 의미

템플릿은 전체적인 모양이나 구조를 잡아 주는 틀을 의미한다.  
즉, 세부 내용은 달라질 수 있지만 전체 흐름은 일정하게 유지되도록 만드는 기준이다.

디자인 패턴에서 템플릿은 알고리즘의 큰 흐름을 정해 두고, 세부 구현은 다른 쪽에서 채우도록 만드는 구조로 이해할 수 있다. 📌

## 2. Template Method 패턴의 개념

Template Method 패턴은 상위 클래스에서 처리의 뼈대를 결정하고, 하위 클래스에서 구체적인 내용을 결정하는 디자인 패턴이다.

즉, 전체 알고리즘의 흐름은 상위 클래스가 가지고 있고, 각 단계에서 실제로 무엇을 할지는 하위 클래스가 구현한다.

정리하면 다음과 같다.

- 상위 클래스 → 처리 흐름, 알고리즘의 뼈대 결정
- 하위 클래스 → 각 단계의 구체적인 처리 구현

## 3. 상위 클래스의 역할

Template Method 패턴에서 상위 클래스는 템플릿이 되는 메소드를 정의한다.  
이 메소드는 전체 처리 순서를 정해 주는 역할을 한다.

또한 세부 단계는 추상 메소드로 선언해 둔다.

즉, 상위 클래스는 다음을 담당한다.

- 전체 알고리즘 흐름 정의
- 처리 순서 고정
- 하위 클래스가 구현해야 할 단계 제시

상위 클래스는 "어떤 순서로 처리할지"를 결정하고, 구체적인 실행 내용은 하위 클래스에게 맡긴다. ✅

## 4. 하위 클래스의 역할

하위 클래스는 상위 클래스에서 추상 메소드로 정의해 둔 부분을 실제로 구현한다.

즉, 하위 클래스는 전체 알고리즘을 다시 작성하지 않는다.  
대신 알고리즘의 각 단계에서 어떤 일을 해야 하는지만 구현한다.

이 구조 덕분에 하위 클래스는 전체 흐름을 신경 쓰지 않고, 자신에게 필요한 구체적인 처리에만 집중할 수 있다.

## 5. Template Method 패턴의 흐름

Template Method 패턴의 흐름은 다음과 같이 볼 수 있다.

1. 상위 클래스가 템플릿 메소드를 가진다.
2. 템플릿 메소드 안에서 처리 순서를 정한다.
3. 일부 단계는 추상 메소드로 남겨 둔다.
4. 하위 클래스가 추상 메소드를 구현한다.
5. 실행 시 상위 클래스의 흐름에 따라 하위 클래스의 구현이 실행된다.

즉, 알고리즘의 큰 틀은 고정하고, 세부 내용만 바꿀 수 있게 만드는 패턴이다. 📌

## 6. Template Method 패턴을 사용하는 이유

Template Method 패턴을 사용하는 가장 큰 이유는 로직을 공통화할 수 있기 때문이다.

여러 클래스에서 비슷한 처리 흐름을 반복해서 작성하면 중복 코드가 많아진다.  
이때 상위 클래스에 공통 알고리즘을 정의해 두면 하위 클래스는 전체 로직을 일일이 작성할 필요가 없다.

즉,

- 공통 흐름은 상위 클래스에서 관리
- 달라지는 부분만 하위 클래스에서 구현

하는 방식으로 중복을 줄일 수 있다. ✅

## 7. 알고리즘과 단계 분리

Template Method 패턴에서는 알고리즘 전체와 각 단계를 분리해서 생각한다.

상위 클래스는 알고리즘을 담당한다.  
하위 클래스는 알고리즘 안의 각 단계별 세부 작업을 담당한다.

즉, 하위 클래스는 전체 흐름을 고민하지 않고 "이 단계에서 어떤 작업을 해야 하는지"에만 집중하면 된다.

이 구조는 유지보수에도 좋다.  
전체 흐름을 바꾸려면 상위 클래스만 보면 되고, 세부 구현을 바꾸려면 하위 클래스만 보면 되기 때문이다.

## 8. 프레임워크와 Template Method 패턴

Template Method 패턴은 프레임워크의 기본 패턴으로 자주 사용된다.

프레임워크는 전체 실행 흐름을 미리 정해 두고, 개발자가 필요한 부분만 구현하도록 만드는 경우가 많다.

예를 들어 Vue 3 같은 프레임워크도 전체 동작 구조는 프레임워크가 관리하고, 개발자는 컴포넌트나 특정 로직을 작성해서 그 흐름 안에 끼워 넣는다.

즉, 프레임워크는 큰 틀을 제공하고, 개발자는 필요한 세부 구현을 작성한다는 점에서 Template Method 패턴의 사고방식과 연결된다. 📌

## 9. Template Method 패턴의 장점

Template Method 패턴의 장점은 다음과 같다.

- 공통 로직을 상위 클래스에 모을 수 있다.
- 하위 클래스의 중복 코드를 줄일 수 있다.
- 전체 알고리즘 흐름을 일정하게 유지할 수 있다.
- 하위 클래스는 구체적인 단계 구현에만 집중할 수 있다.
- 유지보수가 쉬워진다.

즉, 공통 흐름은 재사용하고 차이가 나는 부분만 확장할 수 있는 구조이다.

## 10. 중요 포인트 📌

- 템플릿은 전체적인 모양이나 구조를 잡아 주는 틀이다.
- Template Method 패턴은 상위 클래스에서 처리의 뼈대를 결정한다.
- 하위 클래스는 구체적인 처리 내용을 구현한다.
- 상위 클래스는 알고리즘의 전체 흐름을 가진다.
- 하위 클래스는 각 단계별 작업에 집중한다.
- 로직을 공통화해서 중복을 줄일 수 있다.
- 프레임워크의 기본 구조와 연결해서 이해할 수 있다.
- Vue 3 같은 프레임워크도 큰 흐름은 프레임워크가 잡고, 개발자가 필요한 부분을 구현하는 방식으로 볼 수 있다.

## 정리 ✅

Template Method 패턴은 상위 클래스에서 알고리즘의 전체 흐름을 정하고, 하위 클래스에서 구체적인 처리 내용을 구현하도록 만드는 디자인 패턴이다.  
이 패턴을 사용하면 공통 로직을 상위 클래스에 모을 수 있고, 하위 클래스는 각 단계의 세부 작업만 구현하면 되므로 중복 코드가 줄어든다.  
즉, 전체 흐름은 고정하면서 필요한 부분만 다르게 구현할 수 있는 구조이다.  
시험 대비에서는 상위 클래스와 하위 클래스의 역할, 추상 메소드의 의미, 로직 공통화의 장점, 프레임워크와의 연결성을 함께 정리해 두는 것이 중요하다.
