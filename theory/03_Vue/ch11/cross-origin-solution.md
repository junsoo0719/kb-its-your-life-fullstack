# 크로스 오리진 문제 해결 방법

## 1. 크로스 오리진 문제

크로스 오리진(Cross Origin) 문제는 현재 요청 페이지를 받은 서버와 다른 서버로 자바스크립트 통신을 시도할 때 발생하는 문제이다.  
웹 브라우저는 기본 보안 정책에 따라 현재 페이지를 제공한 서버와 동일한 출처(Origin)에서만 통신하도록 제한한다.

Origin은 현재 요청 페이지를 받은 서버의 정보이며, 일반적으로 주소와 포트 번호를 포함한다.  
즉, 서버 주소나 포트 번호가 달라지면 다른 Origin으로 판단한다.

브라우저 콘솔에서는 다음과 같이 현재 Origin을 확인할 수 있다.

    location.origin

## 2. 브라우저의 기본 보안 정책

웹 브라우저에서 실행되는 자바스크립트는 기본적으로 해당 페이지를 내려준 서버와만 통신할 수 있다.  
이 정책은 악의적인 사이트가 다른 서버의 자원에 무단으로 접근하는 것을 막기 위한 보안 장치이다.

따라서 서버 주소나 포트 번호가 바뀌면 브라우저는 이를 다른 Origin으로 인식하고, 허용되지 않은 요청에 대해 에러를 발생시킨다.

## 3. 해결 방법 1: CORS 설정

크로스 오리진 문제를 해결하는 대표적인 방법은 백엔드 API 서버에서 CORS(Cross Origin Resource Sharing)를 설정하는 것이다.

CORS는 Origin이 달라도 통신을 허용할 수 있도록 서버가 제공하는 기능이다.  
즉, 서버가 응답할 때 특정 HTTP 헤더를 추가해서 브라우저에게 교차 출처 요청을 허용한다고 알려준다.

대표적인 응답 헤더는 다음과 같다.

    Access-Control-Allow-Origin: http://localhost:5173
    Access-Control-Allow-Methods: GET, POST, PUT, DELETE
    Access-Control-Allow-Max-Age: 3600

### 3-1. Access-Control-Allow-Origin

- 어떤 Origin의 요청을 허용할지 지정한다.
- 예: `http://localhost:5173`
- 모든 주소를 허용하려면 `*`를 사용할 수 있다.

### 3-2. Access-Control-Allow-Methods

- 허용할 HTTP 메서드를 지정한다.
- 예: GET, POST, PUT, DELETE

### 3-3. Access-Control-Allow-Max-Age

- 사전 요청(preflight request) 결과를 얼마나 오래 캐시할지 지정한다.

## 4. 해결 방법 2: 프록시(Proxy) 설정

또 다른 방법은 프론트엔드 애플리케이션을 호스팅하는 웹 서버에 프록시(Proxy)를 설치하거나 설정하는 것이다.

이 방법은 개발 단계에서 자주 사용된다.  
프론트엔드 애플리케이션은 같은 Origin으로 요청을 보내고, 개발용 웹 서버가 실제 백엔드 API 서버와 대신 통신을 중개한다.

즉, 프론트엔드 입장에서는 동일한 Origin으로 통신하는 것처럼 보이기 때문에 브라우저의 크로스 오리진 제한을 피할 수 있다.

## 5. CORS와 프록시의 차이

CORS는 백엔드 서버가 직접 다른 Origin의 요청을 허용하는 방식이다.  
반면 프록시는 프론트엔드 서버가 요청을 대신 전달하므로 브라우저 기준에서는 같은 Origin 통신처럼 보이게 하는 방식이다.

즉, CORS는 서버 설정 중심의 해결 방법이고, 프록시는 개발 환경에서 자주 사용하는 우회 및 중개 방식이라고 볼 수 있다.

## 6. 중요 포인트

- Origin은 현재 요청 페이지를 받은 서버의 주소와 포트 번호를 의미한다.
- 브라우저는 기본 보안 정책 때문에 다른 Origin과의 통신을 제한한다.
- 주소나 포트 번호가 달라지면 다른 Origin으로 판단한다.
- 현재 Origin은 `location.origin`으로 확인할 수 있다.
- CORS는 백엔드 서버가 다른 Origin의 요청을 허용하는 기능이다.
- `Access-Control-Allow-Origin` 헤더로 허용할 Origin을 지정한다.
- `Access-Control-Allow-Methods`로 허용할 HTTP 메서드를 지정할 수 있다.
- 프록시는 프론트엔드 서버가 대신 백엔드와 통신하도록 중개하는 방식이다.
- 프록시는 개발 단계에서 자주 사용된다.

## 정리

크로스 오리진 문제는 현재 페이지를 제공한 서버와 다른 Origin으로 자바스크립트 통신을 시도할 때 브라우저의 기본 보안 정책 때문에 발생한다.  
Origin은 주소와 포트 번호를 기준으로 판단하며, `location.origin`으로 확인할 수 있다.  
이 문제를 해결하는 대표적인 방법은 두 가지이다. 첫째, 백엔드 서버에서 CORS를 설정하여 다른 Origin의 요청을 허용하는 방법이다. 둘째, 프론트엔드 서버에 프록시를 설정해서 같은 Origin 통신처럼 보이도록 만드는 방법이다.  
시험 대비에서는 Origin의 의미, 브라우저의 기본 보안 정책, CORS의 역할, 주요 헤더, 프록시 방식의 원리를 함께 정리하는 것이 중요하다.
