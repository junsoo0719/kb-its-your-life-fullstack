# Vue 인스턴스

## 1. Vue 인스턴스

Vue에서 애플리케이션을 생성할 때 다음과 같이 작성한다.

```js
let vm = Vue.createApp({
  name: 'App',
});
```

이때 `Vue.createApp()`으로 만들어지는 앱 객체를 학습 단계에서는 흔히 **Vue 인스턴스**라고 부른다.

Vue 인스턴스는 화면을 구성하고 데이터를 관리하며,  
필요한 경우 렌더링을 다시 수행하는 하나의 단위로 볼 수 있다.

즉, **인스턴스 하나가 하나의 렌더링 단위**라고 이해할 수 있다.

---

## 2. mount와 unmount

### 2-1. mount

`mount()`는 Vue 인스턴스를 실제 HTML 요소에 연결하는 작업이다.

```js
const vm = Vue.createApp({
  name: 'App',
}).mount('#app');
```

이 과정을 통해 Vue가 관리하는 화면이 실제 브라우저 DOM에 연결되고 렌더링된다.

즉,

- 메모리 안에서 준비된 Vue의 구조를
- 실제 브라우저 화면에 연결하는 과정

이라고 볼 수 있다.

컴포넌트 구조 관점에서는 메모리에 준비된 subtree를 실제 DOM과 연결하는 단계라고 이해할 수 있다.

---

### 2-2. unmount

`unmount()`는 연결된 Vue 앱을 DOM에서 해제하는 작업이다.

즉,

- 브라우저 화면에서는 제거되고
- Vue가 연결한 DOM 렌더링은 사라진다

학습 관점에서는 화면에서 끊는 동작으로 이해하면 된다.

---

## 3. 부모 인스턴스와 자식 렌더링

Vue는 보통 부모 컴포넌트와 자식 컴포넌트 구조를 가진다.

부모 인스턴스의 상태가 바뀌면 그 영향 범위 안의 자식 컴포넌트도 다시 평가되고 렌더링될 수 있다.

즉,

- 부모 변경
- 자식에게 전달된 값 확인
- 필요 시 자식도 다시 렌더링

의 흐름으로 볼 수 있다.

다만 실제로는 Vue가 변경된 부분만 최대한 효율적으로 갱신하려고 한다.

---

## 4. data 옵션

`data` 옵션은 Vue가 반응형으로 추적하고 관리할 데이터를 모아 두는 곳이다.

```js
const vm = Vue.createApp({
  data() {
    return {
      message: 'Hello Vue',
    };
  },
});
```

여기서 `message` 같은 값은 Vue가 추적할 수 있는 데이터가 된다.

즉, 화면에서 사용하는 데이터는 보통 `data()`에서 반환한다.

---

## 5. `$`가 붙은 속성

Vue에서 `$`가 붙은 속성은 보통 Vue가 기본적으로 제공하는 내부 속성이나 인스턴스 관련 속성이다.

예를 들면 다음과 같은 형태가 있다.

- `$data`
- `$el`
- `$props`
- `$emit`

예:

```js
console.log(this.$data);
```

즉,

- 사용자가 직접 선언한 데이터와
- Vue가 내부적으로 제공하는 기본 속성

을 구분하기 위해 `$`가 붙는 경우가 많다.

---

## 6. 계산된 속성(computed)

계산된 속성은 Vue에서 매우 자주 사용하는 기능이다.

`computed` 옵션 안에 함수를 정의해서 사용한다.

```js
computed: {
  fullName() {
    return this.firstName + this.lastName;
  }
}
```

### 특징

- 함수처럼 정의하지만 사용할 때는 **속성처럼 사용**한다
- 즉, `fullName()`이 아니라 `fullName`으로 사용한다

```html
<p>{{ fullName }}</p>
```

이렇게 사용하는 이유는 Vue가 계산된 결과를 **속성처럼 관리**하기 때문이다.

---

### computed의 핵심

계산된 속성 안에는 반드시 **반응형 데이터**가 포함되는 것이 중요하다.

```js
computed: {
  fullName() {
    return this.firstName + this.lastName;
  }
}
```

위 예제에서는 `firstName`, `lastName`이 반응형 데이터라면  
이 값들이 바뀔 때마다 `fullName`도 다시 계산된다.

즉,

- 반응형 데이터 사용
- 해당 데이터가 바뀌면 다시 계산
- 화면도 필요한 만큼 갱신

이라는 흐름이 된다.

반대로 반응형 데이터와 관계없는 값만 사용하면  
다시 계산될 이유가 없으므로 의미가 거의 없어진다.

---

## 7. 메서드 옵션(methods)

`methods` 옵션에는 일반 메서드를 정의한다.

```js
methods: {
  changeMessage() {
    this.message = "변경됨";
  }
}
```

이 메서드는 이벤트 핸들러로 자주 사용된다.

```html
<button @click="changeMessage">변경</button>
```

즉, `methods`는 보통

- 클릭 이벤트 처리
- 입력 이벤트 처리
- 사용자 동작 처리

에 많이 사용된다.

---

## 8. 계산된 속성과 메서드 차이

겉보기에는 둘 다 함수처럼 작성되지만 역할이 다르다.

### computed

- 반응형 데이터를 바탕으로 **계산된 값**을 만들 때 사용
- 속성처럼 사용
- 관련 데이터가 바뀔 때 다시 계산

### methods

- 사용자의 동작이나 특정 이벤트에 반응하는 **행위**를 처리할 때 사용
- 호출해서 실행
- 이벤트 핸들러로 자주 사용

예를 들어

- 이름 합치기, 합계, 필터링 결과 → `computed`
- 버튼 클릭 시 실행, 입력 이벤트 처리 → `methods`

로 이해하면 된다.

---

## 9. 관찰 속성(watch)

`watch`는 특정 데이터의 변화를 감시해서  
값이 바뀌었을 때 추가 작업을 수행하는 기능이다.

보통 **비동기 작업과 많이 연결**된다.

```js
watch: {
  keyword(newValue, oldValue) {
    console.log(newValue, oldValue);
  }
}
```

### 특징

- `watch` 옵션 객체 안에 작성한다
- 감시할 데이터 속성명과 동일한 이름으로 함수를 만든다
- 첫 번째 인자: 변경 후 값
- 두 번째 인자: 변경 전 값

즉, 데이터가 바뀌는 순간을 잡아서 후처리를 할 수 있다.

예를 들면

- 검색어 변경 시 API 호출
- 입력값 변경 시 서버 요청
- 상태 변화에 따른 비동기 처리

같은 작업에 적합하다.

---

## 10. Vue 생명주기

Vue 컴포넌트나 앱은 생성되고, 화면에 붙고, 갱신되고, 제거되는 과정을 거친다.  
이 과정을 **생명주기(lifecycle)** 라고 한다.

Vue에서는 특정 시점에 실행되는 생명주기 메서드를 제공한다.

---

## 11. created

`created`는 인스턴스가 생성된 뒤 실행되는 생명주기 단계이다.

이 시점에는

- 데이터 접근 가능
- 반응형 데이터 사용 가능
- 아직 실제 DOM은 완성되지 않음

즉, 데이터 준비 작업에 적합하다.

특히 다음과 같은 작업에 자주 사용한다.

- 서버 통신
- 초기 데이터 다운로드
- 비동기 초기화 작업

예:

```js
created() {
  console.log("created");
}
```

---

## 12. mounted

`mounted`는 컴포넌트가 실제 DOM에 붙은 뒤 실행된다.

이 시점에는

- 데이터 접근 가능
- DOM 접근 가능
- 화면 요소를 직접 다룰 수 있음

즉, 실제 화면 요소를 기준으로 작업해야 할 때 사용한다.

예:

```js
mounted() {
  console.log("mounted");
}
```

---

## 13. created와 mounted 차이

### created

- DOM 완성 전
- DOM 접근 불가
- 데이터 접근 가능

### mounted

- DOM 완성 후
- DOM 접근 가능
- 실제 렌더링된 요소 기준 작업 가능

즉,

- **데이터 준비**는 `created`
- **화면 요소 접근**은 `mounted`

로 기억하면 편하다.

---

## 14. 생명주기 메서드 작성 위치

생명주기 메서드는 별도의 `lifecycle` 같은 옵션 안에 넣는 것이 아니라  
`Vue.createApp({})` 객체의 바로 하위에 작성한다.

예:

```js
Vue.createApp({
  data() {
    return {
      message: 'hello',
    };
  },
  created() {
    console.log('created');
  },
  mounted() {
    console.log('mounted');
  },
});
```

즉,

- `data`
- `computed`
- `methods`
- `watch`
- `created`
- `mounted`

같은 항목들이 같은 레벨에 위치한다.

---

## 15. Vue 생명주기 흐름 간단 정리

학습 단계에서는 다음 흐름으로 이해하면 된다.

1. 인스턴스 생성
2. `data`, `computed`, `methods`, `watch` 등 준비
3. `created` 실행
4. `mount()`로 DOM 연결
5. `mounted` 실행
6. 데이터 변경 시 다시 렌더링
7. 필요 없으면 `unmount()`

즉,  
**생성 → 데이터 준비 → DOM 연결 → 화면 표시 → 변경 시 갱신 → 제거**  
흐름이다.

---

## 16. 부모-자식 컴포넌트 실행 흐름

부모와 자식 컴포넌트가 있을 때는 보통 부모가 먼저 생성되고,  
그 안에서 자식이 연결되는 흐름으로 이해할 수 있다.

단순하게 보면 다음과 같이 이해하면 된다.

1. 부모 생성
2. 부모의 상태 준비
3. 자식 생성
4. 자식 상태 준비
5. DOM 연결
6. 화면 렌더링

그리고 부모 데이터가 바뀌어 자식에게 전달되는 값이 달라지면  
자식도 다시 렌더링될 수 있다.

즉, 부모가 상위 흐름을 잡고 자식은 그 안에서 연결된다고 이해하면 된다.

---

## 17. 컴포넌트 트리에서의 에러 처리

Vue 컴포넌트는 트리 구조로 연결된다.

이때 자식 컴포넌트에서 에러가 발생하면  
상위 부모 컴포넌트 쪽으로 전달되어 부모가 처리할 수 있다.

즉,

- 에러가 자식에서 발생
- 상위 컴포넌트 방향으로 전달
- 부모가 처리 가능

이라는 흐름으로 이해할 수 있다.

이런 구조는 컴포넌트 트리 전체의 안정성을 높이는 데 도움이 된다.

---

## 18. 정리

- Vue 인스턴스는 화면을 구성하고 렌더링하는 하나의 단위이다.
- `mount()`는 Vue 앱을 실제 DOM에 연결하는 작업이다.
- `unmount()`는 연결된 Vue 앱을 DOM에서 해제하는 작업이다.
- `data` 옵션에는 반응형으로 추적할 데이터를 모아 둔다.
- `$`가 붙은 속성은 Vue가 제공하는 기본 속성인 경우가 많다.
- `computed`는 반응형 데이터를 바탕으로 계산된 값을 만들 때 사용한다.
- 계산된 속성은 함수처럼 정의하지만 속성처럼 사용한다.
- `methods`는 이벤트 처리나 동작 실행에 많이 사용된다.
- `watch`는 데이터 변화를 감시하고 후처리할 때 사용한다.
- `created`는 DOM 생성 전 단계이고 데이터 접근이 가능하다.
- `mounted`는 DOM 생성 후 단계이고 DOM 접근이 가능하다.
- 생명주기 메서드는 `Vue.createApp({})`의 바로 아래에 작성한다.
- 부모가 변경되면 자식도 다시 렌더링될 수 있다.
- 자식 컴포넌트의 에러는 상위 부모 컴포넌트에서 처리할 수 있다.
