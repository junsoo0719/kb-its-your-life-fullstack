# vue-router와 axios를 사용한 예제

## 1. vue-router의 기본 처리

vue-router에서는 정의되지 않은 주소로 접근했을 때 처리할 라우트를 따로 설정할 수 있다.

    { path: '/:paths(.*)*', component: NotFound }

이 설정은 어떤 주소와도 일치하지 않는 경우 `NotFound` 컴포넌트를 보여주기 위한 것이다.  
즉, 사용자가 존재하지 않는 경로에 접근했을 때 에러 페이지나 안내 페이지를 띄우는 역할을 한다.

이와 같은 라우트는 보통 마지막에 작성해서 예외 경로를 처리한다.

## 2. 반응형 데이터를 만드는 함수

Vue에서 반응형 데이터를 만들 때 대표적으로 사용하는 함수는 `ref`와 `reactive`이다.

- `ref` → 기본값 하나를 반응형으로 관리할 때 사용
- `reactive` → 객체나 배열 구조를 반응형으로 관리할 때 사용

이 둘은 모두 반응성을 제공하지만 접근 방식이 다르다.

### 2-1. ref

`ref`는 값 하나를 감싸서 반응형으로 만드는 방식이다.

    const todoList = ref([])

이때 실제 값에 접근하거나 값을 변경할 때는 `.value`를 사용해야 한다.

    todoList.value = response.data

이처럼 `ref`를 사용할 경우 `.value`를 통해 값을 바꿔야 반응성이 유지된다.

### 2-2. reactive

`reactive`는 객체 자체를 반응형으로 만든다.

    const todoItem = reactive({ todo: "", desc: "" })

객체의 속성을 직접 수정할 수 있다는 특징이 있다.

## 3. provide와 읽기 전용 데이터 전달

다른 컴포넌트에 데이터를 전달할 때 `provide`를 사용할 수 있다.

    provide('todoList', computed(() => states.todoList))

이 코드에서 `computed(() => states.todoList)`를 사용하는 이유는 데이터를 읽기 전용 형태로 내보내기 위해서이다.

만약 다음처럼 직접 내보내면

    provide('todoList', states.todoList)

주입받은 쪽에서 데이터를 직접 수정할 수 있게 된다.  
이렇게 되면 데이터 흐름이 불명확해지고, 상태 관리가 어려워질 수 있다.

따라서 외부에 데이터를 제공할 때는 `computed`를 이용해서 읽기 전용처럼 전달하는 것이 안전하다.

## 4. reactive 객체를 복사해서 전달하는 이유

다음과 같은 코드가 있다고 하자.

    const todoItem = reactive({ todo: "", desc: "" })
    addTodo({ ...todoItem })

여기서 `{ ...todoItem }`처럼 다시 객체로 묶는 이유는 `reactive` 객체 자체를 넘기지 않고, 순수 객체를 복사해서 전달하기 위해서이다.

즉, 원본 반응형 객체를 직접 넘기면 이후 상태 변화가 원치 않게 연결될 수 있으므로 복사본을 전달해서 안전하게 처리하는 것이다.

정리하면 다음과 같다.

- `todoItem` 그대로 전달 → 반응형 객체 전달
- `{ ...todoItem }` 전달 → 일반 객체 복사본 전달

실제 데이터 추가나 저장 로직에서는 복사본을 전달하는 방식이 더 안전하다.

## 5. find 메서드의 반환값

다음과 같은 코드가 있다고 하자.

    todoList.value.find((item) => item.id === currentRoute.params.id)

여기서 `find()`는 조건에 맞는 요소의 인덱스를 반환하는 것이 아니라, 조건에 맞는 객체 자체를 반환한다.

즉,

- `find()` → 요소(객체) 반환
- `findIndex()` → 위치(인덱스) 반환

따라서 특정 id에 해당하는 todo 객체를 바로 찾고 싶을 때 `find()`를 사용한다.

## 6. axios와 반응성 유지

axios로 서버에서 데이터를 받아올 때 반응성을 유지하는 방식이 중요하다.

예를 들어 상태 객체 안에 `todoList`가 있는 경우에는 다음처럼 작성해야 한다.

    states.todoList = response.data

이렇게 해야 `states` 객체의 반응성이 유지된다.

반대로 다음처럼 작성하면

    todoList = response.data

기존 반응형 연결이 끊어져 반응성을 잃을 수 있다.

### 6-1. ref를 사용할 때

`ref`로 선언한 경우에는 다음처럼 `.value`를 이용해서 값을 변경해야 한다.

    const todoList = ref([])
    todoList.value = response.data

이렇게 해야 Vue가 값 변경을 감지하고 화면을 다시 갱신한다.

## 7. 데이터 추가 후 페이지 이동

다음 코드는 할 일을 추가한 뒤 목록 페이지로 이동하는 예이다.

    addTodo({ ...todoItem }, () => {
      router.push('/todos')
    })

여기서 흐름은 다음과 같다.

1. `todoItem`의 복사본을 전달해서 데이터를 추가한다.
2. 추가 작업이 끝난 뒤 콜백 함수가 실행된다.
3. `router.push('/todos')`로 목록 페이지로 이동한다.

즉, 데이터 저장 후 자동으로 목록 화면으로 되돌아가도록 처리한 것이다.

## 8. 목록 데이터와 캐시 처리

목록 데이터는 항상 다시 불러올 수도 있고, 한 번 불러온 뒤 캐시처럼 사용할 수도 있다.

필기 내용의 핵심은 다음과 같다.

- 목록이 빈번하게 수정되지 않는다면 → 캐시 처리 가능
- 목록이 빈번하게 수정된다면 → 목록 페이지 진입 시마다 다시 로딩해야 함

즉, 데이터 변경이 자주 일어나지 않는 구조에서는 불필요한 요청을 줄이기 위해 캐시를 사용할 수 있다.  
반대로 데이터가 자주 바뀌는 서비스라면 최신 데이터를 보여주기 위해 페이지에 들어올 때마다 서버에서 다시 가져와야 한다.

## 9. 중요 포인트

- `/:paths(.*)*`는 정의되지 않은 모든 주소를 처리하는 라우트이다.
- `ref`와 `reactive`는 Vue의 대표적인 반응형 데이터 생성 함수이다.
- `provide`로 데이터를 전달할 때는 `computed`를 사용해 읽기 전용으로 내보내는 것이 안전하다.
- `reactive` 객체는 그대로 넘기기보다 복사본을 만들어 전달하는 것이 좋다.
- `find()`는 인덱스가 아니라 조건에 맞는 객체를 반환한다.
- axios 응답 데이터를 반응형 상태에 대입할 때는 기존 반응형 구조를 유지해야 한다.
- `ref`는 값을 바꿀 때 반드시 `.value`를 사용해야 한다.
- 데이터 추가 후 `router.push()`로 원하는 페이지로 이동할 수 있다.
- 목록 데이터는 변경 빈도에 따라 캐시 처리 여부를 결정해야 한다.

## 정리

vue-router와 axios를 함께 사용하는 예제에서는 라우팅 처리, 반응형 데이터 관리, 서버 통신 후 상태 반영 방식이 매우 중요하다.  
정의되지 않은 경로는 `/:paths(.*)*`로 처리할 수 있고, `ref`와 `reactive`를 통해 Vue의 반응형 상태를 관리한다.  
또한 `provide`로 데이터를 전달할 때는 `computed`를 사용해 읽기 전용으로 내보내는 것이 안전하며, `reactive` 객체는 복사본으로 전달해야 불필요한 상태 공유를 막을 수 있다.  
axios로 받은 데이터는 반응형 상태에 맞는 방식으로 대입해야 반응성이 유지되며, 데이터 추가 후에는 `router.push()`로 원하는 페이지로 이동할 수 있다.  
마지막으로 목록 데이터는 수정 빈도에 따라 캐시 처리 여부를 결정해야 하며, 데이터가 자주 바뀌면 페이지 진입 시마다 다시 로딩하는 방식이 필요하다.
