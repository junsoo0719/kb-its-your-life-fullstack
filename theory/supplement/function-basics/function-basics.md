# 함수

## 1. 함수의 스코프와 변수 접근

자바스크립트에서는 **내부 함수가 외부 함수의 변수에 접근할 수 있다.**

이때 함수는 자신이 선언된 위치를 기준으로 변수를 찾는다.  
이런 규칙을 **렉시컬 스코프(lexical scope)** 라고 한다.

예:

```js
function outer() {
  const x = 10;

  function inner() {
    console.log(x);
  }

  inner();
}

outer();
```

위 코드에서 `inner()` 함수는 자신의 내부에서 `x`를 찾고,  
없으면 바깥쪽인 `outer()`의 스코프에서 `x`를 찾아 사용한다.

변수를 찾는 순서는 보통 다음과 같다.

1. 자기 자신의 스코프에서 찾기
2. 없으면 바깥 함수의 스코프에서 찾기
3. 계속 없으면 더 바깥쪽 스코프에서 찾기
4. 끝까지 없으면 에러 발생

---

## 2. 외부 함수에서 내부 변수 접근

반대로 **외부 함수에서 내부 함수의 지역 변수에는 직접 접근할 수 없다.**

예:

```js
function outer() {
  function inner() {
    const y = 20;
  }

  inner();
  console.log(y); // 에러
}

outer();
```

위 코드에서 `y`는 `inner()` 함수 안에서만 유효한 지역 변수이므로  
`outer()`에서 직접 사용할 수 없다.

즉,

- 내부 함수 → 외부 변수 접근 가능
- 외부 함수 → 내부 변수 접근 불가

---

## 3. 호이스팅

호이스팅(hoisting)은 **변수 선언이나 함수 선언이 코드의 위로 끌어올려진 것처럼 동작하는 현상**이다.

자바스크립트는 코드를 실행하기 전에 먼저 선언들을 확인하고,  
실행에 필요한 정보를 미리 메모리에 준비한다.

---

## 4. var와 호이스팅

`var`로 선언한 변수는 **선언만 먼저 올라가고 값의 대입은 나중에 이루어진다.**

예:

```js
console.log(x); // undefined
var x = 10;
```

위 코드가 에러가 아니라 `undefined`가 나오는 이유는  
다음과 비슷하게 동작하기 때문이다.

```js
var x;
console.log(x);
x = 10;
```

즉,

- 선언은 먼저 처리됨
- 초기값은 나중에 대입됨
- 그래서 선언 전 접근 시 `undefined`가 나올 수 있음

---

## 5. let과 호이스팅

`let`도 선언 자체는 먼저 처리되지만,  
**초기화되기 전에는 접근할 수 없다.**

예:

```js
console.log(y); // ReferenceError
let y = 5;
```

이처럼 `let`은 선언 전에 접근하면 `ReferenceError`가 발생한다.

이는 `let`이 **TDZ(Temporal Dead Zone)** 의 영향을 받기 때문이다.

즉,

- 선언은 미리 처리됨
- 하지만 초기화 전에는 접근 불가
- 그래서 `undefined`가 아니라 에러 발생

---

## 6. 함수는 값처럼 사용할 수 있다

자바스크립트에서 함수는 **값처럼 다룰 수 있다.**

그래서 함수는 다음과 같은 방식으로 사용할 수 있다.

- 변수에 저장할 수 있다
- 매개변수로 전달할 수 있다
- 리턴값으로 반환할 수 있다

예:

```js
function hello() {
  console.log('hello');
}

const fn = hello;
fn();
```

---

## 7. 함수를 매개변수로 전달

함수를 다른 함수의 매개변수로 전달할 수 있다.

예:

```js
function greet() {
  console.log('안녕하세요');
}

function run(callback) {
  callback();
}

run(greet);
```

이처럼 **작업이 끝난 뒤 실행할 함수를 전달하는 방식**을 자주 사용하는데,  
이때 전달되는 함수를 **콜백 함수(callback function)** 라고 한다.

---

## 8. 함수는 함수를 리턴할 수 있다

자바스크립트에서는 함수가 다른 함수를 반환할 수도 있다.

예:

```js
function outer() {
  return function inner() {
    console.log('inner');
  };
}

const fn = outer();
fn();
```

이처럼 함수가 함수를 리턴할 수 있기 때문에  
자바스크립트에서는 함수를 매우 유연하게 다룰 수 있다.

---

## 9. 클로저

클로저(closure)는 **함수가 만들어질 때의 바깥 변수들을 기억하는 함수**이다.

즉, 바깥 함수가 실행을 마친 뒤에도  
안쪽 함수가 바깥 함수의 변수에 계속 접근할 수 있는 현상을 말한다.

예:

```js
function outer() {
  let count = 0;

  return function inner() {
    count++;
    console.log(count);
  };
}

const counter = outer();

counter(); // 1
counter(); // 2
counter(); // 3
```

위 코드에서 `outer()` 함수는 이미 실행이 끝났지만,  
리턴된 `inner()` 함수는 `count` 변수를 계속 기억하고 사용한다.

이것이 클로저이다.

---

## 10. 클로저의 핵심

클로저의 핵심은 다음과 같다.

- 내부 함수가 외부 함수의 변수에 접근할 수 있다
- 외부 함수의 실행이 끝난 뒤에도 그 변수를 기억할 수 있다
- 상태를 유지하는 함수 작성에 유용하다

클로저는 다음과 같은 상황에서 자주 활용된다.

- 데이터 은닉
- 상태 유지
- 함수 팩토리
- 이벤트 처리
- 콜백 함수

---

## 11. 정리

- 자바스크립트의 내부 함수는 외부 함수의 변수에 접근할 수 있다.
- 외부 함수에서는 내부 함수의 지역 변수에 직접 접근할 수 없다.
- 변수는 자신의 스코프에서 먼저 찾고, 없으면 바깥 스코프로 이동하며 찾는다.
- 호이스팅은 선언이 위로 끌어올려진 것처럼 동작하는 현상이다.
- `var`는 선언 전에 접근하면 `undefined`가 나올 수 있다.
- `let`은 선언 전에 접근하면 `ReferenceError`가 발생한다.
- 함수는 값처럼 사용할 수 있어 매개변수로 전달하거나 리턴값으로 반환할 수 있다.
- 콜백 함수는 다른 함수에 전달되어 나중에 실행되는 함수이다.
- 자바스크립트에서는 함수가 함수를 리턴할 수 있다.
- 클로저는 함수가 바깥 변수들을 기억해서 계속 사용할 수 있는 현상이다.
