# ✨ 뷰, 테이블스페이스

## 1. 뷰의 개념

뷰(View)는 일반 사용자 입장에서 테이블과 동일하게 사용할 수 있는 데이터베이스 개체이다.

실제 데이터를 직접 저장하는 테이블과 달리, 뷰는 특정 `SELECT`문의 결과를 테이블처럼 사용할 수 있게 만든 것이다.  
즉, 복잡한 조회 결과에 이름을 붙여 두고 필요할 때 간단히 조회할 수 있다. 📌

## 2. 뷰 생성 구문

뷰는 `CREATE VIEW` 문으로 생성한다.

기본 형식은 다음과 같다.

    CREATE VIEW 뷰이름
    AS
    SELECT문;

예를 들어 `usertbl`에서 `userid`, `name`, `addr`만 조회하는 뷰는 다음과 같이 만들 수 있다.

    CREATE VIEW v_usertbl
    AS
    SELECT userid, name, addr
    FROM usertbl;

이렇게 생성한 뷰는 일반 테이블처럼 조회할 수 있다.

    SELECT *
    FROM v_usertbl;

즉, 사용자는 복잡한 원본 테이블 구조를 몰라도 필요한 데이터만 쉽게 조회할 수 있다. ✅

## 3. 뷰의 장점

뷰의 대표적인 장점은 다음과 같다.

- 보안에 도움
- 복잡한 쿼리 단순화
- 필요한 컬럼만 사용자에게 제공 가능
- 반복되는 긴 쿼리를 줄일 수 있음

즉, 뷰는 데이터를 더 안전하고 편리하게 조회하기 위한 도구이다.

## 4. 보안에 도움

뷰를 사용하면 사용자가 중요한 정보에 직접 접근하지 못하게 할 수 있다.

예를 들어 원본 테이블에는 민감한 정보가 포함되어 있어도, 뷰에서는 필요한 컬럼만 선택해서 보여줄 수 있다.

    CREATE VIEW v_usertbl
    AS
    SELECT userid, name, addr
    FROM usertbl;

위 뷰는 `usertbl`의 일부 컬럼만 보여준다.  
따라서 사용자는 원본 테이블의 모든 정보가 아니라 뷰에 정의된 정보만 조회할 수 있다. 📌

## 5. 복잡한 쿼리 단순화

뷰는 복잡한 쿼리를 단순하게 사용할 수 있도록 해 준다.

여러 테이블을 조인하거나 함수가 포함된 긴 쿼리를 매번 작성하지 않고, 뷰로 만들어 두면 테이블처럼 조회할 수 있다.

예를 들어 회원 테이블과 구매 테이블을 조인한 결과를 뷰로 만들 수 있다.

    CREATE VIEW v_userbuytbl
    AS
    SELECT U.userid,
           U.name,
           B.prodName,
           U.addr,
           CONCAT(U.mobile1, U.mobile2) AS '연락처'
    FROM usertbl U
    INNER JOIN buytbl B
        ON U.userid = B.userid;

필기에는 `INNER J이N`으로 적혀 있지만, 정확한 SQL 키워드는 `INNER JOIN`이다. ⚠️

## 6. 뷰 조회

생성한 뷰는 테이블처럼 조회할 수 있다.

    SELECT *
    FROM v_userbuytbl
    WHERE name = '김범수';

이 쿼리는 `v_userbuytbl` 뷰에서 이름이 `'김범수'`인 데이터를 조회한다.

즉, 실제로는 조인과 문자열 결합이 포함된 복잡한 쿼리이지만, 사용자는 뷰 이름만 이용해 간단하게 조회할 수 있다. ✅

## 7. 뷰 삭제

뷰를 삭제할 때는 `DROP VIEW` 문을 사용한다.

    DROP VIEW 뷰이름;

예를 들면 다음과 같다.

    DROP VIEW v_usertbl;

뷰를 삭제해도 원본 테이블의 데이터가 삭제되는 것은 아니다.  
뷰는 원본 데이터를 참조하는 개체이기 때문에 뷰만 제거된다. 📌

## 8. 뷰 수정

뷰를 수정할 때는 `CREATE OR REPLACE VIEW` 문을 사용할 수 있다.

    CREATE OR REPLACE VIEW 뷰이름
    AS
    SELECT문;

이 구문은 같은 이름의 뷰가 이미 있으면 기존 뷰를 대체하고, 없으면 새로 생성한다.

즉, 뷰의 조회 컬럼이나 조건을 바꾸고 싶을 때 사용할 수 있다.

## 9. 테이블스페이스

필기 제목에는 테이블스페이스가 포함되어 있지만, 제공된 필기 내용에는 테이블스페이스에 대한 구체적인 설명이 없다.

따라서 이 정리에서는 확실한 필기 내용인 뷰를 중심으로 정리한다.  
테이블스페이스는 추가 필기가 있을 때 별도로 정리하는 것이 좋다. ⚠️

## 10. 중요 포인트 📌

- 뷰는 일반 사용자 입장에서 테이블처럼 사용할 수 있는 개체이다.
- 뷰는 `CREATE VIEW` 문으로 생성한다.
- 뷰는 실제 테이블의 `SELECT` 결과를 테이블처럼 사용할 수 있게 한다.
- 뷰는 중요한 정보에 직접 접근하지 못하게 해서 보안에 도움을 준다.
- 복잡한 조인 쿼리를 뷰로 만들면 단순하게 조회할 수 있다.
- 뷰는 `SELECT * FROM 뷰이름;` 형태로 조회할 수 있다.
- 뷰 삭제는 `DROP VIEW`를 사용한다.
- 뷰 수정은 `CREATE OR REPLACE VIEW`를 사용할 수 있다.
- 뷰를 삭제해도 원본 테이블 데이터는 삭제되지 않는다.
- 테이블스페이스는 제목에 포함되어 있으나, 현재 필기에는 구체적인 내용이 없다.

## 정리 ✅

뷰는 `SELECT`문의 결과를 테이블처럼 사용할 수 있게 만든 데이터베이스 개체이다.  
사용자는 뷰를 일반 테이블처럼 조회할 수 있으며, 원본 테이블의 중요한 컬럼을 숨길 수 있어 보안에 도움이 된다.  
또한 여러 테이블을 조인하거나 함수가 포함된 복잡한 쿼리를 뷰로 만들어 두면, 이후에는 뷰 이름만으로 간단하게 조회할 수 있다.  
뷰는 `CREATE VIEW`로 생성하고, `DROP VIEW`로 삭제하며, `CREATE OR REPLACE VIEW`로 수정할 수 있다.
