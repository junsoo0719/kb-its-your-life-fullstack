# ✨ 인덱스

## 1. 인덱스의 개념

인덱스는 테이블에서 데이터를 더 빠르게 검색하기 위해 사용하는 데이터베이스 객체이다.  
책의 목차나 색인처럼, 원하는 데이터를 찾기 쉽도록 특정 컬럼 기준으로 정리해 둔 구조라고 이해할 수 있다.

즉, 인덱스는 조회 성능을 높이기 위한 도구이다. 📌

## 2. 인덱스의 장점

인덱스를 사용하면 데이터 검색 속도가 향상된다.

특히 테이블에 데이터가 많을수록 조건 검색에서 인덱스의 효과가 커질 수 있다.

인덱스의 장점은 다음과 같다.

- 검색 속도 향상
- 시스템 전체 성능 향상

즉, 자주 검색되는 컬럼에 인덱스를 설정하면 데이터 조회 성능을 높일 수 있다. ✅

## 3. 인덱스의 단점

인덱스는 검색 성능을 높여 주지만 단점도 있다.

대표적인 단점은 다음과 같다.

- 추가 저장 공간 필요
- 처음 생성할 때 많은 시간 필요
- 데이터 변경이 자주 일어나면 성능 저하 가능

인덱스는 별도의 정렬 구조를 유지해야 하므로 저장 공간을 추가로 사용한다.  
또한 `INSERT`, `UPDATE`, `DELETE`가 발생하면 인덱스도 함께 수정해야 하므로 데이터 변경이 많은 테이블에서는 오히려 성능이 떨어질 수 있다. ⚠️

## 4. 인덱스의 종류

인덱스는 크게 다음 두 가지로 나눌 수 있다.

- 클러스터형 인덱스
- 보조 인덱스

두 인덱스는 데이터 저장 방식과 생성 가능한 개수에서 차이가 있다.

## 5. 클러스터형 인덱스

클러스터형 인덱스는 행 데이터를 자신의 열을 기준으로 정렬하는 인덱스이다.

즉, 실제 테이블 데이터 자체가 해당 컬럼 기준으로 정렬되어 저장되는 구조라고 이해할 수 있다.

특징은 다음과 같다.

- 행 데이터를 기준 컬럼에 맞춰 정렬
- 테이블당 하나만 생성 가능

테이블의 실제 데이터 정렬 방식과 관련되기 때문에 여러 개 만들 수 없다. 📌

## 6. 보조 인덱스

보조 인덱스는 별도 공간을 추가로 사용해서 지정한 컬럼만 정렬하여 운영하는 인덱스이다.

즉, 실제 데이터 전체를 정렬하는 것이 아니라 인덱스용 별도 구조를 만들어 검색을 빠르게 하는 방식이다.

특징은 다음과 같다.

- 별도 공간 필요
- 지정 컬럼 기준으로 인덱스 운영
- 컬럼 단위로 여러 개 생성 가능

즉, 하나의 테이블에 여러 개의 보조 인덱스를 만들 수 있다.

## 7. 자동 생성 인덱스

MySQL에서는 특정 제약 조건을 설정하면 인덱스가 자동으로 생성된다.

대표적인 경우는 다음과 같다.

- `PRIMARY KEY` 제약 조건
- `UNIQUE` 제약 조건

즉, 고유성을 보장해야 하는 컬럼에는 자동으로 인덱스가 생성된다. ✅

## 8. PRIMARY KEY와 인덱스

`PRIMARY KEY` 제약 조건을 설정하면 클러스터형 인덱스가 자동으로 생성된다.

즉, 기본키 컬럼을 기준으로 데이터가 정렬되어 관리된다.

기본키는 테이블의 각 행을 식별하는 중요한 기준이므로, 검색 성능을 위해 자동으로 인덱스가 생성된다.

## 9. UNIQUE와 인덱스

`UNIQUE` 제약 조건을 설정하면 보조 인덱스가 자동으로 생성된다.

`UNIQUE`는 중복 값을 허용하지 않는 제약 조건이다.  
따라서 값의 중복 여부를 빠르게 확인하기 위해 인덱스가 필요하다.

즉, `UNIQUE` 컬럼은 보조 인덱스를 통해 중복 검사와 검색 성능을 지원한다.

## 10. PRIMARY KEY가 없는 경우

`PRIMARY KEY`가 없고, `UNIQUE`와 `NOT NULL` 제약 조건이 설정된 컬럼이 있다면 해당 컬럼이 클러스터형 인덱스로 생성될 수 있다.

즉, 기본키가 명확하지 않은 경우에도 고유하고 null이 아닌 컬럼을 기준으로 클러스터형 인덱스가 잡힐 수 있다. 📌

## 11. 인덱스 확인

테이블에 생성된 인덱스를 확인할 때는 다음 명령을 사용한다.

    SHOW INDEX FROM 테이블명;

예를 들면 다음과 같다.

    SHOW INDEX FROM employees;

이 명령을 통해 해당 테이블에 어떤 인덱스가 있는지 확인할 수 있다.

## 12. B-Tree

MySQL 인덱스는 대표적으로 B-Tree 구조를 사용한다.

B-Tree는 Balanced Tree, 즉 균형 트리를 의미한다.  
데이터를 균형 있게 배치해서 검색 속도를 안정적으로 유지하는 자료구조이다.

즉, 인덱스는 단순 목록이 아니라 검색에 유리한 트리 구조로 관리된다. ✅

## 13. 페이지

페이지는 B-Tree에서 노드 역할을 하는 단위이다.

필기 기준으로 페이지는 고정 크기 단위로 관리된다.  
데이터를 한 개만 저장하더라도 페이지 단위로 공간이 할당된다.

즉, 인덱스와 데이터는 작은 단위가 아니라 페이지라는 일정한 블록 단위로 관리된다. 📌

## 14. 페이지 분할

페이지 분할은 페이지에 더 이상 공간이 없을 때 발생한다.

페이지 분할 과정은 다음과 같다.

1. 새로운 페이지를 생성한다.
2. 기존 데이터를 나누어 각각의 페이지에 재배치한다.
3. 페이지 간 링크를 수정한다.

즉, 인덱스 구조를 유지하기 위해 새로운 페이지를 만들고 데이터를 다시 나누는 작업이다.

페이지 분할은 추가 작업이 필요하므로 성능에 부담을 줄 수 있다. ⚠️

## 15. 인덱스 생성

인덱스는 `CREATE INDEX` 문으로 생성할 수 있다.

기본 형식은 다음과 같다.

    CREATE [UNIQUE | FULLTEXT | SPATIAL] INDEX 인덱스명
    ON 테이블명(컬럼명, ...);

예를 들면 다음과 같다.

    CREATE INDEX idx_name
    ON member(name);

즉, 특정 컬럼을 기준으로 인덱스를 생성해 검색 성능을 높일 수 있다.

## 16. 인덱스 옵션

인덱스를 생성할 때 다음 옵션을 사용할 수 있다.

- `UNIQUE`
- `FULLTEXT`
- `SPATIAL`

의미는 다음과 같다.

- `UNIQUE` → 중복을 허용하지 않는 인덱스
- `FULLTEXT` → 전문 검색용 인덱스
- `SPATIAL` → 공간 데이터용 인덱스

즉, 데이터의 성격에 따라 적절한 인덱스 종류를 선택할 수 있다.

## 17. 인덱스 제거

인덱스를 제거할 때는 `DROP INDEX` 문을 사용한다.

기본 형식은 다음과 같다.

    DROP INDEX 인덱스명 ON 테이블명;

예를 들면 다음과 같다.

    DROP INDEX idx_name ON member;

즉, 더 이상 필요하지 않은 인덱스는 제거할 수 있다.

불필요한 인덱스가 많으면 저장 공간을 차지하고 데이터 변경 성능을 떨어뜨릴 수 있으므로 관리가 필요하다. 📌

## 18. 인덱스를 사용할 때 고려할 점

인덱스는 무조건 많이 만든다고 좋은 것이 아니다.

검색이 자주 발생하는 컬럼에는 유리하지만, 데이터 삽입, 수정, 삭제가 자주 발생하는 컬럼에는 부담이 될 수 있다.

따라서 인덱스는 다음 기준을 고려해서 생성해야 한다.

- 조회 조건에 자주 사용되는 컬럼인지
- 데이터 중복도가 낮은 컬럼인지
- 정렬이나 검색에 자주 사용되는 컬럼인지
- 데이터 변경이 너무 잦지 않은지

즉, 검색 성능과 변경 성능 사이의 균형이 중요하다. ✅

## 19. 중요 포인트 📌

- 인덱스는 검색 속도를 향상시키기 위한 데이터베이스 객체이다.
- 인덱스는 시스템 전체 성능 향상에 도움을 줄 수 있다.
- 인덱스는 추가 공간이 필요하다.
- 인덱스는 처음 생성할 때 시간이 걸릴 수 있다.
- 데이터 변경이 자주 일어나면 인덱스 때문에 성능이 저하될 수 있다.
- 클러스터형 인덱스는 행 데이터를 기준 컬럼에 맞춰 정렬한다.
- 클러스터형 인덱스는 테이블당 하나만 생성 가능하다.
- 보조 인덱스는 별도 공간에 지정 컬럼만 정렬해서 운영한다.
- 보조 인덱스는 여러 개 생성 가능하다.
- `PRIMARY KEY`는 클러스터형 인덱스를 자동 생성한다.
- `UNIQUE`는 보조 인덱스를 자동 생성한다.
- 인덱스 확인은 `SHOW INDEX FROM 테이블명;`으로 한다.
- B-Tree는 균형 트리 구조이다.
- 페이지는 B-Tree의 노드 역할을 한다.
- 페이지에 공간이 없으면 페이지 분할이 발생한다.
- 인덱스 생성은 `CREATE INDEX`를 사용한다.
- 인덱스 제거는 `DROP INDEX`를 사용한다.

## 정리 ✅

인덱스는 테이블에서 데이터를 빠르게 검색하기 위해 사용하는 구조이다.  
검색 속도와 시스템 성능을 향상시킬 수 있지만, 추가 저장 공간이 필요하고 데이터 변경이 자주 발생하면 오히려 성능이 저하될 수 있다.  
인덱스는 클러스터형 인덱스와 보조 인덱스로 나뉘며, 클러스터형 인덱스는 테이블당 하나만 만들 수 있고 실제 행 데이터를 기준 컬럼에 맞춰 정렬한다.  
`PRIMARY KEY`와 `UNIQUE` 제약 조건은 인덱스를 자동으로 생성하며, 인덱스는 B-Tree 구조와 페이지 단위로 관리된다.  
시험 대비에서는 인덱스의 장단점, 클러스터형/보조 인덱스 차이, 자동 생성 조건, `SHOW INDEX`, `CREATE INDEX`, `DROP INDEX`, B-Tree와 페이지 분할 개념을 함께 정리해 두는 것이 중요하다.
