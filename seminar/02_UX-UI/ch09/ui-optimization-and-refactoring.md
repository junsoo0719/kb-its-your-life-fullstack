# UI 최적화 및 리팩토링

## 1. 개념

UI 최적화는 사용자가 화면을 더 편하고 빠르게 사용할 수 있도록 인터페이스를 개선하는 작업이다.

즉, 단순히 화면을 예쁘게 만드는 것이 아니라 다음과 같은 목적을 가진다.

- 사용자 경험 개선
- 성능 개선
- 불필요한 요소 제거

리팩토링은 기능은 그대로 유지하면서 코드 구조를 더 좋은 형태로 개선하는 작업이다.

즉, 사용자 입장에서는 동작이 같아 보여도 개발자 입장에서는 코드를 더 읽기 쉽고, 수정하기 쉽고, 재사용하기 쉽게 만드는 과정이다.

정리하면,

- **UI 최적화**는 사용자 화면과 경험을 더 좋게 만드는 것
- **리팩토링**은 내부 코드 구조를 더 좋게 만드는 것
  이다.

## 2. UI 최적화

UI 최적화의 목적은 사용자가 서비스를 사용할 때 더 빠르고 편하고 안정적으로 느끼게 만드는 것이다.

예를 들어 다음과 같은 부분이 UI 최적화와 연결된다.

- 화면이 너무 복잡하지 않은가
- 버튼이 누르기 편한가
- 반응 속도가 빠른가
- 중요한 정보가 잘 보이는가

즉, UI 최적화는 시각적인 문제뿐 아니라 사용 흐름과 성능까지 함께 고려하는 작업이다.

## 3. 리팩토링

리팩토링은 기능을 바꾸지 않고 코드의 내부 구조를 개선하는 작업이다.

핵심 특징은 다음과 같다.

- 기능은 그대로 유지한다.
- 코드 구조를 개선한다.
- 유지보수가 쉬워진다.

즉, 결과 화면이나 기능은 같더라도 코드가 더 정리되고 재사용 가능해지며, 수정 실수도 줄일 수 있다.

## 4. 코드가 사용자 경험에 미치는 영향

코드는 직접 사용자에게 보이지 않지만, 코드 구조는 결국 사용자 경험에 영향을 준다.

### 4.1 일관성 → 사용자의 신뢰감

코드 구조가 잘 정리되어 있으면 화면 요소도 일관되게 구현된다.  
버튼 크기, 간격, 색상, 동작 방식이 통일되면 사용자는 더 안정감 있고 신뢰감 있게 느낀다.

### 4.2 빠른 수정 → 오류 감소

코드가 복잡하면 수정할 때 실수가 생기기 쉽다.  
반대로 구조가 좋으면 빠르게 수정할 수 있고, 버그 발생 가능성도 줄어든다.

### 4.3 구조 명확 → 예측 가능성 증가

구조가 명확한 코드는 UI 흐름도 자연스럽게 만들 수 있다.  
사용자는 다음 화면이나 버튼 동작을 더 쉽게 예측할 수 있다.

### 4.4 재사용 가능 → UI 안정성 유지

같은 구조와 스타일을 반복해서 재사용하면 UI 품질이 일정하게 유지된다.  
즉, 페이지마다 다른 모양이 나오는 문제를 줄일 수 있다.

결국 **좋은 코드 구조는 좋은 사용자 경험으로 이어진다**는 점이 중요하다.

## 5. UI 최적화 체크리스트

UI를 점검할 때는 다음 항목을 확인해야 한다.

### 5.1 간격이 일정한가

요소 사이 간격이 들쑥날쑥하면 화면이 불안정해 보인다.  
일정한 여백은 화면을 정돈되어 보이게 하고 이해하기 쉽게 만든다.

### 5.2 버튼 크기가 적절한가

버튼이 너무 작으면 누르기 어렵고, 너무 크면 화면 균형이 무너질 수 있다.  
특히 모바일에서는 손가락으로 누르기 쉬운 크기가 중요하다.

### 5.3 클릭 영역이 충분한가

텍스트만 겨우 눌리는 구조는 사용성이 떨어진다.  
버튼이나 링크는 실제로 누를 수 있는 영역이 충분해야 한다.

### 5.4 정보가 너무 많지 않은가

한 화면에 정보가 너무 많으면 사용자는 피로를 느끼고 핵심을 놓치기 쉽다.  
중요 정보만 우선적으로 보여 주는 것이 좋다.

### 5.5 반응 속도가 빠른가

버튼을 눌렀는데 반응이 느리면 사용자는 불안함을 느낀다.  
화면 전환, 입력 반응, 로딩 표시 등도 UX에 큰 영향을 준다.

즉, UI 최적화는 단순히 꾸미는 것이 아니라 **간격, 크기, 정보량, 반응 속도**를 종합적으로 점검하는 작업이다.

## 6. CSS 관리의 한계

프로젝트 규모가 커질수록 일반 CSS만으로 관리할 때 한계가 생긴다.

### 6.1 스타일 반복 증가

비슷한 색상, 여백, 버튼 스타일을 여러 곳에서 반복 작성하게 된다.

### 6.2 수정 비용 증가

색상 하나를 바꾸거나 공통 간격을 수정할 때 여러 파일을 찾아서 바꿔야 할 수 있다.

### 6.3 코드 복잡도 증가

스타일이 많아질수록 구조가 복잡해지고, 어떤 코드가 어디에 영향을 주는지 파악하기 어려워진다.

즉, CSS가 커질수록 유지보수 비용이 빠르게 증가한다.

## 7. 해결 방법: Sass

이런 문제를 해결하기 위해 사용할 수 있는 도구가 Sass이다.

Sass는 CSS를 더 효율적으로 관리할 수 있게 도와주는 전처리기(preprocessor)이다.

주요 장점은 다음과 같다.

- 반복되는 스타일을 줄일 수 있다.
- 값을 한 곳에서 관리할 수 있다.
- 코드 구조를 더 체계적으로 만들 수 있다.

즉, Sass를 사용하면 CSS를 더 재사용 가능하고 관리하기 쉬운 형태로 작성할 수 있다.

## 8. Sass와 Scss

Sass에는 두 가지 작성 방식이 있다.

| 구분      | Sass(옛날 방식)    | Scss(현재 방식) |
| --------- | ------------------ | --------------- |
| 문법      | 들여쓰기 기반      | CSS와 거의 동일 |
| 중괄호    | 없음               | 있음            |
| 세미콜론  | 없음               | 있음            |
| 사용 빈도 | 거의 사용하지 않음 | 대부분 사용     |

즉, 현재는 보통 **SCSS 방식**을 사용한다고 이해하면 된다.

SCSS는 기존 CSS 문법과 비슷해서 배우고 적용하기 쉽다.

## 9. 예제

```scss
$primary-color: #2563eb;
$spacing-md: 16px;

.button {
  background-color: $primary-color;
  padding: $spacing-md;
  border-radius: 8px;
  color: white;
}

.card {
  padding: $spacing-md;
  border: 1px solid #ddd;
}
```

위 예제에서

- `$primary-color`는 공통 색상 변수
- `$spacing-md`는 공통 여백 변수

이처럼 반복되는 값을 변수로 관리하면 수정이 쉬워진다.  
예를 들어 버튼 색상을 바꾸고 싶으면 `$primary-color`만 수정하면 된다.

즉, Sass는 **반복 제거와 공통 값 관리**에 매우 유용하다.

## 10. 중요 포인트

- UI 최적화는 사용자 경험 개선, 성능 개선, 불필요한 요소 제거를 목표로 한다.
- 리팩토링은 기능은 유지하면서 코드 구조를 개선하는 작업이다.
- 좋은 코드 구조는 일관성, 오류 감소, 예측 가능성, UI 안정성으로 이어진다.
- UI 점검 시 간격, 버튼 크기, 클릭 영역, 정보량, 반응 속도를 확인해야 한다.
- 일반 CSS는 규모가 커질수록 반복 증가, 수정 비용 증가, 복잡도 증가 문제가 생긴다.
- Sass는 CSS를 더 효율적으로 관리하기 위한 도구이다.
- Sass는 반복 스타일을 줄이고 값을 한 곳에서 관리할 수 있게 해 준다.
- 현재는 Sass보다 SCSS 문법을 더 많이 사용한다.

## 정리

UI 최적화는 사용자가 화면을 더 편하고 빠르게 사용할 수 있도록 인터페이스를 개선하는 작업이고, 리팩토링은 기능을 바꾸지 않으면서 코드 구조를 더 좋게 만드는 작업이다.

좋은 UI는 단순히 예쁜 화면이 아니라, 간격이 일정하고, 버튼이 적절한 크기를 가지며, 클릭 영역이 충분하고, 정보가 과하지 않고, 반응이 빠른 화면이다.

또한 좋은 사용자 경험은 좋은 코드 구조와도 연결된다.  
코드가 정리되어 있으면 UI의 일관성이 높아지고, 수정이 쉬워져 오류가 줄고, 재사용성이 높아져 안정적인 화면을 유지할 수 있다.

프로젝트가 커질수록 일반 CSS만으로 관리하기 어려워지므로, 반복을 줄이고 값을 효율적으로 관리할 수 있는 Sass, 특히 SCSS 문법을 사용하는 것이 유지보수에 유리하다.
