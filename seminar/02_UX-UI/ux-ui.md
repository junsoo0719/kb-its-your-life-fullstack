# UX/UI

## 1. 개념

UX(User Experience)는 사용자가 서비스를 이용하면서 겪는 전체 경험이다.  
즉, 사용하기 쉬운지, 흐름이 자연스러운지, 실수하기 쉬운지까지 포함한 넓은 개념이다.

UI(User Interface)는 사용자가 직접 조작하는 화면과 인터페이스이다.  
버튼, 메뉴, 화면 구성, 시각 디자인처럼 눈에 보이고 직접 만지는 요소가 여기에 해당한다.

정리하면 UX는 전체 경험이고, UI는 그 경험을 구성하는 하나의 요소이다.  
즉, **UX가 더 큰 개념**이다.

## 2. 좋은 UX를 판단하는 기준

좋은 UX는 단순히 화면이 예쁜 것이 아니라 사용자가 **고민하지 않고, 멈추지 않고, 빠르고, 안심하며** 사용할 수 있어야 한다.

### 2.1 명확성

사용자가 화면을 보는 순간 무엇을 해야 하는지 바로 이해할 수 있어야 한다.  
고민하는 순간 사용자는 이탈할 가능성이 커진다.

### 2.2 흐름성

사용자가 중간에 멈추지 않고 자연스럽게 다음 행동으로 이어질 수 있어야 한다.  
좋은 UX는 사용자의 행동 흐름을 끊지 않는다.

### 2.3 효율성

사용자의 시간을 낭비하지 않아야 한다.  
사용자는 항상 가장 빠른 길을 선택하려는 경향이 있으므로, 불필요한 단계와 반복 입력은 줄여야 한다.

### 2.4 안정성

사용자가 불안감을 느끼지 않고 서비스를 사용할 수 있어야 한다.  
실수 가능성을 줄이고, 상태를 명확히 전달하며, 오류가 나도 복구할 수 있어야 한다.

## 3. 페이지 수보다 중요한 것

사용자는 페이지 수 자체를 세지 않는다.  
중요한 것은 페이지 수가 아니라 **예측 가능성**이다.

즉, 화면이 여러 개여도 흐름이 자연스럽고 다음 단계가 예상 가능하면 불편함이 줄어든다.  
반대로 페이지 수가 적어도 한 화면에 너무 많은 정보가 몰려 있으면 사용자는 더 어렵게 느낀다.

## 4. 효율적인 UX 설계

페이지를 나눌 때는 단순히 화면 수를 줄이는 것이 아니라, 사용자가 이해하고 행동하기 쉬운 구조로 나누는 것이 중요하다.

페이지 분할의 기준은 다음 3가지이다.

### 4.1 논리적 그룹핑(Logical Grouping)

성격이 비슷한 정보끼리 한 페이지에 묶는 방식이다.

사용자가 같은 맥락의 정보라고 인식하는 것들을 함께 배치하면 다음과 같은 장점이 있다.

- 행동 흐름이 명확해진다.
- 인지 부담이 줄어든다.
- 단계별 맥락을 이해하기 쉬워진다.
- 심리적 안정감을 준다.

### 4.2 인지적 부하 조절(Cognitive Load Control)

사용자가 한 번에 생각해야 할 정보의 양을 줄이는 방식이다.

한 화면에 너무 많은 선택지와 정보를 넣으면 사용자는 피로를 느끼고 실수할 가능성이 높아진다.  
따라서 다음과 같은 방법이 필요하다.

- 영역 간 간격 조정
- 단계별 제목 추가
- 중요한 버튼 크기 확대

즉, 한 화면에서 처리해야 할 사고량을 줄이는 것이 핵심이다.

### 4.3 데이터 의존성(Data Dependency)

앞 단계의 정보가 다음 단계의 이해와 선택 기준이 될 때, 이를 고려하여 순서를 설계하는 방식이다.

예를 들면 다음과 같다.

- 배송 정보 입력 후 배송 방식 선택
- 할인 적용 후 결제 수단 선택
- 이전 선택 결과가 다음 화면 구성을 결정하는 경우

즉, 데이터 흐름이 자연스럽게 이어지도록 순서를 설계해야 한다.

## 5. 안정성을 높이는 설계

좋은 UX는 사용자가 실수하지 않도록 도와주고, 현재 상태를 확실하게 이해하게 해 주며, 오류가 발생해도 다시 회복할 수 있게 해야 한다.

### 5.1 예측 가능한 인터페이스

사용자는 화면의 동작을 어느 정도 예측할 수 있어야 한다.

중요한 기준은 다음과 같다.

- 버튼 역할이 명확해야 한다.
- 동사형 표현을 사용하면 행동 의미가 분명해진다.
- 인터페이스 동작이 일관되어야 한다.
- 예상 가능한 위치와 패턴을 사용해야 한다.
- 아이콘만 쓰지 말고 텍스트와 색상을 함께 사용해야 한다.

### 5.2 실수 방지 설계

사용자의 실수를 사후에 고치는 것보다 사전에 막는 것이 더 중요하다.

대표적인 방법은 다음과 같다.

- 입력 형식 제한
- 잘못된 입력 사전 차단
- 중요한 행동에 확인 단계 제공

### 5.3 명확한 상태 전달

사용자는 지금 시스템이 어떤 상태인지 알아야 불안하지 않다.

따라서 다음과 같은 요소가 필요하다.

- 처리 과정 표시
- 진행 상태 안내
- 결과 피드백 제공

### 5.4 오류 발생 시 명확한 안내

오류 메시지는 단순히 실패 사실만 알려주면 안 된다.

반드시 포함해야 할 내용은 다음과 같다.

- 오류 원인 안내
- 해결 방법 제시
- 다시 시도할 수 있는 기능 제공

## 6. UI 구조 설계 흐름

UI 구조는 단순히 화면을 예쁘게 배치하는 작업이 아니라, 사용자 목표와 행동 흐름을 기준으로 설계해야 한다.

### 6.1 사용자 목표 정의

가장 먼저 사용자가 왜 이 화면에 들어왔는지 정의해야 한다.

핵심 질문은 다음과 같다.

- 사용자는 왜 이 화면에 들어왔는가?
- 무엇을 하려고 하는가?
- 핵심 목표는 무엇인가?

기능은 여러 개일 수 있지만, **목표는 하나로 압축**되어야 한다.

### 6.2 사용자 행동 흐름 설계

사용자의 행동은 보통 다음 구조를 가진다.

- 시작
- 과정
- 완료

이때 중요한 점은 다음과 같다.

- 단계는 최소화해야 한다.
- 사용자가 막히지 않게 해야 한다.
- 되돌아갈 수 있어야 한다.

### 6.3 화면 단위 분리

원칙은 **한 화면 = 하나의 목적**이다.

한 화면에서 사용자가 무엇을 해야 하는지 분명해야 한다.  
사용자의 행동 흐름을 그대로 복사하는 것이 아니라, 어디서 끊고 어떻게 나눌지 설계해야 한다.

### 6.4 UI 구조 배치

화면을 배치할 때는 다음 요소를 고려해야 한다.

- 정보 우선순위
- 시선 흐름(F형, Z형)
- 행동 유도 요소(CTA, Call To Action)
- 피드백 제공

즉, 사용자가 중요한 정보를 먼저 보고 자연스럽게 행동하도록 유도해야 한다.

## 7. 레이아웃을 위한 우회적 구현

과거에는 CSS에서 전용 레이아웃 도구가 부족했기 때문에 `position`, `float`, `table` 등을 이용해 화면을 배치했다.

하지만 이들은 본래 레이아웃 전용 도구가 아니므로 한계가 있다.

## 8. position

`position`은 요소의 위치를 결정하는 CSS 속성이다.

구성은 다음 두 가지로 이루어진다.

- 기준: `static`, `relative`, `absolute`, `fixed`, `sticky`
- 위치: `top`, `right`, `bottom`, `left`

```css
.box1 {
  position: relative;
  top: 10px;
  left: 20px;
}

.box2 {
  position: absolute;
  top: 0;
  right: 0;
}

.box3 {
  position: fixed;
  bottom: 20px;
  right: 20px;
}
```

### 8.1 static

기본값이다.  
일반적인 문서 흐름에 따라 배치된다.

### 8.2 relative

자기 자신이 원래 있던 위치를 기준으로 이동한다.  
원래 자리는 그대로 유지된다.

### 8.3 absolute

가장 가까운 기준 부모 요소를 기준으로 자유롭게 위치를 지정한다.  
일반 문서 흐름에서 빠져나와 배치된다.

### 8.4 fixed

화면 자체를 기준으로 위치를 고정한다.  
스크롤해도 같은 자리에 남아 있다.

## 9. float와 clear

`float`는 원래 글과 이미지를 자연스럽게 감싸기 위해 만든 속성이다.

```css
.image {
  float: left;
}

.next {
  clear: both;
}
```

### 9.1 float

- `left`
- `right`
- `none`

`float`가 적용된 요소는 일반 문서 흐름에서 제거된다.  
즉, 다른 요소가 그 자리를 일반 블록처럼 인식하지 않는다.

### 9.2 clear

`clear`는 float의 영향을 끊고 다음 요소를 아래로 내려오게 한다.

- `clear: left`
- `clear: right`
- `clear: both`

예를 들어 `float: left` 요소 옆으로 흘러가던 다음 요소를 아래로 배치하고 싶을 때 사용한다.

## 10. position, float, table의 공통 문제점

이 세 가지는 모두 레이아웃 전용 도구가 아니다.

### 10.1 position의 문제

요소를 자유롭게 옮길 수 있지만, 문서 흐름이 쉽게 깨진다.

### 10.2 float의 문제

예상치 못한 예외가 자주 발생한다.  
정렬이 복잡해지고 `clear` 처리도 필요하다.

### 10.3 table의 문제

데이터를 표현하기 위한 구조를 화면 배치용으로 사용하는 방식이다.  
즉, 의미 구조와 시각 구조가 섞여 버린다.

## 11. 중요 포인트

- UX는 전체 사용자 경험이고, UI는 그 경험을 구성하는 화면 요소이다.
- UX가 더 큰 개념이다.
- 좋은 UX의 기준은 명확성, 흐름성, 효율성, 안정성이다.
- 사용자는 페이지 수보다 예측 가능성을 더 중요하게 느낀다.
- 페이지 분할 기준은 논리적 그룹핑, 인지적 부하 조절, 데이터 의존성이다.
- 안정성을 높이려면 예측 가능한 인터페이스, 실수 방지, 상태 전달, 오류 안내가 필요하다.
- UI 구조 설계는 사용자 목표 정의 → 행동 흐름 설계 → 화면 단위 분리 → 구조 배치 순서로 진행한다.
- `position`, `float`, `table`은 레이아웃 전용 도구가 아니므로 한계가 있다.

## 정리

UX는 사용자가 서비스를 이용하면서 겪는 전체 경험이고, UI는 그 경험을 실제 화면으로 보여 주는 인터페이스이다.  
따라서 좋은 서비스는 단순히 예쁜 화면이 아니라, 사용자가 이해하기 쉽고, 멈추지 않고, 빠르고, 안전하게 사용할 수 있어야 한다.

좋은 UX를 만들기 위해서는 명확성, 흐름성, 효율성, 안정성을 기준으로 설계해야 하며, 페이지를 나눌 때도 논리적 그룹핑, 인지적 부하 조절, 데이터 의존성을 고려해야 한다.

또한 UI 구조는 사용자 목표를 먼저 정의하고, 행동 흐름을 설계한 뒤, 화면 단위를 나누고, 정보 우선순위와 CTA를 중심으로 배치해야 한다.

마지막으로 `position`, `float`, `table`은 과거에 레이아웃을 위해 우회적으로 사용된 방식이지만, 본래 목적이 레이아웃 전용이 아니므로 구조 설계 시 한계를 이해하고 사용해야 한다.
